# 自行托管插件与清单安装设计

日期：2026-09-23。状态：**需求与产品行为已确认；协议字段、迁移与实施方案待实施计划细化。**

## 目标与首个案例

让开发者自行部署插件服务，由空间管理员通过插件清单地址审阅并安装。插件既可提供无需外部账号的 Agent 能力，也可提供需要成员个人连接的外部服务操作。首个纵向案例是只读 Jira 插件：成员在对话中查询本人本周待办，看到结果来源；未授权成员先完成自己的 Jira 授权。

“插件”是产品分发单位；MCP 服务是首版执行协议与现有接入资源。插件、空间安装和成员个人连接不能合并成一个状态。现有[领域词汇](../../CONTEXT.md)中的 App、Installation、Connection、Action 继续表达空间安装、外部账号连接和操作；插件清单为自托管交付提供版本化入口，不另建一套同义的安装关系。

## 已确认的产品行为

1. 开发者交付可从 WeKnora 后端访问的远程 MCP 服务。开发指南先基于现有 MCP 配置；后续管理员粘贴清单 URL，审阅名称、版本、能力、授权方式、执行端点后安装。
2. 首版安装权限属于空间管理员。安装后所有空间成员可发现插件；需要个人连接的工具，只在该成员完成授权后可调用。个人连接不向其他成员共享。
3. 无外部账号的工具也可随插件交付。插件声明哪些工具需要个人连接，以及哪些工具存在外部副作用；清单声明不代替 WeKnora 的运行时授权与审批。
4. 每个插件版本有稳定且持续可用的执行端点。空间固定在已接受版本；新版本由管理员审阅后手动接受，未接受时继续调用旧版本。
5. 新增写操作默认关闭。管理员逐项启用，并可对每项操作设置调用时的成员审批。安装或成员授权不自动放行写操作。

## 用户流程与验收

| 场景 | 预期行为 |
| --- | --- |
| 管理员粘贴清单 URL | WeKnora 获取并校验清单，展示版本、端点、工具、权限与授权要求；管理员确认后才创建空间安装 |
| 成员浏览已安装插件 | 能看到 Jira 插件及授权状态；尚未授权者可发起自己的授权，不能借用管理员或其他成员的账号 |
| 成员询问本周 Jira 待办 | Agent 在允许的工具范围内调用已接受版本，插件仅以该成员的连接查询，并返回可追溯 Jira 链接 |
| 插件发布新版 | 旧版继续可用；管理员看到工具、scope、端点及写权限的差异，接受后才切换空间版本 |
| 新版新增写工具 | 切换版本后该工具仍为关闭；管理员逐项启用并设置审批，成员授权本身不启用该工具 |
| 管理员停用插件或成员撤销授权 | 后续调用被拒绝；停用插件不删除其他成员的个人连接，撤销个人授权不影响其他成员 |
| 清单或服务不可达 | 安装/升级不得凭未验证内容成功；已安装版本继续按其健康状态运行或给出明确错误，不偷偷改用新端点 |

## 清单与版本契约

清单至少需要稳定插件标识、版本标识、展示信息、受支持的远程 MCP 传输与执行端点、工具能力快照、每项工具的只读/写入分类、个人授权需求及 scope、声明来源与内容摘要。具体 JSON 字段、签名或信任模型、资源限制和兼容性规则留给实施前的技术设计；**不能仅以清单自报为准给工具授权**。安装时应从版本端点发现工具并与清单核对，记录管理员接受的快照。

升级必须比较已接受快照与候选版本：工具新增/移除、schema、scope、执行端点及读写分类的变化均需展示。已接受版本的端点不得在未接受升级时静默改指向新版。若开发者违反稳定端点承诺，平台需要通过快照和运行时检查阻止未获接受的能力扩张；无法验证的行为变化应被明确视为自托管插件的信任边界，而非声称平台可完全锁住远程代码。

## 与现有实现的边界

现有 `mcp_services`、OAuth、工具发现、Agent 注册、单工具启停与审批为可复用基础，详见 [MCP 功能说明](../../website-docs/03-features/08-mcp.md)。当前功能和目标的差距如下：

| 目标 | 当前状态 | 待补能力 |
| --- | --- | --- |
| 粘贴清单 URL 安装 | 仅手工创建 MCP 服务 | 清单抓取与校验、审阅页面、空间安装绑定 |
| 按版本固定执行 | MCP 服务保存可变 URL | 版本快照、稳定端点约束、管理员升级确认与回退语义 |
| 新写工具默认关闭 | 未配置的 MCP 工具默认启用且无需审批 | 新工具及写工具的默认拒绝、版本差异审批，运行时再次核对 |
| 成员个人连接 | MCP OAuth token 已按 principal 隔离 | 在插件安装视图中展示授权状态，并把授权与具体插件版本/服务关联 |
| 无账号的独立能力 | MCP 工具可无 OAuth | 在清单和安装流程中标明无连接要求 |

不得把 `mcp-server/` 中“向其他客户端提供 WeKnora 工具”的服务方向误用为插件安装运行时。首版自托管插件由 WeKnora **作为 MCP 客户端**调用开发者部署的服务。

## 范围

本设计包含空间管理员安装、成员发现与个人授权、远程工具调用、版本接受、逐工具启停和写操作审批。首个验收案例只读 Jira 查询；写操作用升级和默认关闭的验收场景验证。公开第三方市场、插件代码上传及 WeKnora 托管执行、空间共用 Jira 账号、本机 `stdio` 执行不在本次范围。

实施前需形成独立实施计划，并对清单抓取的网络边界、版本快照与远端漂移检测、OAuth 身份映射、写操作默认拒绝和既有 MCP 数据迁移给出可验证方案。这里不指定数据库表或最终 JSON 字段。
