# Craft 网页作品首版范围

- 日期：2026-09-23
- 状态：已批准（用户逐项回答设计问题，并于 2026-09-23 确认整体理解）。本文定义首版产品范围；实施须另行制定计划和验证。
- 来源：对 `2026-09-10-onyx-craft-product-proposal.md` 的范围收敛；沿用 `CONTEXT.md`、ADR-0004 及已批准的 React/TDesign 迁移设计。

## 目标与边界

在 WeKnora 中提供面向企业普通成员的 Craft 工作台。成员描述目标，明确选定有权访问的知识库和/或上传文件；Lead Agent 负责对话、检索、授权与最终说明，向隔离沙箱中的 OpenCode 委派网页构建。首版交付一个可预览、可继续修改、可重开、可下载源码的交互网页作品。

`assistant-ui` 承担对话界面和状态投影。文件、预览、版本、权限、运行、恢复及持久化由 WeKnora 服务负责。Task 沿用现有 Session 身份；一次执行是 Run。一个 Craft Task 首版只有一个主要网页作品，同一工作区串行写入，多次成功 Run 形成不可变作品版本。

## 用户行为

1. 普通成员新建 Craft Task，选择特定知识库并上传本轮材料。系统只在明确选择范围内检索，不自动搜索其所有可访问知识。
2. 可上传任意扩展名的文件，首版沿用每文件 20 MiB、每轮最多 20 个文件且总计 100 MiB 的 Craft 配额。文件作为只读材料接收；可识别格式提取内容，无法识别的格式保留原始文件并明确告知未被理解，由成员决定继续使用其他材料或取消本轮。上传成功不代表内容可理解。
3. 上传的代码即使被成员明确要求运行，也不直接执行；Agent 可读取其内容、理解意图，并在受控工作区自行编写和运行生成代码。压缩包只按受限规则解包，不能借归档文件突破文件数量、总大小、路径或资源限制。Agent 不因附件内容获得额外权限。
4. Lead Agent 展示实际使用的资料和证据引用，区分来源事实与模型推断。网页中的事实性内容有可追溯的来源标注；下载的源码保留可见引用和来源清单。受限原文链接仍需鉴权，原始知识文件不随源码自动打包。若下载包包含由受限材料转换而来的数据，下载前列出数据文件及来源，并由 Task 所有者明确确认。
5. OpenCode 使用预置模板和依赖构建网页，构建环境无外网。网页预览默认无互联网或企业内网访问，不能写入企业系统；交互仅基于作品自带数据和本次授权材料。
6. 新版本成为默认预览前，至少需要构建成功、预览服务实际可访问和一次页面加载检查。生成文件但未通过验证的 Run 显示失败或待修复，不产生“成功可预览”的版本。验证证据须与版本关联。
7. 新 Run 构建期间默认展示上一个成功版本及明确的构建状态。停止运行时保留未验证的工作区草稿供后续修复，默认预览仍指向上一个成功版本；停止请求和确认停止是不同状态。
8. 历史版本可查看和下载，不能原地覆盖。首版从当前工作区继续修改；从指定旧版本恢复并继续编辑不在首版承诺内。
9. 关闭页面不取消服务端 Run。重开 Task 时读取真实运行状态或已完成结果，不重新提交相同请求。知识库后来发生变化时，旧版本依据仍指向当时材料；新 Run 在当前授权下重新检索。
10. 默认只有 Task 所有者可见。所有者可显式加入 Task 协作者和查看者；协作者可发起新 Run，同一工作区一次至多有一个写入 Run。查看者不获得修改权。共享作品不自动共享原始知识；受限来源生成的作品在分享时由所有者明确确认，查看者只能打开其本身有权访问的原文。
11. 模型与沙箱消耗受空间策略和 Task Budget 约束。达到上限后暂停，交由 Task 所有者或获授权账单管理员处理。

## 首版非目标

- 将预览发布为公开或企业内正式托管应用、绑定域名。
- 直接运行上传的代码、任意外部写操作、网页预览访问互联网或企业内网。
- 多人同时写入同一工作区、从任意历史版本继续编辑。
- 同时交付文档、表格、演示稿等其他作品类型，或完整在线 IDE。

## 与当前实现的差距，实施前核对

- `packages/views/src/craft/assistant-runtime.tsx` 已接入真实 `@assistant-ui/react`，需在此基础上验收完整工作台，而非重建对话层。
- `internal/application/service/temporary_document.go` 当前有文件扩展名白名单并拒绝已知可执行文件；这与“任意扩展名作为只读材料”尚不一致。需设计独立的 Craft 任意文件接收与内容识别边界，并保留明确的大小、数量和资源限制。
- `internal/modules/craft/input.go` 当前限制每文件 20 MiB、每轮 20 个文件和总计 100 MiB；首版沿用此产品配额，归档文件解包后的资源限制需在实施规格中进一步确定。
- Docker 沙箱默认 `bridge` 模式允许出站连接；离线构建及无网络预览需要显式配置和验证。预置依赖的升级与模板版本也需确定。
- Craft 现有 `@weknora/ui` 使用须服从已批准的 TDesign React 迁移目标。

## 首版验收场景

1. 成员选择一个知识库并上传 CSV，要求创建可按地区筛选的销售网页。页面加载成功，筛选有效，事实性数字可追溯到本次输入，源码可下载。
2. 成员要求修改图表。修改期间旧成功版仍可用；新版本通过构建、可访问和页面加载检查后成为默认版，旧版仍可查看和下载。
3. 成员上传未知扩展名文件。系统保留只读文件并提示无法理解，成员可选择继续或取消；上传的脚本不会自动执行。
4. 构建中关闭并重开浏览器，只恢复同一 Task/Run，不重复提交；失败或停止后仍能看到旧成功版及草稿状态。
5. 协作者在授权后发起修改，查看者不能发起修改；未获原文权限的查看者无法通过引用链接读取受限知识。
6. 构建和预览均无法访问外网；未通过预览检查、预算耗尽或沙箱结果未知时均不得显示为成功交付。
7. 上传脚本并要求运行时，系统不直接执行上传文件；下载含受限材料衍生数据的源码包前，所有者看到数据与来源清单并作出明确确认。
