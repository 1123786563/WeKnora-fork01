## 客户端实现（关闭 G04）

- **domain/submission.ts（新）**：
  - `inputDigest`（7 字段稳定键序规范化摘要）；`SubmissionStore` 端口（**先于网络持久化**，落盘失败即抛错且不发送）；`createSubmissionCoordinator`：
    - submit：新 ID → 落盘 awaiting_ack → 发送 → ACK（request_id 回传一致校验）→ bound；ACK 丢失/网络错 → awaiting_reconciliation（**同 ID、不重发**）；
    - 重放：同 ID 同摘要 → 零网络，按 phase 恢复（bound 直返/对账）；同 ID 异摘要 → SubmissionConflictError（零网络）；
    - reconcile：lookup 原 request_id；admitted→bound、rejected→rejected、pending/dispatching/unknown→维持对账态（不自动重 POST、不新建预算预占）；
    - retryEntry：仅 rejected 允许受控重试（新意图=新 ID+用户确认）。
  - `createInMemorySubmissionStore`（测试）；scope 按 origin/user/tenant 隔离。
- **MMKV 适配器（apps/mobile/…/platform/submission-store.ts 新）**：KV 注入式 `createScopedKVSubmissionStore`——同步写、进程重启存活、scope 绑定（跨空间写拒绝、跨空间读为空）、损坏条目 fail-closed。真实 MMKV 实例由 react-native-mmkv 提供（apps 内既有先例）。
- **api-client executions.ts**：`executionEventsRequest` 追加 `?version=2`（D-014 接线——产品流走 envelope+控制帧合同；v1 兼容保留在服务端）。
