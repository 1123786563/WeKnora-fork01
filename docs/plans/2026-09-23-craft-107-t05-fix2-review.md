## Verdict

- **Spec compliance: FAIL for #124 as a whole; conditional progress at the T05 service seam.** The new digest-bound record and publisher contract address same-Run overwrite and partial file visibility *if* a production publisher honors the contract. No production publisher is assembled, so `BuildForRun` fails closed in the current container. Separately, the central delegate still lacks the per-Run sandbox/filesystem read boundary needed to prove that Run B cannot read Run A's raw material after selection changes or revocation. These are two distinct integration gates.
- **Code quality: FAIL pending the recovery finding below and production adapter verification.** Focused fake and SQLite tests cover serial replay, changed material, prepare failure, record-save failure, and one publish-failure retry with unchanged retrieval. They do not cover the failure/recovery transition when retrieval changes between a durable record and successful publication, nor an actual atomic filesystem publisher.

## Findings

### 1. High — production publication and delegate isolation are absent (two separate gates)

**Evidence / affected symbols:** `CraftKnowledgeService.BuildForRun` refuses a nil publisher at `internal/application/service/craft_knowledge.go:150-154`, while `internal/container/container.go:2639-2647` constructs `CraftKnowledgeConfig` without `Publisher`. The only publisher implementation in the reviewed diff is `t05Publisher` in `internal/application/service/craft_knowledge_t05_test.go:237-301`; its in-memory `visible` map is not a filesystem or sandbox boundary. `KnowledgeRunDir` still supplies a sibling relative path under the persistent Workspace (`internal/modules/craft/knowledge.go:38-49`). The approved Spec requires only chosen, authorized knowledge to reach a Run (Spec line 62), while its persistent Workspace and sandbox decisions are at lines 57-58. The prior fix-1 review and material-boundary design identify the same read risk.

**Impact:** Current production assembly cannot create a Run package. If a publisher is added without a fresh private delegate view, a delegate able to read the persistent Workspace may still open old Run A material during Run B. Atomic publication alone does not enforce selected-only reads.

**Smallest defensible correction:** Implement and test a production publisher that privately prepares, digest-verifies, and atomically exposes a complete package; wire it into container assembly. Independently, bind the admitted server Run ID to a fresh execution view exposing only that Run's sealed package and chosen inputs, and prove from inside Run B that old Run A paths and session state are inaccessible after revocation. Keep #124 unverified until both gates pass.

### 2. Medium — a failed publication can strand its immutable record if retrieval changes before retry

**Evidence / affected symbols:** On first build, `BuildForRun` saves the immutable `PackageDigest` at `internal/application/service/craft_knowledge.go:180-208`, then calls `Publish` at lines 210-224. A publish failure intentionally leaves the private candidate. On retry, the service rebuilds from live access/search at lines 170-180 and rejects a different package digest at lines 181-184 *before* it can ask the publisher to publish the original candidate. `CraftKnowledgePackagePublisher` has no operation to resume the already sealed candidate by Run ID and accepted digest. `TestCraftT05PublishFailureRemainsPrivateAndRetryPublishesSamePackage` (lines 153-186) retries only while retrieval bytes remain unchanged; the changed-retrieval test (lines 188-227) starts from an already published package.

**Impact:** A transient publish failure followed by an edit, reindex, deletion, or changed search order can leave a durable source record and private candidate that this service can never publish or resolve. The record can be projected as historical actual-source evidence even though no material was handed to a Run. This is a consistency and recovery gap for #124's immutable actual sources.

**Smallest defensible correction:** Persist publication state with the record or a package pointer, and on an unpublished-record retry resume the exact sealed candidate by its accepted digest rather than rerun retrieval. Make a published record the prerequisite for delegation and for claiming sources were actually handed to a Run. Test publish failure, changed retrieval, retry/recovery, and record projection before and after successful publication.

## Corrected behavior and limits

For a serial same-Run call, the request digest is checked before package construction (`craft_knowledge.go:158-169`), and a matching request is rebuilt and compared against the immutable full-package digest before any publisher call (`176-184`). `Prepare` precedes `Records.Save`; record-save and prepare failures call `Discard` (`194-208`). The test publisher copies package bytes and makes successful serial replays no-ops (`craft_knowledge_t05_test.go:253-301`). This is a sound service-side contract for immutable bytes, subject to the findings and to real adapter behavior. `BuildForRun` still accepts a path-safe caller-supplied Run ID; central admission must bind it to the authoritative Run. No evidence here establishes the actual delegate read boundary.
