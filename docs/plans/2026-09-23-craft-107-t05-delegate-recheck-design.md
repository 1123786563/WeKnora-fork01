## Exact insertion point

`CraftDelegateService.Delegate` already separates (1) stored result replay, (2) prepared-but-unsettled `GetTask` observation, and (3) fresh dispatch. Insert a **server-side dispatch authority guard only in branch 3**, after `GetTask` definitively returns `craft.ErrNotFound` and after lifecycle `GuardDispatch`, immediately before `PrepareTask`. This ensures an unauthorized new delegation creates no prepared task and never reaches `executor.Execute`. Do not run it in result replay or observation: those paths must resolve an already attempted side effect and must never submit a second prompt. The guard reads the accepted knowledge record by `task.Fence.RunID`, not model `goal`, `input_refs`, query, or a newly retrieved package. It invokes `RevalidateForDispatch` once with current actor context; denial returns before PrepareTask.

`PrepareTask` itself is idempotent and may race another caller. After it returns, the service must distinguish **this caller created the fresh dispatch** from **another caller already prepared it**. The current `PrepareTask` return type exposes only `craft.Task`, so a same-request concurrent replay could otherwise pass a precheck and call `executor.Execute` twice. Recommended narrow addition: an atomic `PrepareTaskIfAbsent`/prepare outcome from `craft.Store` that reports `created` versus `existing` under its existing Run/tool-call transaction. `created` may proceed to Execute; `existing` must go to observe (with exact request-hash check) and never call Execute. Preserve the executor's own persisted prompt-message-ID/snapshot defense as a second fence. If repository review proves the existing tool journal already serializes this branch, document that evidence and avoid adding a redundant method; a read-before-write check alone is not proof.

## Identity seam and T08 dependency

`craft.Task.Scope` is currently the **Task storage owner**: registration reads `sessions.user_id`, creates `craft.Scope` from that owner, and `CraftStore.PrepareTask` requires `run.OwnerID == task.Scope.UserID`. `Fence.Owner` is the worker lease token, not a human actor. `RevalidateForDispatch` currently requires `types.CallerFromContext(ctx).UserID == scope.UserID` and compares the loaded record scope to that same scope. Therefore calling it with today's `task.Scope` would either deny a legitimate Collaborator or, if worker context is wrong, authorize as Task owner. Do not substitute model data or `Fence.Owner`.

T08 must first persist and restore immutable `Run.ActorUserID`, and the worker must carry an authenticated `types.Caller` for that actor. The recheck entrance needs two typed identities: owner-scoped record lookup/workspace (`task.Scope`) and actor-scoped authorization (`tenant, actorUserID, sessionID`). The smallest safe change is an additive `RevalidateForDispatchForActor(ctx, ownerScope, actorScope, runID)` (or a typed request with those fields), which asserts actor equals durable Run actor and current context Caller, loads the immutable record under owner scope, then checks actor `TaskWrite` and all recorded source coordinates under actor ACL. Keep existing method as compatibility wrapper only if it cannot be called by production for Collaborator runs. The Run ID must be cross-checked with `task.Fence` and the durable Run row. A missing T08 actor or missing T05 record/ACL port fails closed; no fallback to owner principal.

1. **T08 prerequisite:** `agent_run` contracts/store/worker and tests per `2026-09-23-craft-107-t08-actor-principal-design.md`. Verify current Caller is restored before capability assembly and tool invocation; lease owner never becomes WebUser principal.

Add owner/actor aware recheck without rebuilding or publishing; test collaborator current TaskWrite and source access, revoked role/source, wrong durable actor, record mismatch, no record, empty accepted record.
3. **Delegation owner:** `internal/application/service/craft_delegate.go`, `craft_delegate_test.go`, `craft_guard_wiring_test.go`. Introduce a single `CraftDispatchAuthority` interface/field alongside lifecycle guard, invoked at the fresh branch point only. Test result replay and prepared observation do not call authority, denial prevents PrepareTask/Execute, fresh succeeds, concurrent same-key loser observes.
4. **Store owner only if needed for race proof:** `internal/modules/craft/contracts.go`, `internal/application/repository/craft_workspace.go`, paired tests. Add atomic created/existing prepare outcome; do not change request-hash or fence semantics.
5. **Assembly owner after T05/T08 checkpoints:** `internal/container/container.go` or a small `internal/container/craft_dispatch_authority.go` plus assembly test. Wire the existing `CraftKnowledgeService` and actor/Run lookup to the delegation service once. Production must reject new dispatch when the authority service is absent; existing fail-closed runtime/default-off assembly remains valid. Avoid concurrent `container.go` edits with current T08/T19/RunView work.

The authorization check is a point-in-time gate immediately before preparation, not a perpetual ACL lease. Source files must remain read-only within the RunView mount, and T05's current-ACL check at source opening remains required. Only the integrated actor-aware recheck plus Run-scoped material mount can close the dispatch/read boundary.
