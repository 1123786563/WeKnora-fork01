## Findings

1. **Medium — the required live proof does not identify a positive ACK-exception counter delta.** The existing live fixture sends `reuse` on `w`, its original socket (`test_controller_integration.py:523-526,699-715`), and asserts the `reuse-ok` marker. It checks the different-source canary's loopback-drop delta (`:693-698`), but does not snapshot either of the two WebDriver exception counters before and after the marker. `helper.py:134-137` creates those counters, while `helper.py:334-365` reports only labeled drop/target counters. Thus a marker could pass via another allowance or an unexpected ruleset without proving that the exact ACK rule carried it. The Task 1 plan explicitly requires a positive exact exception-counter delta. **Smallest correction:** in the parent disposable acceptance run, parse the two specific nft rule handles/expressions from raw rules, verify both full tuples and the parsed ACK mask, then compare their counters immediately before/after the same-FD marker. Retain the existing distinct-source drop assertion and bind these receipts to the same image/namespace/inode/run. If that proof is intended to be permanent, add it to the live fixture.

2. **Low — valid expanded IPv6 literals fail the exact dump comparison.** `webdriver_rules` accepts any matching-family loopback literal (`helper.py:121-126`), as does `barrier_adapter.validate_webdriver_flow` (`barrier_adapter.py:80-87`). `_parse_sock_diag_record` compresses the kernel IPv6 address (`helper.py:195-198`), but `parse_sock_diag_dump` compares it with the original host string (`helper.py:208-209,275-280`). For a flow such as `0:0:0:0:0:0:0:1`, the kernel's `::1` record is incorrectly classified absent. The test covers only `::1` (`test_controller_integration.py:125-143`). This is fail closed, but contradicts the admitted IPv6 input contract and can block installation. **Smallest correction:** normalize the two expected addresses with `ipaddress.ip_address(...).compressed` after validation, and test an expanded IPv6 literal.

3. **Low — same-source-port reuse negative proof is absent.** The fixture retains the original FD for its marker, then checks only a new connection from a *different* source port (`test_controller_integration.py:693-715`); there is no forced bind of the old port after close. The architecture ruling and plan call for this test when safely constructible, or a recorded reason why it cannot be run. The outstanding risk is a stale exact tuple after socket loss. **Smallest correction:** in the disposable live proof, attempt a bounded old-port bind/connect after closing the attested FD if the fixture can do so safely; otherwise record the kernel/socket lifecycle reason it cannot and keep the residual risk in the acceptance record.

The approved product no-egress requirement and Task 1 live acceptance still need the parent disposable run with the exact positive counter, fresh-connection, no-egress and cleanup receipts. Finding 1 is a missing required acceptance assertion.

**Code quality: pass with low-risk correction requested.** Parser/query bounds cover deadline, datagram/aggregate bytes, message and record counts; they reject sender PID, sequence, local port ID, bad framing/type, malformed attrs, interruption, truncation, NLMSG_ERROR, missing completion and absent/duplicate exact records. Socket closure is in `finally` (`helper.py:286-332`); tests exercise success and timeout closure and the main parser rejection classes (`test_controller_integration.py:134-259`). The captured kernel dump's header port ID and sender PID agree with this parsing strategy. The IPv6 normalization mismatch in finding 2 should be fixed before declaring all supported address representations accepted. No source or test execution was changed by this review.
