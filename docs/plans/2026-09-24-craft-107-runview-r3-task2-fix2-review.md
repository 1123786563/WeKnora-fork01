## Findings

1. **Medium — the temporary-name unlink can still remove a concurrent replacement.** `writeRunViewInputAtomicWithBeforePublish` creates `.craft-input-*` in an accessible digest directory (`craft_runtime.go:753-755`), publishes its current name via `Linkat` (`:782`), then calls `Unlinkat(dirFD, tempName, 0)` (`:794`) without exclusive directory ownership. Another actor can observe the temporary name, rename it away after the link, and create a different file at that name before the unlink. The unlink then deletes that actor's file. The `Fstat` at `:777` checks the old descriptor, and the `Fstatat` at `:790` checks the *final target*, so neither protects the temporary name. The new replacement test swaps a **final** path before a later failed publication (`craft_runtime_test.go:352-385`); it does not exercise this interleaving. **Impact:** the fix2 promise that cleanup never deletes a concurrent replacement is not met, although the old final-path and digest-directory rollback has been removed. **Smallest defensible correction:** retain the temporary hard link as a dirty marker until the generation is retired under exclusive ownership, or establish exclusive directory ownership spanning creation, publication, and temporary-name removal. Do not add a check-then-unlink of the temporary path. Add a deterministic swap at the publication/removal boundary.

2. **Low — the created-directory failure test supplies its own cleanup; the production path does not.** After successful `Mkdirat`, helper failures on `Openat`, `Fchmod`, or `Fsync` return `created=true, fd=-1, err` without removing or marking the newly created directory (`craft_runtime.go:710-733`). The new test's injected callback itself calls `Unlinkat(..., AT_REMOVEDIR)` before returning the sentinel error (`craft_runtime_test.go:394-409`), so its no-orphan assertion does not test production cleanup. `Fstat` failure also returns `ErrConflict` instead of the syscall error (`craft_runtime.go:736-739`). **Impact:** an error can leave a directory behind and, for `Fstat`, obscure its cause. An empty canonical directory does not by itself reach Prompt: retry inspects the exact tree and may fill the valid subset. **Smallest defensible correction:** preserve the original `Fstat` error; either safely retire a failed generation and allocate a fresh one, or explicitly document/test that a retained empty directory is a valid recoverable subset. Inject the failure at the real helper operation rather than deleting the directory in the test callback.
