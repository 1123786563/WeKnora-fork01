## Findings

No blocking correctness or security finding was established in the six-file B4 delta. The following is a remaining full-ticket gate rather than a B4 regression:

### 1. High, integration gate — membership panel does not establish content-path enforcement

**Evidence / affected surfaces:** `apps/web/src/features/craft/routes.tsx:321-391` loads and renders the membership panel. The route tests mock `client.request` (`routes.access.test.tsx:35-69`) and check the panel, not actual protected content endpoints. The workbench's separate `canWrite` projection still comes from workspace owner identity (`routes.tsx:453,700,758`); B4 does not implement collaborator Run admission, which belongs to T09. The prior central-A review explicitly leaves list, direct content, preview and download path enforcement to central support B.

**Impact:** A user-visible access panel and successful mocked mutations cannot show that a revoked member loses existing Task content or that a Collaborator receives only their own allowed edit authority. Treating B4 as full #126 completion would overstate authorization coverage.

**Smallest defensible correction:** Complete and review central content-path ACL enforcement, join the real authenticated grant/revoke/list endpoints to the workbench, verify revocation on listing/direct/preview/download, and test collaborator admission under T09. Run a browser viewport and assistive-technology pass on the mounted panel before final UI acceptance.
