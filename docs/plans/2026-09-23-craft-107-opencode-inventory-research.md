# Craft RunView R1: OpenCode 1.18.4 inventory research

Research date: 2026-09-23. Scope: read-only protocol research for the pinned lock; no production or test changes.

## Verified facts (pinned inputs and primary source)

- Local lock: `docker/craft/opencode.lock.json` pins OpenCode `1.18.4` at commit `49c69c5ed3ccf706b61b3febb43c8aaff7f8325e`; it records the legacy surface as `POST /session -> {id}` and does not list a session-list or GET-session route. The lock also says `/doc`'s `info.version=1.0.0` is not the runtime version signal.
- The authoritative source at that exact commit defines the v2 list route as `GET /api/session` in [`packages/protocol/src/groups/session.ts` lines 98-126](https://github.com/anomalyco/opencode/blob/49c69c5ed3ccf706b61b3febb43c8aaff7f8325e/packages/protocol/src/groups/session.ts#L98-L126). The response is `{data: Session.Info[], cursor:{previous?,next?}}`; default list limit is 50 in [`packages/server/src/handlers/session.ts` lines 16-65](https://github.com/anomalyco/opencode/blob/49c69c5ed3ccf706b61b3febb43c8aaff7f8325e/packages/server/src/handlers/session.ts#L16-L65).
- The exact GET-session route is `GET /api/session/:sessionID`, with `data: Session.Info`, in [`groups/session.ts` lines 157-170](https://github.com/anomalyco/opencode/blob/49c69c5ed3ccf706b61b3febb43c8aaff7f8325e/packages/protocol/src/groups/session.ts#L157-L170); handler lookup is by `ctx.params.sessionID` in [`handlers/session.ts` lines 90-105](https://github.com/anomalyco/opencode/blob/49c69c5ed3ccf706b61b3febb43c8aaff7f8325e/packages/server/src/handlers/session.ts#L90-L105).
- List supports request-scoped directory selection using query `directory` (absolute path), `project`, `subpath`, `workspace`, `limit`, `order`, `search`, and opaque `cursor`, per [`groups/session.ts` lines 25-104](https://github.com/anomalyco/opencode/blob/49c69c5ed3ccf706b61b3febb43c8aaff7f8325e/packages/protocol/src/groups/session.ts#L25-L104). The common location middleware also accepts `location[directory]` or `x-opencode-directory` (URL-decoded), defaulting to `process.cwd()`, and `location[workspace]` or `x-opencode-workspace`, in [`packages/server/src/location.ts` lines 29-47](https://github.com/anomalyco/opencode/blob/49c69c5ed3ccf706b61b3febb43c8aaff7f8325e/packages/server/src/location.ts#L29-L47).
- `Session.Info` includes `id`, `projectID`, `title`, `location:{directory,workspaceID}`, optional `subpath`, and created/updated timestamps, in [`packages/schema/src/session.ts lines 18-44](https://github.com/anomalyco/opencode/blob/49c69c5ed3ccf706b61b3febb43c8aaff7f8325e/packages/schema/src/session.ts#L18-L44). Thus list responses carry directory/project identity and timestamps; there is no explicit generation/epoch marker in this schema.
- Create is `POST /api/session` with optional payload fields `id`, `agent`, `model`, and `location`; there is no `title` and no idempotency-key field in the schema, [`groups/session.ts` lines 128-143](https://github.com/anomalyco/opencode/blob/49c69c5ed3ccf706b61b3febb43c8aaff7f8325e/packages/protocol/src/groups/session.ts#L128-L143). The handler forwards `id`, agent/model, and location; if location is omitted it uses the server process cwd, [`handlers/session.ts` lines 67-78](https://github.com/anomalyco/opencode/blob/49c69c5ed3ccf706b61b3febb43c8aaff7f8325e/packages/server/src/handlers/session.ts#L67-L78).

## Inference for RunView reconciliation

- A fresh per-Run container can scope `GET /api/session?directory=<run-directory>` (or the location query/header) and inspect the returned `Session.Info.location.directory`, `projectID`, `id`, `title`, and `time.created`. A follow-up `GET /api/session/:sessionID` can confirm one candidate by ID when the ID is known.
- After a lost create response, inventory can authoritatively establish zero/one/multiple matching sessions only relative to a chosen predicate (directory/project plus creation-time window and any caller-known fields). Since CreateSession accepts neither idempotency key nor caller title, and the response has no generation marker, directory-only matching cannot prove ownership if multiple sessions are created in the same scope. Multiple matches must remain ambiguous; do not auto-select.

## Limitations / protocol discrepancy

- The checked-in lock's pinned `POST /session` legacy notation does not describe the exact v2 source routes at the same commit, which are `/api/session` and `/api/session/:sessionID`. This report does not claim that the legacy route aliases expose list/GET behavior; runtime route compatibility must be verified against the actual binary/container before relying on it.
- Source inspection proves route schemas and handler behavior, not that a particular deployment enables every route or that a lost POST leaves a durable session before the list request races it. No production proof or live-container claim is made here.
