## Finding

**R3-VM-01 — Medium — An order-independent manifest can still fail identical publish replay.** `loadCraftVersion` orders persisted files by path (`craft_version.go:127-143`), while `sameCraftVersion` compares the loaded and incoming slices in their original order (`craft_version.go:157-163`, called at `craft_version.go:310-315`). The new test publishes `filesInDifferentOrder` successfully (`craft_version_test.go:205-212`) but never retries it. On an identical retry with that same unsorted input and selected head, the new digest check passes, the version insert hits its existing identity, then `sameCraftVersion` rejects the reordered persisted files with `ErrConflict`. Impact: a valid retry of an already published selected-head version can report conflict despite identical manifest content, contrary to the plan's retry/idempotency requirement; this may turn a recoverable duplicate promotion into a failed response. Smallest correction: compare file manifests in canonical path order (or canonicalize `in.Files` before both insert and replay comparison), preserving the existing equality checks for ref, MIME, bytes, digest and checks. Extend the new ordering test to repeat the same `PublishWithDraftHead` call and assert the same version ID and one row; include the evidence-bearing promotion path if available.

## Evidence and verdicts

- The R3 OCR defect itself is closed in the reviewed source: `prepareCraftVersion` derives `digest` with `craft.ManifestDigest(in.Files)` (`craft_version.go:72-84`); `DraftHead.Validate` uses that same domain function (`internal/modules/craft/draft_head.go:63`); and the transaction locks the selected head, reads the matching immutable revision, then compares `digest` with `expectedHead.ManifestDigest` before version insert (`craft_version.go:243-279`). A mismatch wraps `craft.ErrConflict`; the regression asserts no `craft_versions` row (`craft_version_test.go:150-180`). The `expectedHead == nil` path skips this new fence (`craft_version.go:243-268`). The report records RED/GREEN focused SQLite tests and no PostgreSQL DSN; I did not repeat them.
- **Spec compliance: FAIL for the assigned task** until the identical replay finding is fixed. The manifest binding required by the OCR finding is implemented, but the assigned plan explicitly requires preserving retry/idempotency and order-independent acceptance.
- **Code quality: FAIL** due to the reproducible ordering mismatch at the persisted replay seam. No security or transaction-boundary defect was found in the new digest check itself. PostgreSQL behavior remains unverified by this review.
