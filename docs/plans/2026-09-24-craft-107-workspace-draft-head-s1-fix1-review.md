## Original findings

1. **High owner/head/files race — closed.** `CraftDraftHeadStore.Read` now projects the authorized Workspace, head, selected revision and files in one SQL SELECT (`craft_draft_head.go:80-96`), with `w.tenant_id`, `w.session_id` and `w.owner_id` predicates in that same statement. PostgreSQL and SQLite provide a consistent statement snapshot, so owner transfer or head advancement cannot create a mixed authorized result across separate queries. The later existence query (`:100-108`) runs only when the authorized SELECT returns no rows and cannot return object refs. The selected read also checks revision source Run/digest against the head and revalidates the full manifest (`:124-139`). This closes the original authorization leak at the read boundary.
2. **Medium unresolved-as-not-found — closed.** `craft.ErrDraftHeadUnresolved` is an independent error (`draft_head.go:15-17`); `errors.Is` no longer classifies it as `ErrNotFound` (`draft_head_test.go:51-52`). An authorized existing Workspace with no head returns that sentinel (`craft_draft_head.go:110-113`).
3. **Medium tenant/source referential checks — closed.** PG 000195 and SQLite 000116 both add the `(tenant_id,id)` Workspace unique key, bind heads to that composite parent, bind revisions to `(tenant_id,workspace_id)` heads, and bind revision source Runs to `agent_runs(tenant_id,run_id)` with `ON DELETE RESTRICT` (both up migrations, lines 1-28). Down scripts remove the three tables and supporting index. The existing RunView schema already uses a restricting Run FK, so this deletion choice is consistent with current RunView retention. The repository tests reject a wrong-tenant head and missing source Run in both dialects; the migration test applies SQLite 000116 up/down/up and, when a DSN is supplied, PG 000195 up/down/up. The fix1 report records the latter passing on disposable PG17.

## Remaining finding

**Low — requested behavioral interleavings and legacy read classification lack direct tests.** `TestCraftDraftHeadSelectedReadUsesOneConsistentQuery` (`craft_draft_head_test.go:132-160`) asserts one SELECT and the selected result but does not interleave `PutWorkspace` owner transfer or a head update with the read, as the fix1 plan and original review requested. The SQL FK test deletes a legacy head (`:114-118`) but never calls `Read` to assert `ErrDraftHeadUnresolved` and `!errors.Is(err, ErrNotFound)` for that persisted row; the latter assertion exists only for the sentinel itself in the domain test. **Impact:** a later change could separate authorization and manifest reads, or remap the legacy row to a generic missing result, without these behavior tests failing. **Smallest correction:** add a repository assertion for the legacy row, and a controlled transaction/hook test that changes owner or head at the read boundary; keep the present single-statement assertion. This is a coverage gap, not evidence of a remaining leak in the reviewed implementation.

## Verdict

**Spec compliance: PASS for S1 Task 1 fix1.** The three original findings are resolved in the exact reviewed files; empty revision 0, distinct legacy unresolved classification, scoped selected reads and paired tenant/Run constraints conform to the S1 seam. This does not certify S2 `Advance`, R4 materialization, or the full Craft product acceptance.

**Code quality: PASS with one Low test gap.** Focused Go tests passed locally; the reported PG17 proof was not independently rerun. The test gap should be filled during the next S1/S2 regression pass, but it does not require another production-code correction for this fix1 checkpoint.
