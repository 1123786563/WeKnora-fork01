# T01 RunView R3 Task 2 — independent Spec and quality review

**Scope:** read-only review of `internal/container/craft_runtime.go`, its focused tests, `CraftRunViewMaterialHandle`, approved Craft web-artifact Spec, ADR-0004/0008/0009, `CONTEXT.md`, R3/R4 design, and the Task 2 plan/report/checkpoint. The checkpoint's two final SHA-256 hashes matched the reviewed files. Its patch is cumulative from HEAD, not an exact pre-Task 2 to post-Task 2 delta; the start hashes alone do not reconstruct the pre-task content. No source, tests, requirements, or concurrent `container.go` edits were changed.

## Findings

1. **Medium — Empty admitted input manifest bypasses current workspace authorization.** `selectedWorkspaceInputs` returns at `internal/container/craft_runtime.go:850-852` before the `craft_workspaces` tenant/owner/session association query at lines 853-862. An admitted empty manifest with a revoked or mismatched workspace still reaches `openVerifiedRunViewInputs` and succeeds when the generation tree is empty. The Task 2 brief requires the current association and an empty exact mount; the existing revoked-association test uses a nonempty manifest. **Smallest correction:** check the workspace association before the empty-manifest return and add an empty-manifest revoked-association test.

2. **Medium — Atomic rename can overwrite an object created after the preflight check.** `writeRunViewInputAtomic` checks `Fstatat` for `ENOENT` at `internal/container/craft_runtime.go:775-780`, then calls ordinary `Renameat` at line 781. If another writer creates the target in that interval, `Renameat` silently replaces it; final digest verification can still pass, masking the concurrent object. The code promises to reject unexpected or changed objects, and rollback can then unlink a replacement by filename at lines 790-806. **Smallest correction:** publish with an atomic no-replace operation (Linux `renameat2` with `RENAME_NOREPLACE`, or an equivalent same-directory hard-link publication where supported), retain the created inode identity for rollback, and add a competing target creation test.

3. **Medium — Distinct admitted refs sharing a canonical path are silently collapsed.** `runViewInputManifest` at `internal/container/craft_runtime.go:501-509` treats a second input with the same SHA-256/name/size as already staged even when its `Ref` differs. The subsequent FileService read loop at lines 428-440 reads only the surviving entry. A missing or corrupt second selected object therefore passes, contrary to the R3/R4 design's instruction to read and verify each selected object. **Smallest correction:** reject duplicate canonical paths with distinct refs as an ambiguous manifest, or verify each selected ref before deduplicating its bytes; add a two-ref test.

4. **Medium — A retry accepts executable or otherwise noncanonical input file permissions.** Newly staged files are set to `0644` at `internal/container/craft_runtime.go:764`, but `inspectRunViewInputTree` at lines 648-674 checks type/link count/size/digest without checking mode. A pre-existing `0755` uploaded code file is accepted as an identical retry. The approved Spec requires uploaded code to remain input material without direct execution capability, and the inspected mount specification currently asserts read-only, not `noexec` (`craft_runview_container_provider.go:597-602`). **Smallest correction:** require the canonical non-executable file mode when reusing staged files and test a `chmod 0755` retry; the later live mount gate must also prove executable denial.

## Verdict and evidence

**Spec compliance: FAIL for Task 2 completion.** The main path does use the admitted typed snapshot, checks selected associations for nonempty manifests, verifies FileService byte count and SHA-256, rejects path escapes/symlinks/extras, and confines writes to the verified generation inputs directory. Findings 1, 3, and 4 leave specified input authorization or material invariants unproven.

**Code quality: FAIL for Task 2 completion.** Descriptor-relative no-follow opens, bounded reads, fsync, and final tree inspection are sound improvements. Finding 2 leaves a concrete concurrent publication race. The cumulative patch and start hashes do not provide an exact isolated task delta for independent change attribution.
