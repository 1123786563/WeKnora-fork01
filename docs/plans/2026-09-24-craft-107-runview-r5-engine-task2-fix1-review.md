## Findings

1. **Medium — the immutable admitted snapshot is only checked for Workspace ID.** `ResolveMaterial` (`internal/container/container.go:2782–2785`) parses the current `run.Snapshot` and compares only `CraftWorkspaceSeed.WorkspaceID` with `task.WorkspaceID`. `craft.Task` has no admitted snapshot identity (`internal/modules/craft/contracts.go:66–76`), so a changed but valid `Query`, `ModelID`, input manifest, selected knowledge, or seed revision with the same Workspace passes. The denial table changes only the Workspace ID (`craft_runview_assembly_test.go:83–85`). **Impact:** the Fix1 plan's explicit “changed immutable snapshot must deny” acceptance is not met; material can be resolved for an admitted identity whose frozen inputs no longer match the original Task. **Smallest correction:** establish a server-owned canonical snapshot identity/digest at admission, compare it to the durable Run before `coordinator.Resolve`, and test a valid snapshot change that retains the same Workspace ID. If that identity is unavailable at this seam, record the missing interface and gate this acceptance instead of treating Workspace equality as full snapshot equality.

2. **Medium — the writer lease can be lost between the read and external side effects.** `AgentRunStore.Get` is a single ordinary `Take` (`internal/application/repository/agent_run.go:95–103`). `ResolveMaterial` checks status/owner/epoch/lease once (`internal/container/container.go:2770–2779`) and then calls `coordinator.Resolve` (`:2789`). The coordinator allocates a generation and calls container/session operations (`internal/container/craft_runview_runtime.go:120–194`) without a writer fence; `CraftRunViewStore.Allocate` authorizes tenant/owner/session, but does not compare status, owner slot, epoch or lease (`internal/application/repository/craft_run_view.go:109–151`). A lease can expire or a Run can be cancelled/reclaimed after `Get` and before those calls. **Impact:** a once-valid Task can cause RunView, Docker, or OpenCode effects after losing writer authority, contrary to the Fix1 pre-side-effect guard. **Smallest correction:** carry an authoritative fenced authorization through each mutating stage, with an operation/lease protocol that serializes revocation or prevents effect dispatch after fence loss. Add a deterministic test that changes the durable Run after the initial read and requires zero subsequent external calls. A second uncoordinated read alone would leave the same race.

3. **Low — missing negative tests for deleted/unknown Runs and same-Workspace snapshot changes.** The 15 denial cases (`internal/container/craft_runview_assembly_test.go:72–121`) exercise stale fields but the reader cannot return an error, so missing/deleted Run handling at `container.go:2770–2772` is untested. There is no `unknown` status case or snapshot mutation that retains the Workspace ID. **Impact:** the required fail-closed cases have source-level checks but no direct zero-call regression proof. **Smallest correction:** let the fake reader return an error or mutate its Run at controlled points, and cover missing/deleted, unknown, and same-Workspace snapshot changes with the existing counters.

## Spec compliance verdict

**FAIL for Fix1's full admitted-Run contract.** The new preflight does correctly reject mismatched tenant, owner, session, Run key, actor caller, worker owner/epoch, non-running status, expired lease, invalid snapshot and wrong Workspace before coordinator access in the synchronous cases covered. It keeps missing registry digest default-off and retains the later runtime fence. Findings 1 and 2 leave the explicit immutable-snapshot and before-side-effect writer-authority requirements unmet. The approved Spec's single-writing-Run requirement and ADR-0008's single-writer boundary are the relevant product constraints; the detailed guard behavior is stated in the Fix1 plan and H3 prerequisite.
