# F17/F20 Control Boundary Fix1 Report

**Status:** Fix1 implementation and targeted verification complete; independent review pending. No staging or commit.

## Scope and changes

Fix1 addresses the three independent F17/F20 review findings:

1. `Stop` and `DelegationStatus` load the tenant-scoped persisted Run, validate route tenant/Run/session identity, then replace request `Scope.UserID` with persisted `Run.UserID` for scoped storage. `CallerFromContext` continues to supply the authenticated actor for `TaskAccessChecker` and collaborator `ActorUserID` policy. No handler contract was broadened.
2. Missing `TaskAccessChecker` now denies through `craft.RequireTaskAccess`; no owner-inference fallback remains. Production container wiring already injects the live checker, and its existing wiring test was rerun.
3. Before any stop intent, result lookup, abort or observation, a found Task must match the requested ID, persisted owner/tenant/session scope, and exact `Fence.RunKey`. Missing delegation still follows the existing unavailable-record response and cannot supply a result or executor operation.

The existing `PutStopIntent` / `PrepareTask` Run-row fence was unchanged. Other affected code and tests: [craft_control.go](../../internal/application/service/craft_control.go), [craft_control_f17_f20_test.go](../../internal/application/service/craft_control_f17_f20_test.go), [craft_interaction_test.go](../../internal/handler/session/craft_interaction_test.go).
