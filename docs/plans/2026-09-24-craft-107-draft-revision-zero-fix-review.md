## Findings

**Low — requested missing/corrupt origin read behavior is only partly tested.** `TestCraftDraftHeadReadRevisionRequiresPersistedZeroOrigin` in `internal/application/repository/craft_draft_head_revision_test.go` asserts that direct UPDATE and DELETE are rejected, then confirms D0 remains readable. The migration test confirms a headless legacy Workspace stays unresolved after a new head is inserted, but does not remove or corrupt a D0 marker after D2 and assert `ReadRevision(..., 0)` fails. **Impact:** a later fallback that ignores a missing or invalid marker could survive the focused suite despite the implementation's current fail-closed check. **Smallest correction:** in a disposable database, temporarily remove the immutability trigger, delete or invalidate the origin after D2, and assert `ErrDraftHeadUnresolved`; leave the production trigger in place. This is a behavioral coverage gap, not an observed runtime failure.

**Low — the historical corruption and owner-transfer tests do not exercise all requested interleavings.** The migration test rejects direct UPDATE/DELETE of D1 rows after D2, and the owner-transfer test reads only after transfer. Neither test attempts `ReadRevision(D1)` with a deliberately absent D1 file/revision after D2, or coordinates a transfer at the read boundary. **Impact:** later changes to historical validation or the joined authorization query have weaker regression detection. **Smallest correction:** add a disposable trigger-disabled corruption read and a controlled transfer/read interleaving. The present one-statement authorization query and mutation guards are sound on inspection.

## Verified behavior and limits

- `PutWorkspace` inserts Workspace, empty head and origin in one transaction; injected origin INSERT failure rolls all three back. `ReadRevision(0)` joins Workspace authorization, current head and origin in one SELECT, requires matching tenant and zero/empty identity, and returns unresolved for missing origin or head. The origin survives D1/D2 head advancement.
- The paired migrations backfill valid empty S1 heads and selected heads only with a matching current revision, contiguous positive revision count, terminal same-owner/session source Runs and at least one file per revision. Headless legacy rows are left unresolved. The selected lineage query does not recompute manifest digests; the later positive-revision read validates the requested revision's digest and file metadata. This limit is disclosed in the implementation report.
- PostgreSQL and SQLite triggers reject UPDATE or direct DELETE of origins, revisions and files while the Workspace exists; the parent Workspace DELETE can cascade history. Both down migrations remove the added triggers and origin table. The focused migration test performs up/down/up for each engine when the corresponding database environment is selected. The `sqlite`/`postgres` subtest labels do not themselves choose a dialect: `openCraftDB` uses the test DSN, so the report's separate PostgreSQL DSN run is the evidence for PostgreSQL parity.
- This review does not certify R4 materialization or object-byte verification. The D0 fix does not touch that runtime file.

## Verdict

**Spec compliance: PASS for the D0 prerequisite.** The earlier Medium provenance finding is resolved by a persisted, scoped, immutable origin created atomically for new Workspaces and conservatively backfilled for S1 history. No effective Critical/High/Medium finding remains in this fix scope.

**Code quality: PASS with two Low test gaps.** The focused SQLite suite passes independently; reported PostgreSQL 17.9, race and migration rollback evidence is plausible from the inspected tests and report but was not independently rerun here. R4 Task 1 can proceed with the Low coverage gaps tracked.
