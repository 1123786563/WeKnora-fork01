# T01 RunView OpenCode inventory Task 1 independent review

**Scope:** Exact new `internal/modules/agentruntime/agent/opencode/inventory.go` and `inventory_test.go`, checkpoint manifest/patch, provider plan Task 1, pinned OpenCode 1.18.4 inventory research, and the existing shared `client.go` redirect policy. No source or test edits were made.

## Verdict

- **Spec compliance: FAIL.** The client validates session ID, directory and project metadata, detects duplicate/foreign records and cursor loops, and returns errors for unavailable v2 routes. It does not prove a complete inventory when the response omits the required `cursor` object, or when a same-origin redirect drops the project filter. Both paths can return a success result that a provider may treat as authoritative.
- **Code quality: FAIL pending the findings below.** The typed response and bounded pagination are otherwise coherent. The existing tests pass but encode the missing-cursor behavior as a successful final page, and the redirect test allows the project query to disappear.

## Findings

**INV-1 — Medium — A missing or null cursor envelope is treated as end of inventory.** `ListSessions` in `inventory.go` decodes `Cursor` as a pointer and sets `next=""` when it is nil (near lines 72–113). The pinned protocol research specifies `{data, cursor:{previous?,next?}}`; Task 1 explicitly requires a missing cursor to fail closed. A non-full page with omitted or null `cursor` returns successfully even though page completeness cannot be established. The current `writeInventoryList` helper omits `cursor` on its last page, and `TestInventoryFollowsSameOriginRedirectWithoutLosingDirectory` also succeeds with no cursor. **Impact:** a partial response could be promoted to authoritative inventory; a coordinator could select an incomplete set or initiate creation while an existing session was omitted. **Smallest correction:** require a non-null cursor object on every successful list page, allowing an absent/empty `next` only inside that object; update valid fixtures and add missing/null cursor failures.

**INV-2 — Medium — Same-origin redirects can remove the list's project and pagination scope.** `ListSessions` sends `project`, `limit`, and later `cursor` in the query, but `directoryRedirectPolicy` in shared `client.go` preserves only the directory header and rejects a conflicting `directory` query. The inventory same-origin redirect test redirects `/api/session?project=...&limit=100` to `/api/session/redirected` with no query and still expects success. Exact project values on returned rows cannot prove that the server listed *all* project sessions after the filter was lost; dropping a later cursor similarly breaks completeness. **Impact:** an unscoped or first-page response can be accepted as a complete project inventory. **Smallest correction:** for inventory requests, reject redirects that change or drop the project, limit, or cursor query values (or disable redirects for inventory reads); add same-origin query-loss tests for list and later pages. Preserve the existing directory and origin checks.
