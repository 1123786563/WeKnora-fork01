# T01 RunView provider Task 2 — independent scoped review

**Scope:** Only `internal/container/craft_runview_container_provider.go` and `_test.go` at the Task 2 checkpoint. Reviewed against the approved Craft #107 spec, `CONTEXT.md`, ADR-0003, the RunView provider design/plan, the R1 coordinator review, and the Task 2 report/manifest. No source or test files changed.

## Verdict

- **Scoped Spec compliance: FAIL.** The provider has the intended deterministic generation identity, one-shot container marker, exact inspected container/network/mount checks, and complete typed inventory dependency. The sandbox-root path check can nevertheless admit a forbidden host path through a symlink. The available exact GET-by-ID inventory method is not used to recheck a unique listed session as the provider design requests.
- **Scoped code quality: FAIL.** Focused tests pass, but the foreign/misconfigured-container table never reaches the security inspection under test because its seeded containers have no durable create marker.
- **Production T01/RunView acceptance: NOT VERIFIED.** There is no concrete engine adapter or assembly; `docker/craft/opencode.lock.json` still has `container_digest: null`. The fake engine proves local contract behavior only. No Linux image, live route, private network topology, mount, restart, or Run A→B isolation claim follows from this checkpoint.

## Findings

1. **High — sandbox root symlink can bypass forbidden host-path policy.** `prepareSandboxRoot` checks the configured spelling against `/home`, `/Users`, `/var/run`, and other forbidden roots before `EvalSymlinks`, then returns the resolved path after only checking that it is absolute and non-root (`craft_runview_container_provider.go:700-723`). For example, a configured `/srv/craft-root` symlink resolving under `/home` passes the first check, and the resolved home path becomes the source parent for the generation's input, output, and OpenCode HOME bind mounts (`:635-663`, `:561-569`). `Chmod` also changes the resolved directory. This violates the no host-home/source mount contract and can expose host material to the container. **Smallest correction:** reject symlink components or apply the forbidden-path and dedicated-root checks to the fully resolved path before chmod or layout creation; add a symlink-to-forbidden-root test.

2. **Medium — security mismatch tests are blocked by the missing marker.** The `TestCraftRunViewContainerProviderRejectsForeignAndMisconfiguredContainers` table and wrong-probe case seed engine facts with `seedContainer` (`craft_runview_container_provider_test.go:135-181`), which never creates the required `.container-create-attempted` file. `InspectOrCreateContainer` returns at the marker check (`craft_runview_container_provider.go:291-324`) before `startAndVerify` can validate the mutated image, mount, user, network, command, or probe. The tests therefore pass if those validations are accidentally removed. **Impact:** claimed fail-closed behavior is not protected by meaningful regression tests. **Smallest correction:** create a valid generation through the provider first, mutate the fake's inspected facts/probe, then call it again; assert the error arises after marker validation and that no replacement is created.

3. **Medium — unique session metadata is not rechecked by exact GET.** The provider's session API exposes only `ListSessions` and `CreateSession` (`craft_runview_container_provider.go:161-179`); `FindSessions` marks a valid-looking list authoritative without calling Task 1's available `Inventory.GetSession` (`:346-373`). The approved provider design specifically calls for GET-by-ID when available before treating session metadata as binding evidence. **Impact:** a stale or inconsistent list row can be promoted into a bound runtime without the exact ID's current metadata check. **Smallest correction:** expose typed `GetSession` in the private session seam and recheck the unique candidate's ID, project and directory before returning it as authoritative; test list/GET disagreement and GET failure. If this GET requirement is intentionally deferred, record an explicit design ruling before binding is enabled.
