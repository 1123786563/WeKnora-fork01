# Craft #107 R5 RunView fence architecture

Date: 2026-09-24. Read-only recommendation for the parent; no production or test changes. Sources: `CONTEXT.md`, approved `docs/specs/2026-09-23-craft-web-artifact-spec.md` (one Task/Workspace with distinct Runs, server-authoritative stop/recovery), ADR-0008 (at most one writing Run), R5 Task2 Fix1 plan and independent review, and the cited code below.

## Evidence and boundary

`craft.Task` has a `Fence`, `WorkspaceID`, inputs and request hash, but no admitted snapshot identity (`internal/modules/craft/contracts.go:66`). `AgentRunStore.Admit` stores the final seeded snapshot and derives an admission request hash from it (`internal/application/repository/agent_run.go:411–437, 741–744`); the durable row already has `request_hash`. `AgentRunStore.Get` is an ordinary read (`:95`), while `ClaimDriver` and `Renew` use fenced status/epoch/owner predicates (`:1038–1159`). `ResolveMaterial` compares the currently read snapshot's Workspace ID to Task Workspace ID and then calls `coordinator.Resolve` (`internal/container/container.go:2769–2789`). This cannot prove that the Task was prepared from the same frozen snapshot, and its authorization expires at the read.

`CraftRunViewStore.Allocate` only joins Run owner/session (`internal/application/repository/craft_run_view.go:109–151`). The coordinator then allocates, invokes `InspectOrCreateContainer`, optionally records one-shot session intent, and invokes `CreateSession` (`internal/container/craft_runview_runtime.go:120–194`). Those stages currently have no shared writer authorization. A second `Get` at any point merely moves the race.

## Recommendation: two server-owned identities

1. **Frozen admission identity.** At the same admission transaction that finalizes the seeded snapshot, persist a domain-separated canonical digest (for example `sha256("craft-run-snapshot-v1\0" || canonical-final-snapshot)`) and its algorithm version. The exact canonical bytes must cover every immutable field in the *final* admitted snapshot, including query/model, input manifest, selected knowledge and workspace seed/revision. Reject absent, unknown-version or unparsable identities. Bind the digest from the admission result into Task construction as `AdmittedSnapshotDigest`; do not derive it in `ResolveMaterial` from `run.Snapshot`. The guard compares Task digest to the authoritative Run's persisted digest and also verifies the persisted digest matches the Run snapshot bytes. If reusing `agent_runs.request_hash`, prove it is exactly this canonical final-snapshot digest and is never repurposed; current `admissionRequestHash` includes AssistantMessageID, so a distinct named field is clearer. Task `RequestHash` is the delegation idempotency key and must not silently serve as this identity.
2. **Writer authority and side-effect claim.** Make a repository-owned `CraftRunViewOperationAuthority` port, consumed by the coordinator, rather than letting `RunViewStore` infer writer authority from the key. `BeginEffect(ctx, key, fence, digest, generation, kind)` atomically locks the Run transition row, verifies tenant/owner/session/actor, exact owner/epoch/status/lease and snapshot digest, verifies the active session writer slot, and records a durable, unique effect intent for `(tenant, run, generation, kind)`. `kind` distinguishes Docker create, Docker start and OpenCode create. The returned claim is an opaque server token, never a caller-provided authority value. `FinishEffect` records observed identity/outcome; an unknown outcome stays unresolved. `Allocate` must accept the same fence/digest and execute its allocation under that authority transaction, before any external operation. Read-only Inspect/observe may run without a claim; every create/start dispatch needs one.

**Revocation ordering is the critical contract.** Every cancellation, wait/terminal transition, lease reclaim and writer-slot transfer must use the same Run transition lock and check for unresolved effect intents. Once `BeginEffect` commits, those transitions cannot declare the old writer revoked or grant a new writer until the intent is finished or reconciled. Lease expiry alone may make an intent *reconciling*, but cannot free the slot. The dispatching worker may send only the particular claimed effect, once; after it returns, it must record outcome and reacquire fresh authority before the next stage. If cancellation wins the lock first, `BeginEffect` fails and there are zero later external calls. If the claim wins first, cancellation waits for that already-authorized effect to resolve; this is the linearization point, not a promise to undo an in-flight call. An expiring TTL without this pending-intent rule is insufficient. Keep operations narrowly bounded; never hold a DB transaction across a Docker/OpenCode call.

The existing `SessionCreateIntentAt` is the one-shot OpenCode marker; fold it into (or make it obey) this Run-level claim protocol, preserving its no-resend rule. Docker create/start also need durable intent and deterministic generation/container identity; if Docker cannot establish whether a previous call took effect, leave the RunView unresolved and block reclaim until inspection or manual reconciliation. Never create a replacement generation on an unknown outcome. Claim acquisition failure, DB unavailability, missing digest or missing transition integration must fail closed before external dispatch. If all Run transition paths cannot be made to honor unresolved intents in this fix, restrict the fix to snapshot identity and keep production material resolution disabled; an assembly-only check cannot close Medium 2.

## Ownership and migration

- `internal/modules/craft/contracts.go` and `run_view.go`: typed snapshot identity and effect-authority port; no SQL or Docker concepts in Task-facing API.
- `internal/application/repository/agent_run.go` plus migration: atomic admission digest, locked effect-intent transitions, and Claim/Renew/cancel/reclaim coordination. The Run repository owns writer truth. A new table keyed by Run/generation/kind is preferable to ad hoc booleans on RunView.
- `internal/application/repository/craft_run_view.go`: Allocate with exact fence/digest predicate in the same transaction; no independent authority decisions.
- `internal/container/container.go`, `craft_runview_runtime.go`, provider: pass authority; claim immediately before each mutating provider call; record outcome; keep production feature gate closed until complete.

Existing Runs lack the new identity. Backfill only if their persisted final snapshot and admission hash can be proven consistent with the original admitted bytes; otherwise mark legacy Runs non-resumable for material creation, preserve their history and expose recovery/unknown status. Additive migration keeps existing RunView rows readable; unresolved legacy allocations require reconciliation, never automatic new generation. This sacrifices automatic resume for ambiguous rows rather than inventing authority.

## Deterministic verification

Use barriers at `Get→Allocate`, `Allocate→Docker create`, `Docker create→start`, and `BeginSessionCreate→OpenCode create`. Race each against cancel, lease reclaim, owner/epoch change and slot transfer using one real transactional test database and fake external call counters. Assert a transition committed **before** claim prevents the call; a claim committed first makes the transition wait/reconcile and permits at most that single claimed call; no later stage runs on the old fence. Test crash after intent commit before dispatch and after dispatch before Finish: retries inspect by deterministic identity, never blindly resend non-idempotent CreateSession. Test exact same Workspace but changed query/model/input/knowledge/seed revision against the frozen admission digest, plus missing/unknown digest and Run. Keep positive valid-Run resolution and existing one-generation/idempotency tests. Tests must control ordering with channels/DB locks, not sleeps or wall-clock timing.
