## Retry and reproducibility assessment

`Acquire::Retries "3"` is finite, but [APT documents it as retries of individual failed files](https://manpages.debian.org/trixie/apt/apt.conf.5.en.html); it does not retry the failed *whole* package install after the remaining archives 502. [Docker documents locked APT cache mounts](https://docs.docker.com/build/cache/optimize/) that persist package downloads across attempts and [the APT cache retention setting](https://docs.docker.com/reference/dockerfile/) needed on Debian-derived images. One bounded strategy is to retain downloaded `.deb` files in a BuildKit `sharing=locked` `/var/cache/apt` mount for the large runtime install, with a finite whole-install retry under the existing 1200-second outer timeout. Re-run `apt-get update` with each attempt or keep one signed index set for the bounded retry; never use `--allow-unauthenticated`, `Trusted=yes`, `--fix-missing` as a success shortcut, or remove binary SHA checks. The cache is only an optimization and must not become a prerequisite for a clean build. This is a plausible recovery, not proven until a build completes.

The mirror change does not add package version pins. The existing `debian:bookworm-slim` tag and APT package resolution remain mutable; the current SHA check makes the OpenCode binary repeatable, while the final image contents can drift until base and Debian package versions/snapshot are locked. The lack of a final image digest is therefore material. No broad reproducibility claim is supported by this scoped edit.
