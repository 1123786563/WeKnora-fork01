## 一、做了什么（对照 #134 验收清单）

纵向切片：一个 Workspace 同一时刻至多一个写 Run，持久化为数据库行，绑定 Task（=Session）、Workspace、Run 与 draft-head revision；只读面永不触碰租约；unknown 结局保留 fence；仅在权威核验后释放/接管。

### 1. 迁移（SQLite `000130_craft_writer_lease` / PG `000209_craft_writer_lease`）

`craft_workspace_writer_leases`：`workspace_id` 主键 = 每 Workspace 恰一行，即 CAS 身份；`UNIQUE(tenant_id, run_id)`；列 `session_id`（Task 身份）、`run_id`、`revision`（获取时 draft-head revision）。**刻意不 FK `agent_runs`**：租约必须能比"不可观察的 run 行"活得久（unknown 保留 fence），释放事务内改为对权威 run 行复验。FK 仅指向 `craft_workspaces(id)` 与 `sessions(id)`（PG）/复合键（SQLite），均 ON DELETE CASCADE。down = DROP INDEX + DROP TABLE。

### 2. 领域纯规则（internal/modules/craft/lifecycle.go，本任务所有权文件）

- `WriterLease{WorkspaceID, TaskID, RunID, Revision}`、`WriterAcquisition{Outcome, Lease, Holder}`（Outcome 复用 T00 冻结 `WriterAcquireOutcome`：acquired/conflict/unknown）
- 释放依据常量：`WriterReleaseVerifiedCompletion / ConfirmedStop / AuthoritativeRecovery / Unknown`
- `WriterRunFacts{Observed, Status, PendingToolWriters, PendingDelegations}` + `WriterRunTerminal` + `WriterLeaseReleasable`（Observed 且终态且零未决写手才可释放）+ `WriterLeaseTakeover`（无持有恒可取；持有者权威可释放才可被接管）——**不可观察（unknown）永远不是许可**

### 3. 存储（internal/application/repository/craft_workspace.go，具体类型方法，未动 `craft.Store` 共享接口）

- `AcquireWriterLease`：事务内 `FOR UPDATE` 锁定并授权 workspace 行 → 读 draft-head revision 作栅栏 → 无行则 `INSERT ... ON CONFLICT DO NOTHING` CAS（恰好一个赢家；输家重读持久行）；同 Run 重试幂等 acquired；异 Run 走接管判定：观察持有者 Run 权威事实（`agent_runs.status` + `agent_tool_calls`/`craft_delegations` 未决计数，与 `CraftDraftHeadStore.Advance` 同口径）→ 领域规则决定接管（CAS 替换旧行，防并发双接管）或**稳定 conflict**（携带 Holder 投影，非错误）
- `ReleaseWriterLease`：`unknown` 依据直接 `ErrBusy` 保留 fence；仅持有 Run 本人可释放（`ErrForbidden`）；释放前在同一事务内对权威 run 终态 + 零未决写手复验，不满足即 `ErrBusy`（fence 保留）；`DELETE ... WHERE run_id=?` CAS
- `GetWriterLease`：只读投影，保持 `GetWorkspace` 同形 ACL（跨租户/跨会话 404、他人 403）

### 4. 服务缝（internal/application/service/craft_workspace.go，本任务所有权文件）

`CraftWorkspaceConfig.WriterLeases`（新可选依赖，`CraftWriterLeaseStore` 接口，`*repository.CraftStore` 满足；nil 时写者面 fail-closed `ErrUnsupported`，不影响既有构造测试）+ 三方法 `AcquireWriter / ReleaseWriter / WriterLease`（scope 解析 workspace 后委托 store）。只读路径（Resolve/GetWorkspace/版本读）不经过这些入口。

## 四、集成接线需求（central hooks needed，交总集成工程师）

1. **迁移收编与编号**：SQLite `000130_craft_writer_lease`（集成分支 sqlite 侧现最大 000129，直接顺位）；PG 已按集成分支现状取 `000209`（原拟 000208 已被 T11 craft_share_decisions 占用——lane 内已改名，收编时复核下一可用号即可）。迁移目录被 `.gitignore:96` 排除，提交用了 `git add -f`（T19 先例）。
2. **Run admission 接线（craft_session.go StartRun / durable worker，不在 T16 文件所有权内）**：新 Run 准入在 Submit 成功后应调用 `CraftWorkspaceService.AcquireWriter(scope, runID)`（或直接 store），把结果写进响应投影（acquired/conflict）；`WriterAcquireOutcome` 即 T00 冻结 DTO，可直接进 handler 响应。conflict 不必回滚 admission——run 槽位仍是第一道串行化，lease 是 workspace 级持久权威（供跨进程/恢复/协作者 T09 场景）。
3. **Run 终态编排（T20 中央编排点）**：run 终态 + workspace 捕获（T15 晋升链）完成后调用 `ReleaseWriter(scope, runID, WriterReleaseVerifiedCompletion)`；confirmed stop（T17）落 `WriterReleaseConfirmedStop`；恢复程序（T18）在权威核验后落 `WriterReleaseAuthoritativeRecovery`。**编排不调用释放时，下个写者经权威接管仍可继续（takeover 路径已实现并测试）**，故接线缺失不阻塞、只影响租约行的及时清理。
4. **装配**：`NewCraftWorkspaceService` 的 `CraftWorkspaceConfig` 新增可选 `WriterLeases` 字段——中央装配传入 `repository.NewCraftStore(db).(*repository.CraftStore)` 即可（dig 无需新 Provide；`*CraftStore` 已在图中则直接注入）。
