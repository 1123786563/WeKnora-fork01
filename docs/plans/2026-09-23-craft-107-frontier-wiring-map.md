## Dependency and security notes

- Integrate reviewed T08 checker before final T05/T14 assembly. T05 also needs its immutable record migration; T01 needs recognition columns; T08 needs grant table. These migrations were assigned in the scoped frontier migration brief and must be present in both PostgreSQL and SQLite before the corresponding Ticket is marked vertically verified.
- **DAG ruling needed:** the written DAG lists T05 as depending only on T00, but its concrete `CraftKnowledgeConfig.TaskAccess` and current membership acceptance require T08's checker. This is an evidenced implementation prerequisite, not a new product requirement. Keep T05's independent lane work and review, then integrate/verify T08 first and T05 second; record a T08→T05 integration/verification edge in the Ledger or DAG before marking T05 `verified`. T05 also requires the scoped central `StartRun`/worker hook above before vertical acceptance, rather than deferring all live wiring to T20. The same T08-first rule applies to T14's live access check.
- T19 must feed admission before chargeable model or sandbox work and pause into authoritative Run persistence; a UI-only usage panel cannot satisfy the budget requirement. Avoid making the budget service depend on `CraftSessionService` if `CraftSessionService` takes budget admission; use a narrow port or post-construction attachment.
- T14 network proof must agree with T04 build runtime's effective configuration. Issuance must fail closed on missing origin, checker, stale binding, unavailable inspector or default Docker bridge. Browser-facing preview origin must not inherit app cookies or authenticated API privileges.
- Feature registry (`internal/handler/session/craft_features.go`) accepts only Craft-scoped GET/POST paths and freezes on first mount; it is a route seam, not a Task access seam. Route registration order is sorted, but constructor/invoke order still matters. A duplicate method/path can panic Gin at boot; enumerate legacy routes before adding each feature.
- Existing snapshot restore path in `RegisterCraftSessionRoutes` predates this release; the approved Spec excludes editing from arbitrary historical versions. Do not expose it as part of the new web artifact journey without an explicit product decision.
