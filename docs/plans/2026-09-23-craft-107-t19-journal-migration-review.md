## Verification and design evidence

The journal primary key is `(tenant_id,run_id,activity_key)` and the separate unique key is `(tenant_id,reservation_key)` in both up migrations. All identity columns are `NOT NULL`; `CHECK` admits only `intent`, `started`, `unknown`, and `definitely_unstarted`. The FK points to the existing composite `agent_runs` key, so a journal row cannot silently attach to a Run in another tenant. Neither migration adds a TTL, default transition, or cascade that would convert an unresolved start into permission to retry or delete its evidence. The PG `BIGINT` journal tenant key is compatible with the existing `INTEGER` Run tenant key in the tested PostgreSQL 17 FK.

I independently ran a disposable SQLite 3.54.0 check with foreign keys enabled: accepted all four states; rejected duplicate activity and reservation identities, invalid state, cross-tenant/missing Run targets; confirmed `EXPLAIN QUERY PLAN` uses `idx_craft_charge_start_journal_state_updated_at` for an unresolved-state query; ran down and reapply; and verified preexisting Run/reservation rows remained readable. This was a minimal isolated fixture. The implementation report additionally records applying all 96 preceding SQLite migrations through 000111 and preserving seeded legacy rows.

I independently ran the **actual PG up and down SQL** in a disposable PostgreSQL 17.9 schema inside one transaction on `WeKnora-postgres-dev`: created a compatible composite-key Run, inserted an `intent`, read it, applied down, verified the journal absent and the Run row intact, then rolled back the transaction. `psql -v ON_ERROR_STOP=1` exited 0; output included `CREATE TABLE`, `CREATE INDEX`, `intent`, `DROP INDEX`, `DROP TABLE`, `t`, `legacy`, `ROLLBACK`. ## Remaining central gates

The schema permits updates to identity, `run_revision` and state because SQL alone adds no immutable-column trigger or transition machine. The future repository coordinator must pin these fields and enforce allowed transitions with a durable transaction, using the journal key to refuse duplicate starts. It must commit the G4 hold and `intent` **before** any provider send, keep unresolved holds across crash/retry, and make pause, recovery, cancellation and terminal Run writers honor unresolved entries. Production model and sandbox call sites still require routing through that coordinator. These are implementation gates, not defects attributed to this four-file migration.
