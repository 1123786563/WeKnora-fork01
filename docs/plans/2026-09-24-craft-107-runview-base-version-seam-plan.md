# Craft #107: durable current-Workspace Run seed seam

**Status:** architecture correction; design only. The prior proposal to require a T15 promoted-Version pointer before T01/R4 is **superseded**. R4 is not ready. Sources: approved `docs/specs/2026-09-23-craft-web-artifact-spec.md` lines 57–66; `CONTEXT.md`; ADR-0004/0008/0009; T01 #120, T15 #130 and `2026-09-23-craft-107-dag.md`; current `craft_session.go`, `agent_run_graph.go`, `craft_run_view.go`, `craft_version.go`, `craft_snapshot.go`; R3/R4 plans. No production code or tests changed.

## Authority and dependency ruling

- The Spec says the first release **continues editing from the current Workspace**. A failed/stopped/unknown Run may leave a Workspace draft while the last successful Version stays the default **preview**. Historical Version restoration/editing is deferred. Thus the next Run's writable seed is the latest accepted Workspace draft, which may differ from the promoted Version. The promoted pointer is a delivery/read authority, not the edit seed.
- `VersionStore.Publish/List/Get` records immutable Version rows but no current Workspace draft head or default-preview pointer. `List()[0]` is not a Workspace draft contract. `craftRunSnapshot` currently puts client `BaseVersionID` in the model-facing query; `DurableRunSnapshot` has no server-only seed identity. Existing `CraftSnapshotService` captures Version files plus OpenCode state for a different restore workflow; it must not implicitly become a cross-Run seed.
- Native DAG: T04 depends on T01/T03; T15 depends on T04/T14. Making T01/R4 depend on T15 creates a cycle. This draft seam belongs to T01/RunView support and must be reviewed before T04. T15 later owns promotion/default preview. Earlier R3/R4 notes saying “last promoted Version seeds B” conflict with the Spec and need controller amendment before R4 dispatch.

## Small durable interface

Define a **Workspace draft head** separate from immutable Artifact Versions. The head is server-owned and keyed by tenant, owner Task/session and Workspace. It contains `source_run_id`, monotonic `revision`, and a digest-sealed manifest of current editable `output/` paths with immutable object refs, SHA-256 and byte counts. An explicit `empty` head represents a never-written Workspace. A completed or confirmed quiescent Run may publish a new draft head even if its build/preview failed, provided the captured files are safe and complete. Unknown or active execution cannot assert a new head until authoritative reconciliation. Advance under the existing single-writer lease with revision CAS; no shared directory pointer. T15 promotion does not change this head.

Repository interface, owned by T01 support: `ReadDraftHead(ctx, ownerScope, workspaceID) (DraftHead, error)` and `AdvanceDraftHead(ctx, ownerScope, expectedRevision, sourceRunID, manifest) (DraftHead, error)`. The adapter owns a new table such as `craft_workspace_draft_heads` plus immutable per-head manifest rows/object refs in paired PostgreSQL/SQLite migrations; allocate numbers at dispatch. FK/unique checks bind tenant, Workspace and producing Run. Old Workspaces with no trustworthy head are **unresolved**, never silently empty. Only a newly created Workspace with an atomic initial empty head is known empty. Legacy backfill requires evidence of latest quiescent Workspace bytes and Run identity, not Version order.

Admission reads the head under the same Workspace writer fence used to reserve the new Run. Freeze `{state:empty|selected, draft_revision, source_run_id, manifest_digest}` as typed server-only `craft_workspace_seed` in `DurableRunSnapshot`, with exact immutable manifest addressable by revision/digest. `Submit` and choice must be linearizable: a head change between choice and admission retries the transaction. Same request key replays its original seed after restart. Remove model-query injection of `BaseVersionID`; reject a client-supplied historical Version selection for first-release editing. Generic snapshots remain valid; marked legacy Craft snapshots without a seed cannot enter R4.

R4 consumes only the frozen seed and admitted Run/verified material handle. It verifies scope, producing Run, digest, canonical paths, regular files, byte counts and SHA-256, and seeds **only output files** into the new generation's writable `output/`. It never copies the prior Run directory, HOME, OpenCode state, inputs or knowledge. Missing/corrupt head or legacy snapshot fails before prompt. T15's separate guarded default-preview pointer may later point to a successful Version; failure/unknown preserves it while draft continuation may use newer safe Workspace files.

| S3 RunView material and collection | R4 `backend_implementer` / `backend_validator` | S2 reviewed/integrated; R3 material handle reviewed | B sees prior draft output plus only B inputs/knowledge; corrupt/missing object, unsafe path, extra output, foreign/stale generation fail before prompt; B cannot mutate pinned objects or A; retries byte-identical. For each task record a live baseline/hashes in the shared integration worktree, focused RED/GREEN tests, applicable package tests, `gofmt -d`, `git diff --check`, independent Spec/quality review and an integrated checkpoint before downstream dispatch. T15 later adds its four-check promotion gate without becoming a predecessor of S1–S3.

**Interim:** leave production RunView off until the durable current-Workspace draft contract, admission freeze and real Run A→B isolation are reviewed. Never seed from `VersionStore.List()[0]`, client `BaseVersionID`, a previous Run directory, or a missing head interpreted as empty.
