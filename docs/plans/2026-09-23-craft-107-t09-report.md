## 1. 做了什么（纵向切片）

### 1.1 现场盘点（先查后改）

- T08 已交付：`CraftAccessService`（`internal/application/service/craft_access.go`）持久 Task 角色（Owner/Collaborator/Viewer + 撤销 + 审计）；`StartRun` 经 `writeSession → craft.RequireTaskAccess(TaskWrite)` 已对 Collaborator 放行、Viewer 拒绝；`agent_runs.actor_user_id` 持久化实际发起成员（T08 actor 工作）。
- T16 已交付：`StartRun` Submit 成功后获取工作区写者租约并把 `craft.WriterAcquisition`（T00 冻结 DTO）投影到响应（`craft_session.go:929-944`、`craft_session_lease_t16_test.go`）。
- **验证到的缺口**（本切片实现）：Run 请求边界没有"派生当前角色 + 时间线记录实际发起成员"的准入入口——任何 Run 发起都不落 `craft.run_started` 审计行，服务层也没有一个把"Collaborator 用自己的授权请求串行编辑"作为一等契约的公共 seam；前端没有按角色投影的修改请求面板，也没有写者租约冲突的可见投影。

### 1.2 后端（所有权内新文件）

`internal/application/service/craft_collaborator_run.go`（新，约 120 行）：

- `(*CraftSessionService).StartCollaboratorRun(ctx, scope, req) (agentruntime.Run, craft.WriterAcquisition, error)`——角色派生的串行编辑准入口：
  1. caller 与 scope 同一性校验（身份只来自服务端上下文）；
  2. `craft.RequireTaskAccess(TaskWrite)` 前置派生**当前**角色：当前 Owner/Collaborator 放行；Viewer、已撤销 Collaborator、无授权同租户成员被拒且经 T08 权威落 `craft.access_denied` 审计；`s.access` 未装配时该入口不扩大授权（非 Owner 由 `writeSession` 的 owner 回退继续 fail-closed，保持 pre-T08 行为）；
  3. 委托既有 `StartRun`（同一 Workspace 解析、T01 幂等准入、跨 actor 重放冲突、T16 租约获取与冲突投影）；
  4. 准入成功后落 `craft.run_started` 时间线审计行：`ActorUserID=实际发起成员`（绝无 storage-owner 回退）、`TargetType="run"`、`TargetID=稳定 RunID`、Details 含 `request_id` 与派生角色；审计写失败仅告警，绝不撤销已提交准入（run 行的 `actor_user_id` 恒为发起成员）。
- 未改动 `craft_session.go`/`craft_access.go`/handler/容器/迁移——零共享文件私改。

### 1.3 前端（所有权内新文件）

`packages/views/src/craft/workbench-edit.tsx`（新）：`CraftEditRequestPanel`——只做投影，不推导授权：

- Viewer（`canWrite=false`）：只读通告，无 composer，请求回调不可达；
- 可写成员：composer + 单次提交（busy 禁用）；成功投影服务端记录的**实际发起成员**与 RunID；
- 写者租约 `conflict`：`role="alert"` 可见冲突通告（不吞掉、不隐藏已准入 RunID）；
- 拒绝（如撤销后）：错误告警 + 草稿回填、可显式重试（恢复路径）；
- `runActive`：串行化原因通告 + 提交禁用，槽位释放后可发起下一次编辑；
- `projectEditOutcome`：畸形结果（空 id、未知 writer status）整体丢弃，绝不默认成 acquired 或臆造发起人。T00 冻结的 `CraftWriterAcquireOutcome` 词汇表在文件内镜像（顶层 `@weknora/contracts` 索引未再导出该冻结类型，见 §4 接线需求）。
