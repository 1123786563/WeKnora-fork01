## Verdict

- **Scoped publication-recovery Spec compliance: FAIL pending current-source authorization.** The specific fix-2 Medium data-consistency gap is substantially corrected: an unpublished record resumes its original digest-bound candidate without rerunning mutable search, and actual-source APIs reject prepared/legacy records until publication. However, a prepared package can be published after its underlying knowledge grant is revoked because the retry branch checks only TaskWrite and package integrity. The approved Spec requires current authorization for material passed to a Run.
- **Code quality: CONDITIONAL FAIL for this checkpoint.** The repository's digest-bound `MarkPublished` compare-and-swap and the service's manifest/file validation are sound seams; focused service/repository tests are reported passing. The missing ACL recheck is a high-severity authorization regression in the new recovery path. The full-service package's source-guard failure is real but predates this delta, as detailed below.
- **Full #124 Spec compliance: FAIL.** The production publisher remains unwired and the central per-Run delegate sandbox/read boundary remains absent. This lane cannot certify those gates from an in-memory publisher fake.

## Findings

### 1. High — prepared package can be published after the source grant is revoked

**Evidence / affected symbol:** `CraftKnowledgeService.BuildForRun` calls `RequireTaskAccess(...TaskWrite)` (`internal/application/service/craft_knowledge.go:165-166`), but its existing-record branch (`180-208`) calls `workspaceForScope`, `Resume`, validation, `Publish`, and `MarkPublished` without `s.access` or the underlying KB authorization entrance. `workspaceForScope` checks caller identity and Workspace scope, not knowledge permission (`craft_knowledge.go:323-340`). First-build retrieval uses both ACL-guarded entrances in `buildPackage`; retry deliberately skips live retrieval. The new test changes retrieval content after Publish failure (`craft_knowledge_t05_test.go:184-190`) but does not revoke the source grant; the revocation test creates a *different* Run (`:476-487`).

**Impact:** If an Owner retains TaskWrite but loses access to a selected document/KB after the private candidate was prepared, a retry can expose those old bytes to a Run and mark the record published. Package integrity proves identity of bytes, not present authority. This violates #124's selected∩authorized material rule.

**Smallest defensible correction:** Before publishing a prepared or legacy candidate, reauthorize every accepted source/document and owning KB for the current caller without rebuilding package bytes; fail closed on any denied or missing grant. Bind this check to the central dispatch boundary as well, so a later grant loss cannot race sandbox creation. Add a test: Publish fails, grant is revoked, same-Run retry has zero publisher visibility and remains unpublished; an authorized unchanged-grant retry still resumes the original candidate after retrieval content changes.

### 2. High, central integration gate — publisher durability and per-Run read isolation remain unimplemented

**Evidence / affected symbols:** `CraftKnowledgePackageResumer` is a new optional interface (`craft_knowledge.go:119-127`), exercised by the in-memory `t05Publisher` fake. `internal/container/container.go:2639-2644` still creates `CraftKnowledgeConfig` without a production `Publisher`, `Records`, or TaskAccess; `BuildForRun` fails closed without publisher (`craft_knowledge.go:160-163`). `KnowledgeRunDir` remains a sibling path under the persistent Workspace (`internal/modules/craft/knowledge.go:38-49`), with no actual delegate mount/read restriction in this lane.

**Impact:** Current production cannot build/resume a package. Merely adding an atomic publisher later would not prevent Run B from opening Run A's raw material through the reused Workspace. #124 remains unverified even if the scoped service test passes.

**Smallest defensible correction:** Implement a durable content-addressed publisher/resumer, wire it with records and Task authority, and prove atomic visibility and crash recovery. Separately bind an admitted server Run ID to a fresh delegate execution view containing only its authorized sealed package, and test denied reads of earlier Run paths after revocation.

## Recovery behavior and unrelated full-suite failure

For an existing Run, the service now checks the immutable request digest, resumes by the stored package digest, validates the package's full digest, manifest scope/source facts and file set, and calls `Publish` before `MarkPublished` (`craft_knowledge.go:168-208,371-437`). `Sources` and `AuthorizeSourceOpen` reject records whose state is not `published` (`:268-271,315-318`).
