## Verdict

- **Spec compliance: FAIL, scoped to actor tenant validation.** Owner storage identity, separate durable actor, cross-actor replay conflict, NULL legacy Craft actor handling, and T01 owner-scoped input-claim keys meet the Task 1 plan. However, the new tenant check tests `users.tenant_id` instead of the active `tenant_members` authorization relationship. It rejects a legitimate member whose home tenant differs from the Run tenant and accepts a home-tenant user whose membership has been removed or suspended.
- **Code quality: FAIL pending the medium finding below.** The row insert/load and replay comparison are coherent, and focused tests pass, but the actor check uses the wrong domain fact and its tests cover only users whose `users.tenant_id` equals the Run tenant.

## Finding

**T08-A1 — Medium — Actor tenant validation uses the home tenant rather than active membership.** `actorBelongsToTenant` in `internal/application/repository/agent_run.go` queries `users` with `tenant_id = ?`, `is_active = true`, and no `tenant_members` predicate (near line 247). Craft's authoritative `CraftAccessService.Role` instead resolves one active, undeleted `tenant_members` row for `(tenant_id,user_id)` (in `internal/application/service/craft_access.go`, `activeMemberID` and `Role`). The user model describes `TenantID` as a workspace association; `tenant_members` supports multiple memberships per user. Consequently, a valid invited Collaborator in tenant B with home tenant A fails `Admit` even after Task 2 authorizes TaskWrite. Conversely, a user with home tenant B but no current active B membership passes this repository check, weakening the planned admission fence. The same check also changes generic Run compatibility for cross-tenant members. **Smallest correction:** query an active, undeleted `tenant_members` row joined to an active, undeleted `users` row for the Run tenant and actor ID; do not require `users.tenant_id` to equal the Run tenant. Add tests for a member whose home tenant differs from the Run tenant, and for removed/suspended membership. Keep TaskWrite enforcement in Task 2.
