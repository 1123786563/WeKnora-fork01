## Global constraints and review focus

Preserve `taskId=sessionId`, one writer per Task, immutable promoted Version, durable prompt message ID, and T05 selection intersected with current ACL. The RunView key comes only from the authenticated admitted Run. No model text or client path chooses a host directory. Every nonterminal allocation or prompt outcome is recoverable without a second blind submission. Review isolation at OS mounts and OpenCode state as well as at Go paths.

## What is already present, and the remaining gap

`craft.RunViewStore` and `CraftRunViewStore` already allocate one generation and CAS-bind `(runtimeID, containerID, opencodeSessionID)` to an admitted `(tenant, owner, session, run)`. `Client.WithDirectory` is immutable and sends the directory header on HTTP requests. T05 has a digest-sealed, atomic Run-specific package publisher. These are usable interfaces, not a deployed view: `localCraftRuntime.ensureWorkspace` still creates and stores one OpenCode session in `craft_workspaces`; `opencode.Executor` still reads that task-level session for Execute/Observe/Abort; input staging writes under shared `workDir`; output uses a prompt-hash directory and shared symlink; `newCraftKnowledgeService` still writes Build material to shared `workDir` and ignores the workspace argument. The publisher is not yet the sole read path into an isolated runtime. `Client.Events` reaches global `/event`; a directory header alone does not establish stream confinement.

## Stable seam

Add one **server-owned `RunRuntimeBinding` adapter** to the runtime assembly. It resolves `craft.RunViewKey` from `task.Fence` plus `task.Scope`, calls `RunViewStore.Allocate/Load`, and returns an opaque resolved handle containing generation, persisted runtime identity, a directory-bound OpenCode client, and a canonical private view root. The root never enters API DTOs or model prompts. The adapter owns container lifecycle, mounting, session creation/recovery, and view root validation. The existing `RunViewStore` remains the durable identity authority; the adapter must never mutate an already-bound generation. Keep one provider shared by execution, T05 publication, and artifact reads; do not create separate T01 and T05 roots.

For OpenCode, inject a **per-call binding resolver** into `Executor` so Execute/Observe/Abort all obtain the same persisted Run session and directory-bound client before any network request. The current `craft.Store` still owns delegation prepare/result; `craft.Workspace` remains Task ownership, not OpenCode runtime authority. Any compatibility constructor must fail closed for Craft when no resolver is configured. `Client.WithDirectory` alone cannot prove that CreateSession's response belongs to the intended directory; adapter must observe/check session directory through a pinned endpoint or an equivalent verified runtime probe before BindRuntime.

## Deployment and recovery prerequisites

The selected adapter needs a per-Run container or equivalent OS isolation with a private project directory and HOME/state, read-only `inputs/` and `knowledge/`, writable `output/`, no host home/source/Docker socket/platform credentials, and a controlled network policy. Pin the Linux OpenCode image digest; the source/lock version alone is insufficient. Persist or deterministically recover container identity for a generation. Run view roots must be on a dedicated mount; the Go `x-opencode-directory` header is routing context only. Existing workspace single-writer lease remains authoritative.

For uncertain CreateSession, the durable `allocating` row is a fence. Before call, persist the generation and runtime/container creation identity; after a successful response, verify session directory and then CAS-bind. If the call times out/crashes after the server creates the session, enumerate/observe **within that exact isolated runtime**, match a unique generation marker/session directory, then bind. If OpenCode cannot expose evidence sufficient to distinguish zero, one, or multiple created sessions, keep allocating/unknown and require explicit reconciliation; never create a replacement or submit a prompt. `BindRuntime` currently stores the final triple only, so allocation intent/recovery evidence may need an additive schema field or a runtime whose identity is derivable from generation. The present interface cannot itself prove external CreateSession uniqueness.

`/event` is global in the pinned protocol. A per-Run process gives process-level event scope; still require matching session/message IDs in the normalizer. On shared serve, the directory header has not proved `/event` filtering or filesystem confinement. Do not enable this adapter with shared serve based only on the existing client tests.

## Integrated Run A → B acceptance

Run A selects input A and knowledge K_A, gets `(D_A,S_A)`, writes output and promotes V1. Terminal A then admits B on the **same Task**, selecting only B and K_B. Assert `(D_B,S_B)` differ, B can read verified V1 output plus B/K_B, cannot read A/K_A or A history or sibling root, and writes cannot mutate read-only mounts. V1 digest/promotion remain unchanged until B passes collection; B success yields immutable V2. Inject restart after CreateSession and after prompt dispatch: recover the same generation/session/message ID, with no extra session or prompt. B failure/stop/unknown leaves V1 promoted and only a separately identified B draft. Include cross-tenant RunView substitution, symlink escape, corrupt seed/input, revoked ACL, missing mount, concurrent allocation, and foreign `/event` frame cases. This must run against the actual deployment adapter, not only temp-directory helpers.

## Unproven by current interfaces

`RunViewStore` proves row identity and CAS, not container ownership, mount confinement, runtime liveness, directory/session affinity, or uncertain CreateSession recovery. `Client.WithDirectory` proves header construction, not server enforcement or global event filtering. T05 Publisher proves atomic package exposure and digest recovery, not its read-only mount into the Run container or current-ACL retrieval at every source open. `CraftArtifactService` proves bounded collection/publication of its supplied source, not that the source is Run-scoped. R1/T01 and T05 runtime read boundary remain pending until the integrated A→B and restart evidence above exists.
