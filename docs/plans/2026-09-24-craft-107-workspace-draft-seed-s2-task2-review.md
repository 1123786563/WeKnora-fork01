## Findings

**High — registered Craft admission can omit the marker and bypass seed selection.** In `internal/application/repository/agent_run.go:318–332`, `craftSeedAdmission := isCraft && markedCraft` makes a valid `craft_input_manifest` field an optional switch even after the database identifies the Session as Craft. At lines 404–417, the unmarked case persists the caller snapshot and hash without reading the Workspace head. `internal/application/service/agent_run_graph_test.go:442–449` demonstrates the route: the new worker test registers a Craft Session, builds a generic snapshot, and successfully admits and claims it without a seed. The worker later rejects it, but the Run, writer slot, and messages were already created, violating S2's requirement that every newly admitted Craft Run freeze its current head atomically. An internal caller or alternate submission route can create a durable unusable Craft Run, and a missing or corrupt head no longer fails before admission. **Smallest correction:** for a registered Craft Session, reject a fresh admission without a valid Craft marker; retain read compatibility for preexisting legacy rows through a database fixture or direct legacy-row insertion in the worker test. Derive the seed requirement from the registered Session, never the caller's marker alone. Add a repository denial test asserting no Run, slot, or input-claim transition for an unmarked Craft request.

**Low — race test observes one scheduler outcome without forcing both serial orders.** `TestAgentRunCraftSeedAdmissionSerializesAgainstDraftAdvance` at `internal/application/repository/agent_run_craft_seed_test.go:348–391` starts both goroutines together once per dialect. It asserts the result of whichever order happens, but does not pause admission after the Session lock while Advance has the head lock, or force Advance to commit before admission's head read. Thus it cannot prove the specific lock-order claim in `agent_run.go:406–413` or detect a regression that occurs only under the opposite interleaving. **Smallest correction:** add deterministic transaction hooks or controlled connection barriers for both orders and assert the exact selected revision/digest and rollback state. Keep the existing randomized race as a supplement.

## Verified boundaries and limits

For marked Craft snapshots, admission holds the Session writer row through Workspace/head selection, slot reservation, Run insertion, and T01 claim transition. The S1 `Read` uses one joined statement for the authorized Workspace, current head, selected revision, and files, and validates the manifest digest. Task 2 additionally checks the selected source Run's tenant, owner, Session, and terminal status. A supplied `craft_workspace_seed` is rejected. Fresh admitted snapshot bytes and stored request hash include the repository-selected seed. Same-key replay compares actor and canonical incoming intent to stored snapshot minus the seed, then returns the stored Run without rereading the newer head. The focused SQLite tests cover empty A, selected D1 for B, D2 replay/fresh-key behavior, changed actor/prompt/input/knowledge, corrupt or absent head, and rollback of a failed Run insert.

PostgreSQL admission, contention, rollback, and migration behavior remain **unverified** here. The report's broader repository/service suite was interrupted. S3 still must prove stopped/idle capture and validate material objects before use; Task 2 does not establish those guarantees.

## Verdict

**Spec compliance: FAIL for Task 2 admission.** The registered Craft marker omission permits a newly admitted Craft Run with no frozen Workspace head, contrary to the approved current Workspace continuation and the S2 atomic seed contract. The marked Craft path appears aligned with that contract within the SQLite evidence.

**Code quality: FAIL pending the High finding; one Low behavioral test gap.** The checkpoint is reproducible and focused SQLite tests pass, but they include a test that successfully admits the prohibited unseeded Craft Run. PostgreSQL parity and a green full suite are not established.
