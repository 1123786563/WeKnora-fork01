# Craft Workspace Draft Seed S2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. S2 begins only after S1 Task 2 independent review PASS and its exact checkpoint is integrated. This plan does not dispatch work or enable RunView.

**Goal:** Freeze the exact current Workspace draft head in each newly admitted Craft Run's durable, server-only snapshot, atomically with the Run writer reservation. Same-key replay keeps that seed after restart.

**Architecture:** The admission repository owns the linearization point. `CraftSessionService` builds a Craft request snapshot without a caller-selected predecessor. Inside `AgentRunStore.Admit`'s existing Session-lock transaction, the repository resolves the authorized Workspace head and immutable selected revision, adds a typed `craft_workspace_seed` to the snapshot, calculates the durable request identity consistently, and reserves the Run slot. An existing request key returns its stored snapshot/Run without rereading today's head; it still rejects different actor or request content. The Run executor consumes the frozen seed later; S3 owns object capture/materialization.

**Tech stack:** Go service/module/repository, GORM, PostgreSQL and SQLite, focused service/repository tests.

## Global Constraints

- Current Workspace draft is the edit seed; promoted Artifact Version is preview/read authority. No `VersionStore.List()[0]`, `BaseVersionID`, prior Run directory, HOME, OpenCode state, inputs or knowledge as a seed. T15 is downstream and not an S2 dependency.
- Only an explicit S1 `empty` head means empty output. Missing legacy head, corrupt selected revision/digest, wrong tenant/owner/session/Workspace, and unavailable draft store fail closed before admission. The typed seed includes Workspace identity, state, revision, source Run ID and manifest digest; selected files are addressed only by that exact revision/digest, not copied into a model prompt.
- Keep `Admission.UserID` as Task storage owner and `ActorUserID` as authenticated Run actor. Actor replay and T01 input-decision claims keep their present fences. T05 chosen input/knowledge manifests remain bound to this Run; the seed carries no material authorization.
- Lock order must be compatible with S1 `Advance`: Session writer fence first, then head/revision choice, then Run insert/slot reservation in one transaction. A head change between any speculative pre-read and commit must be detected and retried as a whole transaction; never commit a snapshot whose seed differs from the chosen head at the admission linearization point. Avoid a second long-lived lock inversion with S1.
- Generic durable snapshots remain parseable. A marked Craft snapshot missing `craft_workspace_seed` is legacy/unresolved and may not enter R4; reject missing/null/invalid seed at Craft execution and R4 entrance. No migration invents a seed for historical Runs.
