# Issue #65 error-category metric: architecture follow-up

Read-only assessment, 2026-09-28. Facts: `CONTEXT.md` Marketplace Metrics definition; `docs/adr/0011-agent-marketplace-release-adoption-boundary.md`; approved `docs/specs/2026-09-20-agent-marketplace-domain-model.md` §§1, 4, 8, 12, 15; assigned parent brief requesting a privacy-safe adopter-level source. No production change or test run.

## Finding

The approved Spec explicitly calls for aggregated, de-identified adoption, upgrade, and **error-category** metrics, and says publishers cannot access Tenant identity or Task content (§12; acceptance 10). It also defines the attribution chain Adoption → Variant → local Agent Version → Task (§§4, 8). The current repository does not yet persist that chain: `internal/types/agent_marketplace_persistence.go` has only Listing, Submission, Review, Release, and the present `AgentReleaseEntity.AgentVersionID` is the *publisher's source version*. Using it to attribute an adopter run would be incorrect.

Durable run entry is `AgentRunService.Submit` (`internal/application/service/agent_run_service.go`), ultimately `AgentRunStore.Admit` (`internal/application/repository/agent_run.go`). The conventional chat path builds an admission in `internal/application/service/agent_run_graph.go`; Craft has its own path in `internal/application/service/craft_session.go`. Neither `runtime.Admission` nor persisted `agent_runs` has adopted Release, local Variant, or pinned local Agent Version identity. Terminal completion is fenced `AgentRunStore.SetStatus` (same repository), called from `AgentRunWorker.runOne` (`internal/application/service/agent_run_worker.go`). Its `reason` can be `err.Error()`, so forwarding, grouping, or retaining it as a metric is unsafe. Deadline and cancellation have other terminal routes; a worker-only hook would miss outcomes.

## Bounded source design, after attribution exists

At the *server-owned admission boundary*, resolve `(tenant_id, pinned local_agent_version_id)` through immutable local-version provenance to `(adoption_id, release_id)`. Persist those IDs on the run or a private run-attribution row in the same transaction as Admit. The lookup must be tenant-scoped and reject missing/mismatched provenance; never infer from the live Agent Definition, current Listing pointer, prompt, message, snapshot JSON, or publisher source `AgentVersionID`. Existing runs without attribution remain unattributed; do not backfill by mutable relationships.

At the fenced terminal transition, classify an internal typed failure into a closed allowlist (for example `provider`, `capability_unavailable`, `timeout`, `policy`, `internal`, `other`; exact categories need product/operations approval). Insert a private event `(tenant_id, release_id, run_id, category, occurred_at)` with unique `(tenant_id, run_id, event_kind)` in the same transaction as the terminal status. This provides idempotency across lease retry and avoids losing an event after committing failure. `run_id` is an internal idempotency token only; aggregation output contains only release, category, count, time bucket, and appropriate suppression threshold. No raw reason, tool names, user IDs, local mapping, Tenant IDs, or Task joins cross the aggregation boundary. A publisher read API must enforce cohort threshold and query scope independently of the private event table.

Likely owned files for a later implementation task: `internal/modules/agentruntime/agent/runtime/contracts.go` (server-owned admission attribution contract), `internal/application/service/agent_run_graph.go` and other admission paths (pass pinned version identity), `internal/application/repository/agent_run.go` (transactional attribution/event), `internal/types/agent_marketplace_persistence.go` plus both `migrations/versioned/` and `migrations/sqlite/` (provenance and event schema), and a Marketplace metrics service/repository read port. Avoid making the generic run worker import Marketplace or exposing event persistence through its public store interface unless required.

## Recommendation

This is **not a bounded Issue #65 task in the current schema**. It requires the unimplemented Adoption/Variant/local-version provenance and a reliable version selection contract across all run admission paths. Adding only an event table would yield unattributed or falsely attributed counts. Conservative Issue #65 delivery should state that error-category metrics are unavailable until the adoption/version execution seam is implemented, rather than return fabricated zeros or infer categories from `wait_reason`. This is a visible gap against the approved Spec, not a silent reinterpretation of it; the parent should record it as a dependency/blocker or obtain a scoped Spec decision if Issue #65 must complete independently. Once the provenance task lands, the private allowlisted event plus aggregate read is a bounded follow-on task with a clear transactional seam.
