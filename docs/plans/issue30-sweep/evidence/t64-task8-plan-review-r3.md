# T64 Task8 architecture plan review, round 3 — 2026-09-29

Read-only review of the revised Task8 plan, parent Task8 amendment, proposed ADR-0015, round-2 review, approved Marketplace spec §10–11, `CONTEXT.md`, and current Run/AgentQA interfaces. No requirements or production code changed.

**Decision: keep ADR-0015 proposed and hold Task8 dispatch.** The round-2 schema identity, both-tenant lock order and share revalidation, server-derived Version route, assistant placeholder ordering, revocation transaction methods, and parallel schedule are substantially repaired. The remaining interface contradictions below would otherwise leave worker Briefs to invent security behavior.

1. **Claim interface cannot express its stated expiry result or stop transition.** `Admit` is declared with three return values `(claim, ReplayState, error)` at plan lines 68–74, but line 77 says it also returns target-session claims terminalized by expiry cleanup. More seriously, `Finish` requires `leaseOwner` (line 73) and line 79 says Stop uses the same owner-bound CAS; the Stop HTTP caller has no handler lease owner. Line 196 assigns Stop a CAS without naming an operation or ownership rule. Define separate owner-fenced handler finish and authorized Stop cancellation APIs, including their tenant/session/message checks and race winner. Specify whether expiry cleanup is internal or a fourth return value. Keep revocation cancellation in its guarded repository transaction, independent of the live handler's lease owner.

2. **The message fence is not yet an executable atomic boundary.** The plan requires *every* continuation and final message write to CAS against active generation (lines 64, 79, 195), but the published claim store has only `Renew/Get/Finish`, with no fenced message write. Existing AgentQA calls `messageService.UpdateMessage` separately (`internal/handler/session/qa.go:1558,1707`); a prior `Get` or `Renew` cannot prevent revocation committing before that update. Put the claim-state/generation check and message update in one repository transaction, or name an equivalent conditional update on the message row tied to the claim. Include user-message creation after claim and placeholder terminalization in the fence policy. Test revocation/expiry between a permitted read and the attempted write.

3. **Version and claim schema rules still disagree at the non-Marketplace boundary.** The claim DDL makes `local_agent_version_id` and `release_id` nullable (line 156), while the shared text says the claim stores a local Version and pinned Release (line 64) and 8D always loads the stored Version for execution (line 194). Define the invariant for confirmed non-Marketplace Agents: whether both fields are null and which immutable execution snapshot is used; for adopted Agents require both non-null, preferably with a database check or explicit store validation. Also remove line 156's statement that `Admit` receives an exact Version: the input contract at line 77 correctly excludes it and resolves it under the guard. The Workbench Version route is otherwise coherent at lines 58–60, but the 8E steps at lines 135–149 only mention `VerdictForAgent` and a fast gate; add the required resolver-to-binding-to-`agentruntime.Admission` steps and a stale-Version race test to its Brief.

4. **Checkpoint owned-file lists still conflict with the map.** The map assigns `internal/application/repository/agent_security.go`, `internal/container/container.go`, and the migration schema test to 8B (line 41), but 8B's `Files` list omits all three (lines 158–166), even though steps 176 and 179 require repository and schema changes. The map assigns `runtime/contracts.go` to 8C (line 42), but 8C's `Files` list omits it (lines 100–105). Line 198 asks 8D to commit Container wiring although line 43 and line 186 explicitly forbid 8D Container edits. Reconcile these before creating Briefs or separate worktrees. The parent amendment at `plan-t64.md:1409` correctly points to this detailed schedule and supersedes the old pseudocode.

5. **HTTP contract needs one explicit acceptance line.** The detailed plan specifies Workbench security refusal as 409 and infrastructure failure as 500 (line 148), and blocked AgentQA with zero side effects (line 192), but does not assign the AgentQA 409/500 mapping or any OpenAPI annotation/schema check. The parent superseded sketch identifies AgentQA blocked 409 and infrastructure 500 (`plan-t64.md:1593`). Name the response/error mapping and update or verify generated OpenAPI only if these routes are represented there. This preserves the approved spec's new-work prohibition without changing product behavior.

The revised lease heartbeat (10 seconds/30 seconds), same-session bounded expiry sweep, placeholder terminalization, exact dependency selection, rollback behavior and post-commit notification watcher now address the corresponding round-2 concerns at the design level (plan lines 77–79, 156, 176–179, 193–196). Acceptance of ADR-0015 is recommended **after** the owner/fence/message-write contract and the above Brief inconsistencies are resolved and independently checked; its current proposed status is appropriate.
