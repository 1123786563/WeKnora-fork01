## Finding

### F1 — High — The typed callback contract does not bound `Seal` or prevent late callback effects for every accepted implementation

**Evidence / affected symbols:** `DockerNormalExecOutputCallback` is an exported interface whose only enforcement is a comment requiring prompt, linearizable `Seal` (lines 105–112). `freezeAndSeal` calls arbitrary `callback.Seal()` synchronously without a deadline or implementation check (lines 528–535). The stream worker invokes arbitrary `callback.Deliver` outside the writer lock (lines 500–518). Thus a callback whose `Deliver` is blocked and whose `Seal` waits for that `Deliver` still blocks provider return after `dockerExecDrainGrace`; a callback with a no-op `Seal` can resume `Deliver` and perform side effects after the provider returns. Both satisfy the Go interface and are accepted at `StartAttachedExecOnce` after the physical start. The new blocked-callback test uses a cooperative test implementation: its `Seal` only sets a flag and its `Deliver` explicitly checks that flag before its side effect (test lines 76–99, 519–563). It proves the mechanism works for that implementation, not for every accepted implementation.

**Impact:** The Fix2 global constraint requires bounded return and no callback work after return for every accepted callback form. A misimplemented live projection can still hold a claimed command/budget recovery indefinitely, or publish output after the frozen result. Moving `Deliver` outside `w.mu` closes the Fix1 mutex inversion for conforming callbacks, but transfers the same unbounded dependency to the caller's `Seal`. This is a contract/integration gate even though the provider is presently unrouted.

**Smallest defensible correction:** Make accepted live projection callbacks a provider-owned, verifiably sealable implementation or a narrow concrete capability whose `Seal` and post-seal behavior are controlled here; reject other callback implementations before the physical start. If callers require arbitrary callback code, it cannot be promised both bounded return and no post-return side effects, so keep that form unsupported. Add an adversarial blocked `Deliver`/blocked `Seal` or ineffective `Seal` test to prove rejection before `ExecAttach`, alongside the conforming callback test. The existing sink has the same external `Seal` contract, so production routing must separately use a reviewed durable sink implementation.
