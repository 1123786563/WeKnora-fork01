## Four-finding disposition

1. **Empty manifest association — closed.** `selectedWorkspaceInputs` checks the scoped `craft_workspaces` row before returning an empty manifest (`craft_runtime.go:904-915`). The new revoked-association/empty-manifest test exercises this case (`craft_runtime_test.go:185-190`).
2. **Publication overwrite — closed; rollback race remains.** `writeRunViewInputAtomicWithBeforePublish` uses same-directory `Linkat` and treats `EEXIST` as conflict (`craft_runtime.go:790-795`); this cannot replace a competing target at publication. The deterministic competing-target test confirms the target bytes remain unchanged (`craft_runtime_test.go:291-319`). The rollback half of the original finding is still open, as detailed below.
3. **Distinct refs at one canonical path — closed.** `runViewInputManifest` rejects a duplicate path when `Ref` differs (`craft_runtime.go:509-515`), before FileService reads or writes. The new two-ref test checks both absence of reads and an empty material tree (`craft_runtime_test.go:256-275`).
4. **Noncanonical retry mode — closed for staging.** Inspection now requires exact `0644` on both the path and opened descriptor (`craft_runtime.go:648-661`); the `0755` retry test fails closed (`craft_runtime_test.go:277-289`). This is a staging invariant only. A live `noexec` mount and denial of uploaded-code execution remain separate acceptance gates.

## Remaining findings

1. **Medium — rollback can delete a concurrent replacement despite the inode check.** In `rollbackRunViewInputWrites`, `Fstatat` compares the target's device/inode at `craft_runtime.go:840-845`, then `Unlinkat` acts on the name at line 846. A writer can replace the target *between* those calls. The inode-safe claim is therefore not established: rollback can unlink the writer's replacement, exactly the loss the original finding sought to prevent. The new test replaces the inode *before* rollback starts (`craft_runtime_test.go:339-343`), so it cannot expose this interleaving. The same check/use gap applies to digest-directory removal at lines 857-862. **Impact:** concurrent staging or hostile mutation of the generation tree can cause rollback to remove an object this call did not create. **Smallest defensible correction:** do not unlink published names while another writer can mutate this tree; serialize all tree writers through an exclusive generation owner/lock that spans staging and rollback, or fail the generation and defer cleanup until exclusive ownership is established. Add a deterministic interleaving test at the identity-check/removal boundary. An inode comparison followed by pathname unlink is insufficient by itself.

2. **Low — a newly created digest directory can be orphaned and its original error obscured.** `openOrCreateRunViewInputDigestDir` returns `created=true, fd=-1, err` after a `Fchmod`, `Fsync`, or validation failure (`craft_runtime.go:733-746`). The new caller branches on `created` first, calls `Fstat(-1)`, and returns `EBADF` before recording the directory for rollback (`craft_runtime.go:461-473`). **Impact:** the staging error is misreported and a partial directory may remain, making retry fail as an extra/noncanonical object. **Smallest defensible correction:** handle `err` before `Fstat`, and arrange cleanup of a directory created before the helper failed using a safely verified identity; preserve the original error. Add fault-injected coverage for the created-directory failure path.
