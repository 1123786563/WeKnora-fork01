1. **Temporary replacement deletion:** `writeRunViewInputAtomicWithHooks` (`internal/container/craft_runtime.go`) publishes with a single `renameRunViewInputNoReplace` call and never unlinks the temporary, target, or digest-directory path. The deterministic after-publication hook creates a replacement at the former temporary name; `TestRunViewInputPublicationDoesNotUnlinkReplacedTemporaryName` verifies its inode and bytes survive. The staging-level variant verifies that this extra object fails final exact-tree inspection before Prompt. The report records a behavioral RED failure on the fix2 `Linkat`/`Unlinkat` implementation; the current test passes. Linux uses `Renameat2(..., RENAME_NOREPLACE)` and Darwin uses `RenameatxNp(..., RENAME_EXCL)`, with no ordinary-rename or hard-link fallback. Primitive tests cover existing regular-file, symlink, and directory targets, and source-name consumption on success.
2. **Created-directory errors:** `openOrCreateRunViewInputDigestDirWithOps` keeps a successfully created directory on injected real-operation `Openat`, `Fchmod`, `Fsync`, and `Fstat` failures, returns `created=true, fd=-1`, preserves the primary error via `errors.Is`, closes an opened descriptor, and short-circuits later operations. A successful but noncanonical stat returns conflict. The test no longer removes the directory from its callback. Separate staging tests accept a canonical empty admitted digest directory and reject a noncanonical or extra-object directory; existing revoked-association tests check current scope before staging.

The source-swap test moves the original temporary inode away before publication and puts foreign bytes at its name. The no-replace rename can move that foreign inode, but the final target/open-descriptor identity check returns conflict; no rollback deletes the foreign target and the Prompt spy remains at zero calls. An injected `ENOTSUP` reaches the caller unchanged, makes exactly one publication attempt, retains the temporary marker, and does not reach Prompt. A target appearing before publication maps `EEXIST` to conflict without replacement. Errors after successful publication retain `published=true` and fail preparation without pathname cleanup.
