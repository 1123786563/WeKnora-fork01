> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 首个纵向案例端到端：Jira 示例插件经空间安装与成员个人连接接入后，成员在对话中查询本人本周 Jira 待办，收到带 Jira 来源链接的结果；未授权成员先获得授权引导；两名成员数据隔离；空/403/超时/失效结果如实呈现，不虚构。

**Architecture:** 纯集成验收切片（无新生产代码——除非验收暴露缺陷）：复用 T10/T11 的 `plugintest` + `pluginpg` 基建，将受控替身升级为"Jira 形替身"（内嵌 fake Jira HTTP 服务按成员凭据分账本返回事项），沿 `RegisterMCPTools → discover → describe → call` 应用边界 seam 断言全部用户可见行为。替身复刻 T04 契约：工具名 `search_my_week_issues`、无参 schema、目录公开/执行鉴权、输出含 `browse` 链接。

**Tech Stack:** Go 1.26；`//go:build integration` 真 PG 集成（`PLUGIN_TEST_DATABASE_URL` Fatal 模式）；sdkserver + httptest。

**Spec:** `docs/specs/2026-09-23-self-hosted-plugins-spec.md`（Solution 第 13 行；User Story 20/21/23；Testing Decisions 第 61-66 行首条）；范围裁决 R10。

**Issue:** https://github.com/1123786563/WeKnora-fork01/issues/113 （blocked_by #109+#111+#112 → 任务级前置 T04、T05、T10、T11）

## Global Constraints

见总索引。fake Jira 的成员凭据（如 `tok-user-a`）为测试专用随机生成（`"tok-"+uuid`），不构成可用凭据字面量。

## Review Focus（本切片）

- 未授权引导发生在**对话内**（调用时 OAuthRequiredError → 授权完成 → 重试成功）——不是仅 API 层静态状态（T13）。
- 模型侧注入账号参数（args 带 `token`/`jql`）→ schema 拒绝（T13，替身与 T04 同契约）。
- Jira 侧 403/超时/失效 → 对话结果如实报错、不虚构空列表（T13）。
- 每成员只见本人事项且链接可打开格式（`<jira-base>/browse/<KEY>`）（T13）。
