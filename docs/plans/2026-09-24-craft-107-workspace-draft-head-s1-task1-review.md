# S1 Task 1 independent Spec and quality review

**Scope:** Task 1 checkpoint `e9a94451b9644a6859a2c91677ccf1667f76ac8a334c58d283f84640cb2c59f5`, its ten listed files (including both paired ignored SQL migrations), approved Craft artifact Spec, `CONTEXT.md`, ADR-0004/0008/0009, corrected draft-head seam, and S1 plan. Task 2 `Advance` returning `ErrUnsupported` is intentional and was not reviewed as an implementation gap. The checkpoint and sampled file hashes match the manifest. I independently ran `go test ./internal/modules/craft ./internal/application/repository -run 'DraftHead|Workspace' -count=1`: both packages passed. PostgreSQL execution remains unverified because `TRPC_TEST_POSTGRES_DSN` is unset; the report records that skip accurately.

## Findings

1. **High — authorization can race owner transfer.** `CraftDraftHeadStore.Read`, `internal/application/repository/craft_draft_head.go:61-89`, checks Workspace owner in one statement, then reads the head and selected file object refs in later statements without a shared snapshot or owner predicate. `CraftStore.PutWorkspace` can update `owner_id` (`craft_workspace.go:166-175`) between these statements. A formerly authorized caller can receive the new owner's draft refs after transfer; similarly a head advance between the head and files queries can give a mismatched result. **Smallest correction:** read authorization, head revision, and its files from one consistent database snapshot with owner/session/tenant checked at the read boundary (for example, a repeatable-read transaction with a scoped Workspace predicate, or a scoped joined query), and add a concurrent owner-change/head-advance test. The current empty-only tests cannot expose this.

2. **Medium — unresolved is also classified as not found.** `craft.ErrDraftHeadUnresolved` in `internal/modules/craft/draft_head.go:17` wraps `craft.ErrNotFound`; `draft_head_test.go` explicitly asserts that relationship. The seam and Task 1 plan require an existing legacy Workspace without trustworthy history to return a **distinct unresolved** result, never be interpreted as an absent Workspace or empty seed. A caller using normal `errors.Is(err, craft.ErrNotFound)` recovery can take the absent-Workspace path. **Smallest correction:** make unresolved an independent sentinel and test that it matches neither `ErrNotFound` nor `nil` while `Read` still returns it for a legacy row.

3. **Medium — SQL does not bind head tenant or selected source Run to their parents.** Both `000195` and `000116` migrations declare `heads.workspace_id` as an ID-only FK to `craft_workspaces`, and `revisions.source_run_id` has no FK to `agent_runs`; see PostgreSQL SQL lines 1-24 and corresponding SQLite lines 1-24. Both parent tables have usable identity keys (`craft_workspaces.id` plus tenant and `agent_runs(tenant_id,run_id)`). The S1 schema contract calls for composite tenant/Run referential checks where supported, while the current DDL permits a head with the wrong tenant and a revision naming a foreign or nonexistent Run. Go authorization during `Advance` is still mandatory, but cannot repair malformed rows written through another path. **Smallest correction:** add a supporting unique `(tenant_id,id)` key to `craft_workspaces` only if this is acceptable for that table, then use composite FK for head identity; add `(tenant_id,source_run_id)` FK for selected revisions, choosing deletion behavior explicitly. If the existing schema/retention contract prevents either FK, record the concrete constraint and add transactional identity/integrity tests before S2.

## Verdict

**Spec compliance: conditional, not approved for downstream S2.** Atomic empty revision 0, scoped legacy unresolved read, paired up/down schema, and canonical selected-manifest validation are present. The unresolved error hierarchy and omitted referential checks diverge from the explicit S1 contract. The high-severity read race leaves an authorization gap once selected heads exist.

**Code quality: blocked by the read race.** The focused test passes and the Task 1 report accurately distinguishes SQLite coverage from skipped PostgreSQL coverage. Add tests that exercise authorization and consistent reads during concurrent owner/head changes; PostgreSQL migration and runtime behavior should be exercised when a DSN is available. Existing Task 2 CAS and quiescence work is outside this review.
