## Medium — fixture-driven abort is credited as network denial

**Evidence / affected symbols:** `validate_browser_evidence` requires only a nonempty `failure["error"]` (`probe.py:185-187`); when the URL and type match Fetch/WebSocket, it adds the attempt to `failed_ids` and then `covered_classes` (`:188-197, 239-253`). The page fixture sends every Fetch with `AbortSignal.timeout(1000)` (`preview/app.js:163-172`), which can produce CDP `net::ERR_ABORTED` because JavaScript canceled a request before its network result. I independently changed only the synthetic `fetch-public` failure reason to `net::ERR_ABORTED` in a read-only invocation of the current test evidence builder. The validator returned `fetch:public` in `covered_classes`, omitted `fetch-public` from `unobserved_browser_attempt_ids`, and reported no observation limit for it. The 19-test Python suite does not cover this case.

**Impact:** A request canceled by the test page can be counted as evidence that the container/browser denied that external destination. That is a false-green per-class proof even though the current 25 Document limits still prevent the entire runner from passing. Future resolution of Document evidence could make this materially affect the release gate.

**Smallest defensible correction:** Classify CDP failure reasons by whether they establish a network boundary outcome. Treat `net::ERR_ABORTED` and other client/fixture cancellation reasons as unobserved with an explicit `client_aborted` limit; do not put them in `failed_ids`. Keep the exact URL/type and response/handshake checks. Add a test with all 37 rows and a matching Fetch failure whose reason is `net::ERR_ABORTED`; it must not credit `fetch:public`. The live proof should also distinguish the fixture's timeout from a network namespace denial before claiming a class.
