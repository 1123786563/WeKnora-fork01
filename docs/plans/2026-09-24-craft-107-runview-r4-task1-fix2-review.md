Its update compares old `task_json` and `prompt_message_id` while requiring the matching tenant/session/owner/epoch Run (`craft_runtime.go:454–463`). A failed CAS reloads the scoped row and only returns its durable `msg_` winner after request and current-fence checks (`:469–524`). A retry with the original UUID reuses that winner. The changed-request `Execute` test asserts conflict, unchanged task JSON/message ID, and zero inner dispatch (`craft_runtime_r4_seed_execute_test.go:250–272`). The two-adopter test checks one returned ID; 50 repeated runs and the R4 race suite passed. These tests exercise SQLite concurrency; they are not a PostgreSQL-specific transaction test.
- The partial frozen D1 test pre-seeds an exact `index.html`, lets production `Execute` add the missing sealed `site.css`, then changes the private CSS bytes and confirms the next retry conflicts before inner dispatch (`craft_runtime_r4_seed_execute_test.go:50–66`). This covers partial completion and tamper rejection through the runtime boundary.
- Failed B returns before artifact collection (`craft_runtime.go:249–257`). The persisted V1 fixture checks that its list position, manifest row, and object bytes survive the failed Execute. The current/default projection is derived from newest-first listing, with no mutable pointer column in this seam.

Two H2 knowledge tests stop on `craft forbidden: incomplete durable Run writer fence`, before their intended knowledge assertions. The first pair and the H2 fixture defect were already recorded in the Fix1 review; this Fix2 delta did not edit those fixtures. The full package gate is **red**, and those failures must be resolved by their owners before overall completion.
