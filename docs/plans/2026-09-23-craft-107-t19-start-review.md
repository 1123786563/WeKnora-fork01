## Critical finding — denied budget or call cap can start externally without intent/hold

**Evidence / affected symbol:** In `CraftBudgetService.StartBinding`, reaching `used >= row.MaxCalls` pauses the Run, sets `startErr = craft.ErrGrantExhausted`, and returns `nil` from the transaction (`craft_budget.go:208-218`). A mapped G4 reserve denial similarly deletes the provisional call row, pauses the Run, sets `startErr`, and returns `nil` (`:230-243`). After the transaction commits, the code checks only the transaction error and context; it never checks `startErr` before calling `start(boundedCtx)` (`:253-274`). `journal` remains the zero value in both branches, because journal creation is below the reserve step (`:248-252`). The subsequent state update against zero tenant/Run/activity cannot undo an external start (`:287-301`). The new tests cover successful reservation, lost response and pause order, but not either denial branch (`craft_budget_start_test.go:16-122`); older cap/reserve tests exercise `AuthorizeBinding`, not this new `StartBinding` branch.

**Impact:** A chargeable model/sandbox initiation can occur after the Run has been paused, with no committed journal intent and no G4 hold. It is untraceable by the recovery scan and can exceed the call cap or available funds. This is an actual control-flow path in the reviewed checkpoint, not a hypothetical provider behavior.

**Smallest defensible correction:** Immediately after the prepare transaction succeeds, return the mapped `startErr` with no callback whenever it is non-nil; do not run the pre-send cancellation or outcome-update paths with a zero journal. Add two focused tests with callback counters: exhausted MaxCalls after a first activity, and G4 reserve denial with insufficient funds/task limit. Assert callback count zero, no new journal/hold, and durable budget pause for each. Re-run the existing B-first/pause and fault tests on the corrected snapshot.

## Confirmed normal path and verification limits

The normal path locks and checks the tenant/Run row and mapping, rejects duplicate `(tenant, Run, activity)` journal keys, counts call cap, reserves/marks dispatched and inserts `intent` before the SQL commit (`craft_budget.go:187-253`). Callback initiation is outside the transaction (`:269-274`); outcome persistence uses `state='intent'` CAS (`:287-301`). An outcome-write failure leaves committed intent/hold; possible-send errors become `unknown`. The revised B-first test confirms pause can commit during callback while the dispatched hold remains (`craft_budget_t19_test.go` checkpoint patch). These are meaningful improvements but do not offset the Critical branch.
