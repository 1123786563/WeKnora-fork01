# T08 Opportunity Web implementation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user paste a JD in the Web conversation experience, import it exactly once under a stable request ID, open the resulting immutable evidence page, and reopen it after reload.

**Architecture:** Add a decoded Opportunity contract/API separate from profile `CareerAction`. Keep the chat host's import affordance explicit and pass the typed imported reference to a Career-owned result action. Register a fixed-ID evidence route in the platform router; the evidence page reads by both opportunity and snapshot ID. Render the JD only as escaped text. Use the existing scope controller to fence late responses and clear sensitive content on scope change.

**Tech Stack:** TypeScript, React, TanStack Router, `@weknora/api-client`, `@weknora/career-core`, Node/Web tests.

**Sources:** #146 snapshot `docs/plans/issue-140/issues/issue-146.md`, approved `docs/specs/2026-09-23-weknora-job-search-design.md`, ADR-0017, `docs/plans/issue-140/task-8-architecture.md`, reviewed backend contract (to be integrated before implementation).

## Global Constraints

- Implement after reviewed T08 backend integration; read actual wire structs/handler tests before coding and record any difference from this plan. Backend routes are POST `/api/v1/career/opportunities/import`, GET `/receipt?requestId=`, and GET `/:opportunityId?snapshotId=`.
- JD text is untrusted plain text. Never parse it as a tool directive or render it as HTML/Markdown. Do not fetch its `sourceReference` URL.
- The Opportunity command is independent of profile revision and must not use `CareerDesk.act`. Same attempt uses the same request ID; changed intent must be an explicit conflict; ambiguous response must preserve a receipt recovery action.
- Local commits authorized; no push/merge/deploy. No backend writes. Preserve user changes and the existing chat behavior.

## Review Focus

- A normal chat user can explicitly paste and import a JD, receive a typed result action, navigate to evidence, reload, and see exact raw text, source and acquisition time. There is no reliance on parsing assistant prose for IDs.
- Missing extracted fields are shown as unknown. `needs_review` is shown as saved evidence awaiting review, never as a failed import or invented condition.
- The result action includes fixed `opportunityId` and `snapshotId`, and stale request/tenant responses cannot leak previous content.
- Replay/receipt recovery and bad wire payloads are covered by tests. Browser acceptance uses real local API/SQLite after focused tests pass.
