# T19 E0 Fix1 independent review

**Date:** 2026-09-24. **Scope:** Fix1 plan, updated E0 report, `egress-probe/run.sh`, mock server, and retained `raw-output-20260924013413.txt`, `raw-output-20260924013431.txt`, `raw-output-20260924013433.txt`. Read-only; no probe or OCR rerun.

## Verdict

**E0 remains blocked; Fix1 does not satisfy its own acceptance.** The retained `13431` log closes the earlier missing-artifact gap for image/version, one successful unprotected baseline, adapter route, and basic external IP/DNS failures. It does not prove exclusive adapter reachability, a successful model completion, same effective HOME after restart, or the redirect/custom-baseURL/proxy bypass matrix. The report correctly says “blocked/partial” and keeps model egress off, but its claim of exactly two adapter POSTs is false for the retained successful-baseline run.

## Findings

1. **High — A direct listener on the internal network is reachable in principle; no no-bypass result is shown.** `run.sh` attaches both `mock-adapter` and `direct-listener` to the same `--internal` network. `raw-output-20260924013431.txt:96-110` confirms adapter `192.168.229.2` and direct listener `192.168.229.3`. Docker `Internal=true` blocks routes outside that network; it does not deny a container on that network from contacting the directly attached listener. No custom-baseURL or proxy attempt to `direct-listener:8080` and no direct-listener request count were captured. **Impact:** the recorded IP/DNS denials do not establish the required adapter-only route or gateway/provider bypass prevention. **Smallest correction:** use the final topology in which OpenCode shares only the adapter's isolated network and the direct gateway/provider listeners live on a separate network; test hostile baseURL, direct IP, DNS, proxy and redirect routes, with both denied connection and zero listener counts.
2. **Medium — The report understates route calls and does not establish model completion.** The Fix1 paragraph says “exactly two” adapter POSTs. `raw-output-20260924013431.txt:64-67` has **four** `/v1/chat/completions` POST records: title and task calls for each of two OpenCode invocations. The client output shows the `> build · mock-model` line and clean loop exit but no `probe-ok` completion; the mock returns a JSON completion to requests whose body has `stream:true`. `run.sh` retains `|| true` for both OpenCode invocations and never asserts exit, POST count/path, or returned content. **Impact:** a failed turn can be reported as route success, and request-count evidence is misstated. **Smallest correction:** use a valid streaming response or non-streaming test setting, assert observed completion and exact expected calls per turn, save exit codes, and correct the report to four POSTs for the `13431` run.
3. **Medium — The claimed persisted HOME does not match OpenCode's observed config location.** `run.sh` mounts one host directory at `/tmp/home` and sets `HOME=/tmp/home` in both runs, but `raw-output-20260924013431.txt:7-10,37-40` shows OpenCode loading `/home/craft/.config/opencode/*` and `/workspace/opencode.json`. There is no mount/config/network/environment inspection inside either OpenCode container. **Impact:** the second invocation is a new container, but this evidence does not establish recovery with the same effective OpenCode HOME or sealed config. **Smallest correction:** inspect effective UID, HOME, XDG paths, mounts and loaded config in both containers; persist the paths OpenCode actually reads, then restart and verify their identity/content and route.
4. **Medium — The fixture remains fail-open and the report mixes failed and successful attempts.** `raw-output-20260924013413.txt` records `baseline_direct_http=000`; the later `13431` log records `baseline_direct_http=200`. The report attributes `000` to “the rerun” and cites an earlier independent `200`, obscuring that the retained `13431` Fix1 run itself reached `200`. `run.sh` prints rather than asserts image ID, architecture and version, suppresses baseline/OpenCode failures with `|| true`, and has no post-run inventory. The `13433` file is a hand-written summary, not raw command output, and its stated exit 6 is not captured alongside the `13431` transcript. **Impact:** a run with a failed control or wrong image can appear evidentially successful; per-attempt status and cleanup are hard to audit. **Smallest correction:** index each attempt with timestamp, command, exit code and artifact hash; assert the exact image ID/version, baseline 200, route result and cleanup inventory; retain stdout/stderr and status before any summary.
5. **Medium — Release-critical bypass cases are still absent.** `mock_server.py` has a `GET /redirect` response, but `run.sh` does not exercise it; it also does not run writable custom-provider/baseURL or proxy-env attempts. The logged `direct_ip_rc=7` and `provider_dns_rc=6` test public `1.1.1.1` and `api.openai.com`, not a directly attached gateway listener. **Impact:** E0's explicit redirect, config override, proxy and listener-zero criteria remain unmet. **Smallest correction:** execute the Fix1 plan's full matrix against controlled mock targets, record each exact command and exit, and require zero direct-listener requests after each attempt.
