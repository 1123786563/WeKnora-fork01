# T19 E0 independent evidence review

**Date:** 2026-09-24. **Scope:** read-only review of the E0 brief, report and checked-in `docs/testing/craft/egress-probe/` fixture. No probe or OCR was rerun. The approved Craft Spec stories 34–35 require budget-controlled model spending and a durable budget pause; ADR-0003, ADR-0009 and `CONTEXT.md` keep execution, credentials and budget authority with WeKnora. E0 is a route and bypass feasibility gate, not proof of those later T19 behaviors.

## Verdict

**Spec compliance: partial, E0 not passed. Quality of evidence: incomplete.** The observed adapter route and basic Docker internal-network denial are plausible and consistent with the fixture, but only the report contains the measured HTTP and direct-control results. The checked-in script does not run the direct-control or deny commands, and no raw logs/inspect output are retained. The report correctly labels this partial evidence, keeps paid egress off, and lists the major untested paths. The next task must close the evidence and bypass gaps before treating the route as enforced or starting E1 under the brief's gate.

## Findings

1. **Medium — Control and deny results cannot be independently reproduced from the retained fixture.** `docs/testing/craft/2026-09-24-t19-egress-e0-report.md` states `baseline_direct_http=200`, `direct_ip_rc=7 http=000`, and `provider_dns_rc=6 http=000`; `egress-probe/run.sh` contains none of these commands and `egress-probe/` contains no output log. Impact: the unprotected baseline and the two `--internal` denials are uncorroborated measurements, so the policy result cannot be reviewed against target addresses, network attachment, timing, or command exit status. **Smallest correction:** retain a redacted transcript with exact commands, target IP/hostname, response/exit codes and `docker network inspect` output; put those checks in the fixture with assertions.
2. **Medium — The adapter invocation is not a fail-closed assertion.** `egress-probe/run.sh` executes `opencode ... run ... 2>&1 || true`, then prints the adapter log if present, also with `|| true`; it never asserts the two POSTs, their paths, or a successful model turn. The report says two `/v1/chat/completions` POSTs were observed, one title turn and one task turn, but retains no raw adapter log or OpenCode output. Impact: a failed OpenCode run or missing adapter call could still produce a successful script exit. **Smallest correction:** preserve the redacted raw request/response and OpenCode transcript, fail on unexpected exit, and assert exact POST count/path and the expected completion response. Record automatic retry observations separately; equal request bodies do not identify retries.
3. **Medium — The release-critical bypass matrix and recovery seal remain untested.** The E0 brief requires restart with the same HOME, redirect, custom `baseURL`, proxy-env route and zero requests at every direct listener. The report explicitly excludes restart, redirect and hostile project config, and neither the fixture nor report shows proxy override or listener-zero checks. The fixture's project config is mounted read-only for a fresh, disposable HOME; it does not establish that a writable persisted OpenCode HOME/workspace cannot override the route on creation or recovery. Impact: `--internal` may deny the two reported external probes while a supported alternate route or a changed config bypasses the private adapter; E0's no-bypass exit criterion is unmet. **Smallest correction:** run each named attempt under the final proposed network/config policy, restart the same HOME, inspect the effective config/network/env before each turn, and retain zero-count logs from independently reachable direct mock listeners.
4. **Low — Image identification is accurate but not enforced by the fixture.** Live read-only `docker image inspect weknora-craft-runtime:1.18.4` returned ID `sha256:9678e13bd1c7dc9650aef26623ef8ab276d46565bbd6cb006b8e308229968f11`, `linux/arm64`, matching the report. This is a local image ID, although the report calls it an “ID/digest.” `run.sh` permits arbitrary `IMAGE` and only prints inspect output. Impact: a later successful run could silently use another image. **Smallest correction:** assert the expected ID, architecture and OpenCode version at fixture startup and record the actual immutable image ID with each run.
5. **Low — Cleanup is bounded but only partly evidenced.** The fixture trap removes its adapter, run container, network and temporary directory on exit. Current read-only `docker ps -a` and `docker network ls` filters show no `craft-egress-*` containers or `craft-egress-probe-*` networks. The report does not retain post-run inventory, and the `--rm` OpenCode container and trap behavior were not tested under failure. Impact: resource cleanup is credible for this run but not auditable from its original output. **Smallest correction:** append post-run resource inventory and assert absence of the fixture's exact names.

## Evidence reconciled with the claim

- The pinned image exists locally with the stated **image ID** and architecture. The report's `opencode --version = 1.18.4` is consistent with the earlier image-build report, but the E0 fixture does not run or save that version command.
- `egress-probe/opencode.json` sets `provider.mock.options.baseURL` to `http://mock-adapter:8080/v1` and a probe-only API key. `run.sh` attaches OpenCode and the Python mock adapter to a disposable `docker network create --internal` network, then invokes `mock/mock-model`. This supports route feasibility if the report's two POST observations are accurate. The exact route headers and bodies are report claims without retained raw log evidence.
- The report's `direct_ip_rc=7` and `provider_dns_rc=6` are consistent with IP connection failure and DNS lookup failure, respectively, but without target/command/output detail they do not prove gateway/provider-specific denial. No direct-listener zero count was recorded. The reported `internal=true containers=0` is not a saved `docker network inspect` output; the fixture inspects before its trap removes the adapter, so that count cannot describe the same instant. Effective attachments during the OpenCode run are not retained.
- Neither the fixture nor the report places a real upstream key or gateway credential in OpenCode; the mock `apiKey` is `probe-only`. This proves the probe did not need a real key, not that the eventual production credential path is safe.

## Next concrete checks

Run one self-contained, pinned-image fixture that saves redacted raw transcripts, asserts the baseline direct listener is reachable without the policy, and then asserts adapter POSTs plus zero direct-listener requests under the policy. Repeat with the same persisted HOME after restart and with redirected responses, writable custom provider/baseURL, proxy environment variables, direct gateway/provider IP and DNS targets. Capture effective container network, DNS, mounts, HOME config and environment at creation and recovery. A denied curl and zero listener count should both be required. Keep E0 partial and model egress default-off until these pass; E1–E5 remain separate implementation and acceptance gates.
