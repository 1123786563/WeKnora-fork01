## Findings

### T14-R1 — High — generated page can initiate browser navigation to external or internal URLs

**Evidence:** `internal/application/service/craft_preview.go:532-549` sets `connect-src 'none'` but allows the generated page's scripts (`script-src 'self' 'unsafe-inline'`) and does not restrict navigation. `deploy/craft/preview.conf:32-36` delegates only an iframe `sandbox="allow-scripts"` rule to a future embedding task; it does not constrain a direct preview tab. `deploy/craft/browser_probe.py:78-103` exercises `fetch` and WebSocket only, while its route handler aborts any external request if one occurs. The Docker probe's network namespace covers the server-side sandbox, not the end user's browser, as the lane report itself states at lines 26-30. A page script can assign `window.location` to a public or private URL; an iframe may navigate itself even when top navigation is disabled.

**Impact:** A generated artifact can cause the user's browser to make a request to an internet or enterprise-network address. That violates #129's no-egress intent and can carry data in a URL even though the Docker container has `network_mode=none`. The existing browser probe would not identify this as a policy failure because no navigation probe is attempted.

**Smallest defensible correction:** Add a real-browser navigation probe (direct preview and embedded preview) that fails if any request leaves the preview site. Constrain navigation in the supported browser/deployment path and verify it at the browser network boundary; CSP fetch/WebSocket checks and the server Docker namespace alone are insufficient. Keep the feature gated until this path is demonstrated.

### T14-R2 — High, integration gate — live selected sandbox and site policy are not wired

**Evidence:** `internal/application/service/craft_preview.go:405-410` refuses every issuance/read if `NetworkChecker` is nil. The current central `internal/container/container.go:2537-2545` constructs `CraftPreviewConfig` with only the two origins and no `AccessChecker` or `NetworkChecker`. `deploy/craft/preview.conf:44-48,58-64,93-99` is a template with hostname/upstream/certificate placeholders. `deploy/craft/probe-preview-network.sh:7-16` creates its own `--network none` container rather than loading the Task's selected binding. `internal/application/service/craft_preview_network_test.go:54-64` inspects an ID supplied by an environment variable, independent of the bound Task. The T14 report explicitly defers central assembly and live verification.

**Impact:** The central app fails closed and cannot serve #129 previews yet. The evidence does not establish that a real tenant's selected sandbox configuration, running container, and production preview host enforce the intended boundary.

**Smallest defensible correction:** In the centrally owned integration step, inject the T08 `TaskAccessChecker` and `CraftPreviewDockerNetworkChecker` using the Task's selected binding, deploy the actual isolated site, then run an end-to-end request and inspect that *same bound running container* for `NetworkMode=none`. Record browser and network evidence against that assembled version before accepting #129 or T15 promotion. This is an integration dependency, not a request for T14 lane ownership expansion.

## Positive evidence and limits

- `PreviewOriginAllowed` compares registrable sites rather than ports/subdomains (`internal/modules/craft/preview.go:46-66`); the preview handler rejects a request on the app host before redeeming a ticket (`internal/handler/session/craft_preview.go:116-125`).
- Ticket digest storage, one-time consumption, scoped file-set capabilities, expiry, fresh membership checks and per-read live network check are present in `internal/application/service/craft_preview.go:233-410`. Version lookup and manifest membership are checked on each read; invalid paths are rejected by `ValidatePreviewRequestPath` and `ValidateArtifactPath`.
- The browser evidence `/tmp/craft107/t14/browser.json` and Docker result are reported by the implementer. The Go browser test uses an in-process service with a fake always-allow `previewNoEgress` (`internal/handler/session/craft_preview_test.go:322-325`), so it does not combine browser rendering with the selected live Docker checker. That split is acceptable as a lane test but does not satisfy the final environment gate.

**Disposition:** Do not mark T14 verified or allow T15 promotion until R1 is resolved and R2 is demonstrated on the assembled deployment. Re-review the resulting exact checkpoint and bound evidence.
