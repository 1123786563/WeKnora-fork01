# RunView Durable Create-Intent Plan

> **For Codex:** Execute through SDD RED → GREEN → REFACTOR, exact uncommitted checkpoint, independent Review and backend validation. No commit.

**Goal:** Add the missing durable pre-CreateSession fence to RunViewStore, closing the R1 feasibility blocker in `runview-runtime-r1-report.md`. A worker may send a non-idempotent OpenCode CreateSession only after it uniquely wins and commits a generation-scoped create intent; retries/restarts see an unknown attempt and must reconcile, never issue another POST blindly.

**Sources:** Approved Spec #107/#120/#124, RunView runtime adapter plan/R1 report, RunView binding/retention plans/reviews, PG 000192/SQLite 000113, current `craft.RunViewStore` and `CraftRunViewStore`. Migration numbers reserved here: PG `000193_craft_run_view_create_intent`, SQLite `000114_craft_run_view_create_intent`. Check names remain unused before writing.

**Global Constraints:** backend_implementer owns only new four 000193/000114 migration files; `internal/modules/craft/run_view.go` and tests; `internal/application/repository/craft_run_view.go` and tests; task report. No `container.go`, runtime adapter, OpenCode, T05 Publisher, T08/T19 code, commits or subagents. Other agents share integration Worktree; preserve their changes. Migration files are Git-ignored: include full contents+SHA in report and controller will `git add -N -f` after review. Do not alter existing 000192/000113 so already-applied installations can migrate forward.

**Review Focus:** one atomic CAS winner per `(tenant,owner,Task,Run,generation)`, commit before external call, no automatically retryable state after lost response, no partial runtime binding, no cross-scope intent, robust SQLite/PostgreSQL transaction behavior. `BeginSessionCreate` returns a one-shot `maySend` only to the transaction winner; all later callers get a durable unknown/attempted view with `maySend=false`. Crash between committed intent and actual POST can strand the Run, which is a conservative limit and requires explicit reconciliation/provider proof. Marking a blank allocating row as safe to send on a later retry is prohibited.

## Task 1 — migration and typed contract

1. RED: contract/repository tests require `CreateIntentAt` (or equivalent durable marker) absent on fresh Allocate, a one-shot begin operation, and no second permission after store reopen/concurrent connections. Run against current code to capture missing API/column failure.
2. GREEN: add nullable UTC timestamp and/or unguessable attempt token through additive PG/SQLite migration; clear `NULL` means no recorded attempt. Update typed RunView validator and store interface with `BeginSessionCreate(ctx,key,generation) (view,maySend,error)` or equivalent. CAS with tenant/owner/session/run/generation and `state='allocating'` and intent NULL, in one committed transaction; return `maySend=true` only when UPDATE affected one row and commit succeeded. Store Load/Allocate return the marker. `BindRuntime` requires recorded intent for new allocation and still CAS-binds complete runtime triple; exact bound replay works.
3. Test migration absent/up/down/reapply, old bound rows, old allocating rows, two-connection races, restart, wrong scope/stale generation, external failure after begin and no repermission. Run focused Craft/repository tests, full repository suite if shared work stable, PG17 in disposable schema if available, `git diff --check`, full-content/hashes/status checkpoint. Independent Review before R1 coordinator resumes.

**Failure handling:** If the selected SQL dialect cannot atomically expose one winner, report it; do not implement process-local locking. If a pinned provider lacks scoped session inventory, this marker still prevents duplicate CreateSession but does not by itself resolve unknown outcomes; keep R1 and T01 unverified until that second seam is proved.
