# Issue #106 自行托管插件与清单安装 — 实施计划总索引

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 开发者自行部署远程 MCP 服务并发布版本化插件清单；空间管理员粘贴清单地址核验预览后安装确定版本；成员发现插件、完成个人授权后，Agent 仅调用空间已接受版本中已启用的工具；新版差异审阅手动接受、远端漂移阻断、新增写工具默认关闭并可配置成员审批。

**Architecture:** 在既有 MCP 客户端链路（`MCPManager` → `tools.RegisterMCPTools` → `MCPCatalog`/`MCPTool.Execute` → `approval.Gate`）之上增加插件产品层：新 `internal/modules/plugins/` 包承载清单协议、SSRF 安全抓取、工具快照核验与版本差异；新表 `plugin_previews`/`plugin_installations`（PG 000189/000190、SQLite 000110/000111）持久化预览有效期、已接受版本快照与漂移状态；安装时把插件**物化**为一行 `mcp_services`（新列 `plugin_installation_id` 关联），从而零侵入复用 Agent 工具目录、per-principal OAuth、工具启停与审批闸门；`RegisterMCPTools` 新增 `PluginSnapshotProvider` 参数对插件服务实施快照过滤与漂移拒绝。

**Tech Stack:** Go 1.26（`mark3labs/mcp-go` 客户端/服务端、gorm + PostgreSQL versioned migrations + SQLite twin、gin handler、node:test/require）；React（`apps/web` + `packages/api-client` + `packages/views`，node ≥26 经 `pnpm gates`）；示例插件服务为 Go 独立 main 包（`examples/plugins/jira-todo-mcp`）。

**Spec:** `docs/specs/2026-09-23-self-hosted-plugins-spec.md`（已批准）；`docs/specs/2026-09-23-self-hosted-plugins-design.md`（设计）；`docs/plans/issue-106-scope-dag.md`（范围裁决与依赖 DAG）；`docs/plans/issue-106-code-baseline.md`（代码基线勘察，本计划引用的行号均以该 worktree HEAD 为准）。

**Worktree:** `.worktrees/issue106`，分支 `codex/issue-106-self-hosted-plugins`。所有改动只发生在本 worktree。

其余架构决策：

- **物化 MCPService**：安装确认在事务中创建 `plugin_installations` 行 + 一行 `mcp_services`（`Name = "plugin:" + plugin_id` 保证 `(tenant_id, name)` 唯一稳定；`URL` = 版本端点；OAuth 清单声明时 `AuthConfig.AuthType = oauth`；`PluginInstallationID` 指回安装）。停用/启用同步 `mcp_services.enabled`，Agent 侧 `registerMCPTools` 只注册 `Enabled` 服务（agent_service.go:279-283），停用即不可见不可调。
- **写工具默认关闭**：安装与升级接受时为快照内**每个**工具写显式 `MCPToolApproval` 行——只读 `Enabled=true`，写 `Enabled=false`（types/mcp.go:148-152 的"缺行=启用"兼容语义只保留给手工服务）。运行时核对复用 `MCPTool.Execute` 的 `gate.IsEnabled`。
- **ADR-0001 边界**：本需求不迁入 open-connector、插件不获得其管理凭据（spec 57 行）；`MCPOAuthBindingStore`/`installations` 表（open-connector 域）不被插件域触碰。
- **示例服务（#109）用 Go**（`examples/plugins/jira-todo-mcp`，独立 main 包，进 `go test ./...`），行为契约：MCP 端点**目录公开、执行鉴权**（未认证 `ListTools` 可用，`CallTool` 校验 Bearer token）——这是安装前核验（#108）能在无个人授权下 `ListTools` 的前提；OAuth 授权码 + PKCE + 动态客户端注册 + RFC 9728 metadata；JQL 由服务端固定模板构造，工具 schema 无输入参数。
- **测试双层**：tools 组装层集成测试（fake plugin repo + 真实 `MCPManager` + httptest 受控服务，先例 mcp_catalog_integration_test.go）+ 服务层应用边界集成测试（真实 PostgreSQL，环境变量 `PLUGIN_TEST_DATABASE_URL`，缺失 `t.Fatal("blocked-env: ...")` 绝不 Skip 通过；isolated schema + AutoMigrate 冻结模型，先例 oc_integration_test.go:83/408-455）。

## Review Focus（Spec 隐含但易咬人的五类输入/失败模式 → 承接测试）

1. **恶意清单 URL（SSRF/协议混淆）**：管理员提交 `file://`、`http://127.0.0.1`、`http://169.254.169.254`、`http://10.0.0.1` 等清单地址 → 抓取前明确拒绝，不发任何请求。→ T01 Step 1 测试 `TestFetchRejectsNonHTTPAndPrivateManifestURLs`、T02 handler 测试。
2. **清单声明与远端目录不符**：清单声明工具在远端缺失、schema digest 不符、远端多出未声明工具 → 预览核验拒绝并列出差异，绝不静默接受。→ T01 `TestBuildVerifiedSnapshotRejectsMismatch`、T14 `TestDiffSnapshotsCoversAllDimensions`。
3. **预览过期/重放/身份变化**：确认安装时 preview 已过期、已被消费、或重抓后 `identity_fingerprint`/`tools_digest` 与预览时不一致 → 安装拒绝且不创建任何安装。→ T02 `TestPreviewExpires`、T06 `TestConfirmInstallationRejectsStalePreview`。
4. **跨成员/跨空间越权**：成员 A 的授权被成员 B 借用、空间 2 看见空间 1 的安装或调用其服务 → 全链拒绝。→ T07 跨空间隔离、T11 `TestMemberConnectionsIsolated`、T13 两成员 Jira 数据隔离。
5. **写工具绕过与审批未决外部写入**：升级新增写工具被 Agent 直接调用、成员拒绝/超时/停用审批后仍发生外部写入 → 运行时 `gate.IsEnabled` 拒绝 + 受控服务写计数恒为 0 + 批准后仅一次派发。→ T18 `TestUpgradedWriteToolStaysDisabledAndZeroExternalWrites`、T19 `TestWriteApprovalRejectTimeoutDisableDispatchZeroWrites`。
