## 做了什么

纵向切片：成员上传归档（走 T01 既有 `AcceptInputRound`，归档本身是不透明输入）→ 服务端
`CraftSessionService.ExpandArchive(ctx, scope, ref)` 在硬资源上限内提取 → 成员成为
**内容寻址只读输入**（对象 + `craft_workspace_inputs` 行，可被 Run 的 InputRefs 解析），
或类型化拒绝且**无任何部分材料**。

### internal/modules/craft/archive.go（纯规则提取器，无 I/O 依赖）

- `DetectArchiveFormat`：仅按内容魔数识别 zip / tar+gzip / tar（扩展名不作为理解证据）。
- `ValidateArchiveEntryPath`：条目名规范化（`path.Clean`）并拒绝空名、NUL、反斜杠、绝对路径、
  Windows 盘符、`..` 穿越、深度 > `MaxArchiveDepth`(8)、超长段（>255）。
- `ExtractArchive`：拒绝一切非常规成员——zip 符号链接/目录以外 ModeType；tar 的
  TypeLink/TypeSymlink/TypeChar/TypeBlock/TypeFifo 及厂商扩展；目录条目占位去重但不产材料。
- 归一化重复路径（如 `b.txt` 与 `./b.txt`、`b.txt` 与 `docs/../b.txt`）→ `ErrConflict`。
- 嵌套归档：成员名带归档扩展名**或**内容带归档魔数 → `ErrUnsupported`（递归展开确定性失败，
  改名绕过被封死）。
- 硬上限（全部按**实际读取字节**判定，不信任头声明）：成员数 ≤ `MaxArchiveEntries`(20=每轮输入数)、
  单成员 ≤ `MaxArchiveMemberBytes`(20 MiB)、累计展开 ≤ `MaxArchiveExpandedBytes`(100 MiB=每轮上限，
  亦即内存上限——成员缓冲至全部通过)、压缩比 ≤ `MaxArchiveCompressionRatio`(100:1)、墙钟
  ≤ `MaxArchiveExtractDuration`(30s，服务层强制)；CPU 由字节上限 × 每字节 O(1) 结构性界定。
- 流截断/损坏在成员读取中途报 `ErrInvalidInput`；空归档/仅目录归档拒绝；输出按规范路径排序。

### internal/application/service/craft_archive.go（服务编排，挂 CraftSessionService）

三段闸门：

1. **授权加载**：`writeSession`（owner ACL）+ craft 行 + workspace；归档必须是**本 workspace 已关联
   输入**（`ErrNotFound`），租户不符 `ErrForbidden`；有界读取 ≤ 20 MiB+1；SHA-256 必须等于受理时
   记录摘要（内容寻址完整性）。
2. **提取**：`craft.ExtractArchive` 全量缓冲；随后以**基名**（`path.Base`）构造成员清单并复用
   `craft.ValidateInputManifest` 做 T01 回合配额二道门（名称形状/摘要形状/每文件/数量/100 MiB）。
   基名取舍原因：T01 冻结输入契约 `ValidateInputName` 只允许单一规范路径元素，且 Run 准入
   （`agent_run.go:568` 等 6 处共享调用点）与暂存布局都校验该形状；归档内完整路径已在提取期
   完成校验与去重后收敛为基名，**零中央改动**即可端到端（旅程测试走真实 StartRun 准入验证）。
3. **发布**：全部成员对象 `SaveBytes`（storageName=`craft_input_<digest><ext>`，内容寻址）→
   单事务插入清单行（`OnConflict DoNothing` + 既有行同内容校验 = 幂等重放返回持久清单）；
   任一失败回滚**未关联**对象（T01 回滚契约）。失败时零行零对象——Run 解析不到任何部分材料。

上下文：入口即检 `ctx.Err()`，全程 `WithTimeout(MaxArchiveExtractDuration)`，加载/提取/发布前
三处再检（取消即中止、无材料）。
