# T08/#146 architecture recommendation (read-only, 2026-09-24)

## Evidence and ruling

Read `CONTEXT.md`, approved `docs/specs/2026-09-23-weknora-job-search-design.md` (§§2–4, 6.1), ADR-0015–0018, #146 snapshot, `docs/plans/issue-140/task-8-research.md`, and integrated T03 Go/TS/Web contracts. #146 requires separate raw JD and extracted fields, explicit unknowns, stable request replay, inert JD instructions, and conversation-result navigation to evidence. ADR-0017 and the Spec require fixed evidence despite later source changes. Current `Office.Act` and `/api/v1/career/act` accept only profile actions; `CareerView.revision`, `/changes`, and `career_receipts` currently encode profile changes. `apps/web/src/chat/ChatRoutePage.tsx` owns chat orchestration, `@weknora/views/chat/page` renders messages, and `apps/web/src/router.tsx` registers routes. No existing Career Web conversation/result component is integrated yet.

**Recommendation:** add a bounded Opportunity interface under Career Office, not a new authority or an overloaded profile fact. Freeze the public wire before T09/T10 consume it. T08 must wait for verified T03 integration, including the SQLite startup fix.

## Public contract

- Input: an explicit `import_jd` command with `requestId`, exact `rawText`, and optional user supplied source label/reference. Server determines `(tenantId,userId)`, receipt acquisition time, and IDs. `source.kind` is `manual_paste`; no implicit URL fetch. Do not use the profile `expectedRevision` for this command. If the generic `CareerRemote.act` signature requires that argument, split/overload the typed command rather than sending a dummy profile revision.
- Result: additive discriminated `kind: 'opportunity_imported'` receipt with `requestId`, `opportunityId`, `observationId`, `snapshotId`, `status`, and stable evidence URL/reference. Existing profile receipt discriminators and their revision semantics remain intact. The receipt decoder must reject malformed variants. A receipt may include summary fields, but IDs are the navigation authority.
- Evidence read: dedicated scoped `GET /api/v1/career/opportunities/:id` (or equivalent versioned Career Office read) returning opportunity identity and current observation references plus a selected immutable snapshot: exact `rawText`, extracted fields, source observation, `acquiredAt`, and extraction state. Include `snapshotId` in the route/query so reopening an old result cannot silently switch to a newer snapshot. A list can expose refs and summaries; `/open` and `/changes` remain profile read models unless a separately versioned aggregate cursor is designed.
- Extracted fields: a structured value with explicit `known`/`unknown` per field, separate from the original text. A missing requirement is unknown, never an empty string interpreted as “no requirement.” Distinguish source fact from extraction inference; T08 may use deterministic limited parsing or return unknowns. Do not call model extraction authoritative without a validated contract and provenance.

## State and ownership

- Persist opportunity, source observation, immutable snapshot, and request receipt atomically under authenticated personal Career scope. Use opaque immutable IDs; retain a content hash of exact raw bytes for integrity/dedup evidence, not as the only identity. Same scoped `requestId` plus identical canonical input returns the stored receipt/IDs; changed input gives `idempotency_conflict`. Replay must be checked before any extraction or revision check. The existing receipt table can be extended only if its profile payload and replay semantics remain compatible; a separate opportunity receipt store is acceptable.
- A source observation records `manual_paste`, optional user provided reference, acquisition time, and its snapshot ID. Later source reads append observations and snapshots. The opportunity is the grouping identity; it can gain observations, but an existing snapshot, observation, acquisition time, and receipt never change. Avoid automatic cross-source merge in T08 because the Spec permits merging only at high confidence.
- Profile revision is for confirmed facts/proposals and `/changes`. Importing a JD does not advance it. An opportunity-local sequence or opaque list cursor can be introduced when T09 needs incremental observation updates; T08 can use stable IDs and ordinary scoped reads. This avoids false profile conflicts and avoids consumers treating an opportunity write as a profile fact change.
- Import outcome vocabulary: `stored` (raw evidence committed, extraction usable) versus `needs_review` (raw evidence committed, extraction missing/failed/uncertain). Transport/persistence failure returns a standard error and no success receipt; an ambiguous commit uses the existing `outcome_unknown` plus request-ID receipt lookup. `needs_review` is a successful evidence import, not a claim that extracted conditions are true. This is a recommendation for interface naming, not a new product policy.

## Trust and navigation boundary

- JD text is untrusted data from the HTTP command through persistence, extraction, rendering, and later Agent consumption. Do not interpolate it into system/developer instructions, tool names, tool arguments, URL fetch targets, grants, or approval decisions. A parser may produce candidate fields only; it cannot dispatch tools or change Task Grant. Render raw text as escaped text, never injected HTML/Markdown with executable links. The explicit user action, authenticated scope, and server policy authorize the import; the JD does not.
- Add a Career-owned conversation result/action adapter at `apps/web/src/career/` that emits a typed opportunity reference (`opportunityId`, `snapshotId`) and navigates to a registered evidence route. The chat host may render that action through an explicit callback/slot; it should not parse arbitrary assistant prose or JD content for IDs/URLs. The evidence page reloads from Career Office by ID and shows source/acquisition time, exact raw text, field provenance/unknown markers, and `needs_review` guidance. Keep `ChatRoutePage` and shared `@weknora/views/chat/page` changes to the smallest integration hook, coordinated with the integration owner.

## Owned files / tests

T08 implementation ownership: `internal/modules/career/service/opportunity.go` and focused tests, or the existing `internal/modules/career/` package if keeping its current package boundary; additive handler/read route registration in `internal/modules/career/handler.go` and `internal/router/routes_career.go`; `packages/career-core/src/contracts.ts` and fixture/decode tests; `apps/web/src/career/opportunity.tsx` and focused Web tests. Router/chat host and shared contract files are integration-owner coordinated seams. Database AutoMigrate/migration registration must be checked against the SQLite startup repair before integration.

Meaningful tests: same request replay returns the same receipt/IDs and one persisted snapshot; changed input conflicts; missing fields stay unknown; extraction failure still reopens exact raw text; adversarial JD creates no tool calls, network fetch, grants, or external side effects; cross-tenant/user reads are denied; later observation cannot alter a previously opened snapshot; malformed wire variants fail decode; Web paste → result action → evidence → reload preserves exact text and source/time, including `needs_review` and duplicate submission. Test the public Office/HTTP seam, not only model structs.

## Spec conflicts / limits

No genuine approved-Spec conflict found. The plan's `CareerRemote.act({kind: 'import_jd', payload}, requestId, expectedRevision)` is an implementation sketch that conflicts with T03's profile-only action shape if copied literally. Resolve it as an additive typed command with independent opportunity concurrency; do not silently repurpose profile revision. The Spec does not choose an extractor, field schema, or opportunity cursor, so keep extraction conservative and record unknowns. T08 does not create an application Task (ADR-0016 applies when the user chooses to prepare a specific application).
