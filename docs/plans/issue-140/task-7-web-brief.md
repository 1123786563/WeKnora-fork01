## Files and interface

Own `packages/career-core/src/contracts.ts` and focused fixtures/tests; `packages/api-client/src/career.ts`, `career.test.ts`, and only a narrow request/transport edit if required for browser multipart; `apps/web/src/career/CareerPage.tsx` and its focused tests/new adjacent components. Keep backend, router, migration, architecture manifests and unrelated Web files untouched. `CareerSource` already names fact provenance; use a separate `CareerDocumentSource` for `/sources` records. A file upload must use multipart `file`, nonempty stable `requestId`, and `expectedRevision` from the displayed view. Browser `FormData` can be sent through the existing `ClientRequest.body` path; do not set a JSON `Content-Type` for it. The upload response is `{source, receipt?}` with 201 initial completion, 202 active processing, 200 exact replay, 409 changed intent. GET `/api/v1/career/sources` returns `{sources: CareerDocumentSource[]}`. A ready receipt uses `kind: "intake_completed"` and `proposals[]` (`internal/modules/career/profile_intake.go:599`). Proposal `evidence` is an optional exact source line. Source has ID/revision/fileName/MIME/size/digest/status/createdAt, optional completedAt/errorCategory/errorMessage/missingCategories/reviewFlags; it does not expose raw text or resource ref.

## Observable acceptance

1. Authorized user selects a local resume, sees upload/progress or processing state, and can review missing categories, flagged conflicts, source versions, exact evidence, and pending proposals. Each proposal is confirmed or dismissed individually using the existing CareerDesk receipt/revision seam; neither pending nor dismissed item is presented as a confirmed fact.
2. Upload/parse failure stays visible with safe message, permits reupload with a new request ID or manual proposal/confirmation, and leaves prior confirmed facts and provenance visible. Do not erase the old profile on a failed upload.
3. An ambiguous transport outcome preserves the same File, request ID and expected revision. Poll `/sources`; same-input replay uses the same ID and fields. While processing, do not create a second upload claim. A terminal failed source offers a fresh upload ID. Do not silently retry with changed bytes or revision. 409 revision conflict refreshes the view and requires an explicit new attempt.
4. Switching user/Tenant or losing authorization clears in-memory source, file and unknown-outcome state and prevents a late response from the old scope from rendering. Retain current T03 CareerDesk semantics.
5. Tests cover multipart/auth scope/decoder, six-category sample with missing graduation and conflicting experience, failure preserving old confirmed facts, receipt replay/unknown handling, revision conflict and scope switch. Run `pnpm typecheck:web`, focused tests, `pnpm test:web`, `pnpm build:web`, and `git diff --check`. Report exact commands and outcomes. Root will run isolated local-server browser acceptance after independent review.

No Web code should infer confirmed status from a ready source or batch proposal. `CareerDesk` already owns action receipts; upload source state can be a small separate controller as long as stale async responses are fenced by scope generation and/or AbortSignal.
