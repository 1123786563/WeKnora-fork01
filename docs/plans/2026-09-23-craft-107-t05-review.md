## Verdict

- **Spec compliance: FAIL for the T05 checkpoint.** The selected document ACL and immutable source-record path are substantially implemented, but a Task reader can stage new Run material, old selected material remains in the shared workspace after a later selection changes, and clipping an individual excerpt is not disclosed as truncation. - **Code quality: FAIL.** The three findings below require correction and behavioral tests. ## Findings

1. **High — Task Viewer can invoke the authoritative material builder.** `internal/application/service/craft_knowledge.go:122-140` calls `RequireTaskAccess(..., craft.TaskRead)` before `Build`, whose `writer` stages files at lines 401-446. T00 defines a separate `TaskWrite` action in `internal/modules/craft/web_contracts.go:18-28`. Thus a Viewer granted only Task read can cause a new retrieval, workspace writes, and a Run source record if this public service seam is called with their scope; the T05 service does not itself require a Run admission or writer grant. The tests' checkers ignore the action and do not exercise a read-only Viewer at `BuildForRun`. **Impact:** a lower role can mutate Task material and create source history through a service called as the authoritative Run entry. **Smallest correction:** require `TaskWrite` for `BuildForRun` (and require the central Run admission to bind `runID` to the Task); add a checker that allows read but rejects write and assert no writer call or record insertion.

2. **High — a later selected scope leaves earlier material in the persistent Workspace.** `BuildForRun` calls `Build` at `internal/application/service/craft_knowledge.go:129`; `Build` writes each selected excerpt at `knowledge/<citation>.txt` and rewrites only `knowledge/manifest.json` at lines 414-446. Neither the new Run nor a changed selection removes prior `knowledge/*.txt` files. The Task has one persistent Workspace per the approved Spec, and the T05 report expressly leaves clearing stale material to central integration. With Run A selecting KB A followed by Run B selecting KB B, the A excerpt remains readable to a delegate receiving the workspace even though B's manifest lists only B. **Impact:** unselected or revoked content can enter a later Run's material boundary, contradicting #124's selected-and-authorized-only criterion. **Smallest correction:** stage a per-Run isolated material directory and delegate exactly that directory, or atomically replace the dedicated knowledge material directory before delegation; test sequential Runs with disjoint selections against actual workspace files, including revocation.

3. **Medium — clipped excerpts are reported as complete.** `internal/application/service/craft_knowledge.go:387-399` clips each result with `craft.ExcerptOf(..., MaxKnowledgeExcerptBytes)` then passes the clipped source to `BoundSources`. `internal/modules/craft/knowledge.go:79-92` marks `Truncated` only when a whole source is dropped. A single result longer than 8 KiB therefore produces `bundle.Truncated == false`, `record.Truncated == false`, and a manifest/UI that omits the truncation warning. `ExcerptOf` also appends a replacement rune after taking up to `max` bytes (`knowledge.go:116-131`), so the recorded/staged excerpt may exceed the stated per-source 8 KiB bound by up to three bytes. The T05 test allows `MaxKnowledgeExcerptBytes+3` and tests truncation only by adding 21 chunks. **Impact:** members mistake partial evidence for a complete retrieval, and the advertised hard bound is false. **Smallest correction:** bound the final UTF-8 output to `max` bytes, propagate per-excerpt clipping into bundle/record/manifest `Truncated`, and test one overlong ASCII and one multibyte result.
