# Issue #87 Lago Admission Pricing and Wallet Authority Implementation Plan (R16)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Before every paid external action, reserve a version-bound, conservative charge upper bound against the same tenant's Task Budget and verified Lago Wallet balance.

**Architecture:** Extend the frozen `CommercialPlatform.ReadSnapshot` seam with a pricing kind, then store a publication-bound, expiring read-only projection. One admission-pricing module derives bounded costs for semantic, voice, and Workbench callers. A complete Lago benefits observation folds account and lot faces in one database transaction; failed or partial observations cannot renew admission freshness.

**Tech Stack:** Go, Gorm, PostgreSQL and SQLite, dig, Lago Community v1.53.0.

1. One package unit is billed as a whole package: Task 2 tests 1/99/100/101 and overflow.
2. A plan is edited or Lago is unreachable after projection: Task 3 tests divergence, expiry and readback failure before Reserve.
3. A wallet has foreign/unanchored/expired/negative batches: Task 5 tests completeness and refusal to certify freshness.
4. Concurrent refresh Begin, balance fold, known-unsafe observation and Reserve, including shrinking authority balance below held: Task 5 tests atomic account/lot/task consistency and immediate admission block on PostgreSQL.
5. A model is BYOK while a connector remains paid: Task 4 tests dimension-specific exemption and no caller-supplied upper. Semantic package quantities 1 and 101 retain their exact bound through capability verification and Reserve.
6. Same reservation key and numeric upper under a new publication identity must conflict: Task 4 tests durable identity comparison independently of row CAS `Version`. Task 5 makes exact replay pass the same current account authorization guard before any outbound retry.
7. Identical wallet bytes across a batch expiry must lower certified spendable balance and lot capacity: Task 5 tests account, display and Reserve at the boundary.
