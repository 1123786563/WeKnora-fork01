# CRAFT-107 RunView R3/R4 material and version seam

**Status:** architecture recommendation, 2026-09-24; read-only analysis, no production or test edits. **Workspace:** `codex/craft-107-integration`, HEAD `a5e9195acd6500c085c85d60c852148e7bbbbf34` at inspection; concurrent uncommitted edits require a fresh checkpoint before implementation.

## Evidence and controlling invariants

Sources read: `CONTEXT.md`; approved `docs/specs/2026-09-23-craft-web-artifact-spec.md` (selected authorized material, uploaded code as read-only input, immutable versions, follow-up Run); ADR-0004/0008/0009; `2026-09-23-craft-107-runview-runtime-adapter-plan.md`; R1 and provider fix-1 independent reviews; R2 executor report; T05 publisher and durable KB snapshot plan; current `craft_runtime.go`, RunView coordinator/provider, artifact collector, VersionStore. R1/provider reviews explicitly leave production container engine, pinned Linux digest, assembly, and Run A→B proof unverified. R2 binding remains unassembled. The accepted T05 package has an atomic seal and exact Run ID/digest, but no production read-only mount is wired.

The admitted `(tenant, owner, session, run)` and RunView generation determine every path. The Task Workspace owns authorization and one-writer lease; it is not an OpenCode session or reusable filesystem view. Inputs and knowledge are exact selections for this Run. Only a server-selected last *promoted* Version may seed a follow-up Run. A Run failure/unknown must leave promotion unchanged. The container's project, HOME, OpenCode state, inputs, knowledge, and output stay generation-private.

## Recommended ownership and interfaces

1. **RunView material adapter in `internal/container` (R3/R4 owner).** Extend the existing coordinator/provider assembly with a server-only handle for the verified generation's host layout; do not accept a root, directory, or Version ID from a model/client. The current `CraftRunViewRuntimeHandle` exposes only the in-container `Directory`; the container provider internally derives `root/{inputs,knowledge,output}` from generation. Add a narrow provider method such as `MaterialHandle(ctx, verifiedRuntimeHandle) -> {generation, canonical host inputs/knowledge/output, in-container directory}` which re-inspects the exact container identity/mounts, or have one cohesive provider method prepare materials before returning an executable handle. A bare `string root` parameter is not sufficient authority. Keep host paths private to `internal/container` and bind them to the persisted RunView generation. Material preparation must finish before first prompt, and must be idempotent against retry/restart.
2. **Input staging.** Reuse `selectedWorkspaceInputs` and `admittedRunInputManifest` semantics: tenant/owner/workspace association, immutable admitted manifest, delegated subset validation. Replace only the write target and staging lifecycle. Read each selected object from `FileService`, enforce existing per-file/manifest quotas, exact byte count and SHA-256, create via no-follow, same-directory temporary file and atomic rename under the current generation's `inputs/`; reject any pre-existing symlink, extra file, changed file, or path escape. An empty manifest yields an actually empty mount. Seal/verify the complete directory before execution, then verify the provider reports it mounted read-only. Never stage under `workDir` or copy prior Run inputs.
3. **Knowledge handoff.** T05 owns selection, ACL checks, digest-sealed package creation, and durable acceptance; T01 owns the host view and mount proof. Inject a T05 publisher factory that receives the **same verified generation handle** and admitted Run ID; it may use `NewCraftKnowledgePackagePublisher` only on the provider's canonical root. Resolve the accepted package by Run ID plus accepted digest through `CraftKnowledgePackageResumer`; do not rebuild from current search on retry. Validate the seal and exact package paths, and ensure `knowledge/` contains only the accepted package for this Run (currently `craft.KnowledgeRunDir(runID)`), with no sibling Run package. Recheck current source authority at T05's retrieval/dispatch boundary. A revoked source fails closed; prior Version evidence remains immutable. Keep legacy `CraftKnowledgeService.Build` shared writer out of the RunView assembly.
4. **Version seeding.** The application service chooses the exact promoted Version ID under the admitted Task scope; R4 consumes that ID as server-only data, calls `VersionStore.Get`, checks workspace/tenant scope and manifest, and fetches each pinned object from `FileService`. Verify relative paths, regular-file type, size and SHA-256, quotas, and no extra output before atomic preparation of current generation's writable `output/`. No previous Run directory is mounted or copied wholesale. An initial Run has an explicitly empty output; a missing/unknown base Version is an error, not a fallback to `List()[0]` or a draft. Record the selected base Version identity in durable Run facts so retry uses the same seed even if promotion changes later.
5. **Collection.** Keep `CraftArtifactService` as validation/upload/immutable publication owner. Supply it a source bound to the current verified RunView handle, rather than `localCraftArtifactSource{workDir}`. Its `ListSessionFiles`/`ReadSessionFile` calls must resolve only `handle.output` and reject symlinks at every path component, devices, escapes, and files changed between list/read. The source must compare the requested Task session/Run against its bound handle; the existing `SandboxArtifactSource` session-only signature otherwise allows accidental reuse across Runs of the same Task. Prefer a per-Run collector/source instance over a process-global mutable current root. A successful collection still requires existing build/preview/page-load gates before promotion. Failure/unknown retains the previous promoted Version and a separately identified draft, if retained.

The runtime owner edits `craft_runtime.go` and container-side material/source tests serially after R2 review. T05 owner edits `craft_knowledge.go`/publisher assembly after durable KB snapshot and current-ACL handoff are reviewed. Artifact service changes are justified only if the per-Run source cannot satisfy the current interface safely. Central assembly owner alone edits `container.go` after interfaces settle. Do not concurrently edit `craft_runtime.go` or `container.go` with other owners.

## Ordering and blockers

R3 input staging can start against the current admitted input snapshot and verified RunView layout contract, without waiting for R2 assembly or T05 durable KB snapshot. R4 collector source and path defenses can also start against an injected verified handle; exact promoted-Version seeding needs the durable base-Version selection contract. T05 read-only handoff can define the interface now but cannot claim GREEN until the accepted digest is durable and `BuildForKnowledgeBases` dispatch carries it. End-to-end Execute/Observe/Abort, actual mounts, and Run A→B acceptance need R2 integrated, real engine and pinned image, T05 snapshot, and central assembly. If the provider cannot expose a verified generation layout without weakening isolation, stop at the interface and leave production dial off; do not create a synthetic root in `craft_runtime.go`.

## Exact RED behavior tests

- Two Runs A→B on one Task: A selects input A/K_A and publishes V1; B selects input B/K_B and exact promoted V1. B sees V1 output plus B/K_B, cannot list/read A/K_A, A HOME/state or sibling root, and cannot write either read-only mount. B output mutation yields V2 only after collection/gates; V1 bytes and promotion remain unchanged on B failure/unknown.
- Input manifest empty means an empty `inputs/`; a delegated extra input, removed workspace association, corrupt object, wrong size/digest, symlink parent/target, pre-existing extra file, and cross-tenant handle all reject before prompt. Retry with identical manifest remains byte-identical and never broadens selection.
- Accepted T05 package: exact Run ID/digest/seal is mounted read-only; missing or mismatched acceptance, partial candidate, altered seal, stale ACL, or a package from A in B rejects before prompt. Restart resumes the accepted bytes without live retrieval or shared writer fallback.
- Seed: B takes only the durably selected promoted V1, never newest draft; missing V1, changed object bytes, unsafe path, unexpected output file, and concurrent promotion change reject or retain the frozen base. Initial Run proves empty output. Neither seed nor subsequent B writes can mutate V1 objects.
- Collector: list/read through a B-bound source cannot read A even with same session ID; symlink, hard link/device, traversal, and list/read replacement reject. An unbound or stale generation and container inspection/mount mismatch reject before upload or promotion. No shared `output` symlink exists. Test a real container mount plus restart; temp-dir tests alone do not establish confinement.

## Alternatives and decision

Directly adapting `localCraftRuntime.workDir` is small but preserves shared serve and prompt-hash symlink races; reject. Copying T05's package into a second staging tree creates two authorities and uncertain recovery; keep the publisher on the exact RunView root, then verify its read-only container mount. Adding Run ID to the generic artifact source interface is explicit, but a per-Run bound source with strict Task/handle comparison is the smaller change if collection constructs it per Run. No production acceptance should be claimed until real OS mount and Run A→B evidence exists.
