# Semantica 使用独立语义知识服务

2026-09-20 确认 Semantica 作为独立 Python 服务部署，使用独立专用 gRPC 协议并由 Go adapter 接入；借鉴 DocReader 的通信、配置和部署模式，但不扩展 DocReader 服务。文档解析生命周期继续独立于语义索引和查询生命周期：上传经 DocReader 解析后，由 Go 保存正文和标准分块；Semantica 接收标准分块，负责语义图谱、语义索引和推理产物。tenant、知识库、文档和权限由 Go 保持权威。独立服务避免解析接口承担构图及推理的不同生命周期，复用 Go 业务权威避免两套权限模型。

最终能力范围是构图、GraphRAG 和知识推理，回答必须区分原文事实和推理结论。模型配置和调用经 WeKnora 授权入口，关联用量、预算和任务；Python 不配置独立长期密钥，该适配仍待验证。首期知识关联范围为单一知识库内的跨文档关联。

每个知识库选择一个图后端，保留 native 后端；选择 Semantica 的知识库先构建其索引并完成验收后才切换，每个知识库的正式查询只使用一个图后端。首期推理采用模型辅助推断和开发者注册的版本化规则推导，规则编辑器另议。知识库启用后自动处理存量文档，新增和修改持续异步更新；记录进度、失败重试和用量，解析状态与语义状态分开。

普通知识问答可退回现有检索，并显式注明未使用语义图谱；明确请求推理但服务不可用、索引未就绪或推理执行失败时，显示推理未完成和重试入口，不能用普通检索结果冒充推理成功。

普通更新在新索引构建期间可继续使用旧版本，回答标注所用旧版本，成功后再切换。删除或撤权立即阻止失效证据：新请求禁止使用；执行中请求在交付前重校验，受影响结果作废或重算。物理清理可以异步，其他有效来源仍可支持同一事实。

优先复用基础设施；不能可靠隔离时允许独立实例。复用时使用专用账号及适用的 database、schema、collection 或 prefix，具体拓扑待能力验证。首期知识库问答与 Agent 两个入口共用 Go 授权和适配，沿用现有页面增加索引状态、推理结果和证据。

首期规则验证场景是技术文档依赖分析：显式注册依赖传递规则“A 依赖 B 且 B 依赖 C，则 A 间接依赖 C”，不推广为任意关系。用户明确请求或选择推理模式时才推理；普通问答可使用 GraphRAG，Agent 任务仅在需要且获授权时调用推理工具，不为每个问题自动推理。

默认关闭。具有知识库管理权限者选择试点知识库，启用前展示存量规模和预算设置；启用后自动构建，验收后才正式切换，其他知识库保留 native。验收分两阶段：可复现中文样本覆盖跨文档检索、规则链、冲突、证据不足及删除/撤权；正式切换前，以授权的代表性业务样本对比 native，并在测量后确定质量、延迟和成本门槛，不作现成数值承诺。

2026-09-20 整体 Q1–Q17 已确认；本轮设计确认不等于实现或能力验收。上游冻结版本和能力适配、具体协议/持久化/拓扑、试点样本选择与数值阈值是后续验证设计产物，不可宣称已验证；旧实现计划不能直接当作本轮批准执行。
