## Remaining gaps (explicit)

1. PlatformShell delta: in Vue the page renders ListSpaceSidebar INSIDE the page container and it visually merges into the app sidebar column (OrganizationList.vue:3-4); in React the sidebar belongs to PlatformShell (not editable in this slice), so the 全部/我创建的/我加入的 filters ship as a page-level rail at the left edge of the content area. Merging them into the global sidebar rail under the 共享空间 nav item is a PlatformShell follow-up.
2. RBAC gating: Vue disables create/join + toasts organization.rbac.cannotCreate/cannotJoin unless the tenant role is admin (OrganizationList.vue:495-500); the React page receives no role prop and api-client auth.me exposes no tenant role, so buttons stay enabled (server remains the security boundary). Needs a role source (scopeRuntime role prop) in a follow-up.
3. Settings modal is a functional simplification of OrganizationSettingsModal.vue (3464 lines): no left-nav group titles/badges, no emoji avatar picker, no permissions matrix tab, no join-settings toggles (require_approval/searchable/member_limit), no per-member tenant grouping, no invite-link validity selector. Data wiring (members/roles/requests/shares/invite code/upgrade) matches the legacy React page 1:1.
4. TDesign icon glyphs are approximated with inline SVG paths (16px stroke icons); organization-green.svg and agent-green.svg and the constellation constellation decoration are ported exactly.
5. common.create i18n key missing (see above) — report to i18n owners; not edited here.
6. Organization card create/edit uses organizationsApi.update but Vue's modal also persists requireApproval/searchable/memberLimit on the same form — not reachable from React until gap 3 is closed (endpoint exists; no client gap).
