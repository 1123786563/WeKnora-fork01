## Vue baseline

- `frontend/src/components/ListSpaceSidebar.vue:111-125` (expanded panel) and `:35-49` (collapsed strip): in resource mode, after the workspace (本空间) bucket, a `countByOrg`-driven shared-spaces group renders one entry per org — the panel shows a `.sidebar-section` title (`listSpaceSidebar.spaces` = 「共享给我」) plus avatar + name + count; the strip shows an `icon-strip-divider` plus a 4-char truncated label (`truncateLabel`, :244-247) with a `name (count)` tooltip. `organizationsWithCount` (:271-274) renders only orgs with `countByOrg[org.id] > 0`. Clicking selects the org id (`select(org.id)`), i.e. `?scope=<orgId>`.
- `frontend/src/views/knowledge/KnowledgeBaseList.vue`: scope state lives in `?scope=` (:821-830) with reserved pseudo-scopes `all|mine|favorites|recents` (:897-906); any other value is a per-space view. `sharedCountByOrg` (:966-985) groups `sharedKbs` by `organization_id`. The per-space view (:908-913, :536-560) shows that org's shared KBs as a flat, sorted grid. Its empty state (:674-678) renders `knowledgeList.empty.sharedTitle/sharedDescription` with the illustration and no create CTA. Stale-URL guard (:1246-1251): the removed aggregate 协作 view used `scope=shared` and now resets to `all`.

## React implementation

- `apps/web/src/App.tsx` (kb-list rail + scope model only):
  - `KbListSpace` widens to include per-org scope values; `KB_RESERVED_SCOPES`/`isOrgScope` mirror Vue's `RESERVED_SCOPES` check. `readScopeFromUrl` returns non-reserved values verbatim (org id) and maps the stale `scope=shared` to `all`; a mount effect cleans the stale param from the URL (mirroring Vue's `useListUrlState` sync). `urlHasScope` is snapshotted once via `useRef` so the cleanup cannot let the contributor default override a deep link. Retry-dispatch hardening: an empty `?scope=` now falls back to `all`, matching Vue's `!!s` gate in `spaceSelectionOrgId` (previously it was treated as an org id and rendered the shared-empty state).
  - `orgShareData` memo derives both Vue-side structures locally: `countByOrg` (share rows grouped by `organization_id`, positive counts only → rail entries) and a `share_id -> organization_id` join. Field check: React share rows (`OrganizationSharedResource`) carry `organization_id` + `org_name`; `mergeAllScopeKnowledgeBases` strips `organization_id` from merged cards but keeps `share_id`, so the join needs no domain change and no new API.
  - Rail: org entries append below the workspace bucket in both strip (divider + truncated label + `name (count)` tooltip) and panel (「共享给我」 section title + full label + count badge); active state follows `space === orgId`; click runs `setSpace(orgId)` which writes `?scope=<orgId>`.
  - Scope filtering: org scope filters merged cards to shared ones whose share maps to that org; section grouping stays flat in the per-space view (Vue `sortedSpaceKbsList`). Org-scope empty state uses the Vue shared-empty copy without the create CTA; the illustration empty state is narrowed to `all|mine`.
- `apps/web/src/knowledge-list.css`: `.kb-list-rail-strip-divider` (width-constrained strip divider) and `.kb-list-rail-section-title` (12px/600 secondary title with top border, Vue `.sidebar-section`).

## Known gaps / deviations

- Vue renders a `SpaceAvatar` initial-avatar per org entry; the React rail reuses the existing `workspace` icon (no avatar component exists in `apps/web` yet). Follow-up if visual parity is demanded.
- Vue's per-space view additionally fetches own KBs shared into that org (space-level API `listOrganizationSharedKnowledgeBases`); per slice scope the React view filters the already-loaded merged cards (shared-with-me) by org only.
- Stale-scope URL after reset: React always deletes the param (scope=all = no param, this file's established convention); Vue writes `?scope=all` for contributors because it diffs against `defaultScope`. View state is identical.
- Org counts use the Vue `sharedCountByOrg` fallback path (raw share rows grouped by org); Vue additionally overrides with per-space API totals (`spaceCountByOrg`) that the React side does not fetch.
