# 求职三端 UI 原型（THROWAWAY）

要回答的问题：同一条“找岗 → 判断 → 准备材料 → 本人投递 → 跟进”流程，在 Web、原生移动端、微信小程序上怎样呈现最容易理解？

**选定方向（2026-09-24）：C「对话指挥台」。** 用户选择以自然语言指令作为找岗主入口，岗位结果、资格状态、匹配依据、待核实项和下一步行动在同一对话上下文呈现。申请、材料、档案仍有清晰的独立入口；Web、原生移动端和小程序保持相同业务闭环。A、B 保留用于回顾比较，不作为正式交互方向。

在仓库根目录运行一个命令：

    python3 docs/design/job-search/prototype/serve.py

然后打开终端打印的本地地址。页面不连接后端、不存储用户资料、不提交职位申请。点击顶部端类型查看 Web、移动端、小程序或三端并排；底部切换 A/B/C 三个结构明显不同的方案。URL 参数 variant=A|B|C 与 platform=web|mobile|mini|all 可直接分享；左右方向键切换方案。所有按钮只改变内存中的演示状态，“原型状态”面板显示当前完整状态。

- A 工作台：岗位列表与资格证据并排，适合高密度筛选。
- B 求职旅程：突出建档、匹配、材料、投递、跟进的连续进度。
- C 对话指挥台：自然语言找岗作为主入口，结果与下一步行动跟随对话。

本原型位于产品设计文档旁，未接入任何生产路由。C 的选择已同步到正式规格；正式实现须按规格重写，并补齐真实数据、权限、失败状态和跨端验证。原型源文件保留为评审依据，不应作为生产页面直接发布。

配色依据 [`docs/plans/2026-09-21-tdesign-react-migration.md`](../../../plans/2026-09-21-tdesign-react-migration.md) 的 Task 4：从 `packages/design-tokens/src/tdesign-theme.css` 的亮色主题提取品牌绿 `#07c05f` 系、灰阶及语义色。此原型只演示视觉与交互结构，正式页面应直接消费设计 token。
