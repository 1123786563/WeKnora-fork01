## 5. 具体代码风险与接入前阻断项

### 5.1 上传：HttpTransport 不代表零改造

`client.ts` 先组装 request.body，遇到 multipartFields 就调用 `multipartBody()` 创建 FormData，然后才判断是否调用 sendMultipartFile。微信实现 sendMultipartFile 仍可能在此前失败。必须将 nativeFile 分支提到 FormData 创建之前；无 native transport 时明确返回可诊断错误，而不是静默降级为错误上传。[R15–R16]

同时检查 AbortController、URLSearchParams、Blob、TextDecoder、AsyncIterable 等实际运行时能力。只对确实缺失的能力增加小型适配/补丁，禁止为修一个上传问题导入整套浏览器环境。

### 5.2 SSE：已有 parser，但要修边界而非照抄

`createServerSentEventParser.push()` 对每个 chunk 独立做 CRLF/CR 替换。如果 `\r` 与 `\n` 分在两个 chunk，可能变成两个换行，导致提前 dispatch。此结论来自已读实现的静态推导；交付包含独立最小复现，不代表运行了仓库测试套件。[R17]

还要补中文/emoji UTF-8 跨字节、多 data 行、注释心跳、多个事件粘包、空 id、终端关闭和不完整帧测试。缓冲状态应跨 chunk 保留。普通聊天与工作台事件的 payload 不是同一协议，不要只做 JSON.parse 后直接通用渲染。

### 5.3 支付回调与全局鉴权的路由关系需要验证

`routes_commercial.go` 把 `/commercial/callbacks/:provider` 注册在 API 路由组，注释认为回调公开、由签名认证；已读 `middleware/auth.go` 的 noAuthAPI 列表未包含该路径，而 router 组装中 API 路由在全局 Auth 之后。[R07、R09、R12]

因此存在**回调可能先被 JWT/API Key 中间件挡住**的接线风险。本次未运行服务，不能直接声称生产故障已确认。MP00 必须用真实 NewRouter 做无 JWT 回调集成测试；正确修复是精确的公开回调路由 + 渠道验签，不是放开整个 commercial 路由。新增微信登录也必须正确加入公开认证路径与限流。

### 5.4 能力和权限不能仅靠菜单判断

Workbench handler 可选；已有 deploymentCapabilitiesFromRouter 并未覆盖所有 workbench/commercial/mini 能力。应补服务器能力声明，区分 supported / unavailable / forbidden，不能把 404/503 显示为“暂无任务”。已有 ExecutionDTO.capabilities 可继续用于单任务操作。[R10、R14、R19]

SaaS 上线须核实 RBAC 配置实际启用。用户有空间成员身份，不代表可查看其他人的私有会话/执行；不得将空间 Owner 自动当成全部用户任务的所有者。[R07–R11]
