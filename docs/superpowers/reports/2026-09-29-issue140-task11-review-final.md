## Finding

**Medium — server errors mentioning other local markers still lose recovery intent.** `apps/miniprogram/src/services/career-intent.ts:67` applies `/SCOPE_CHANGED|AUTH_REQUIRED/i` to every error's message and code before checking the error's HTTP status. `errorFromResult` in `packages/api-client/src/errors.ts` preserves server-provided messages on an `ApiError` with status. A 503 response such as `{error:{code:'upstream_error',message:'upstream AUTH_REQUIRED'}}` is therefore ambiguous under `ambiguousOutcome` but definite under `definiteLocalFailure`. The catch paths in `recoverableWrite`, `searchOnce` through that helper, and `deleteWholeSpace` then throw `SCOPE_CHANGED` without retaining the original request ID. If the server completed the write before returning the gateway error, the user loses its reconciliation path and a later fresh attempt can duplicate work. This predates Task 11, but the Task 11 brief explicitly requires server errors to remain ambiguous, and the follow-up test covers only a server message containing `RUNTIME_UNAUTHORIZED`. **Smallest correction:** require an untyped local error (no HTTP status and no remote error code) before applying the message-based `SCOPE_CHANGED`/`AUTH_REQUIRED` markers; preserve narrowly typed local codes if used. Add a 503 `AUTH_REQUIRED`-in-message recovery regression beside the new 503 `RUNTIME_UNAUTHORIZED` test.
