# 杂项四轮（#3941 / #3837 / #3878）

日期：2026-10-06 · 分支：fix/misc4-3941-3837-3878（基于 merge/upstream-20261003）· 模式：3 并行实现者 + 验证门

## 背景

- #3941：技能安装验证把 bundle 全部 .py/.js/.sh 拼进单条 sh -c 参数，vendored .venv（数千文件 260KB）超 MAX_ARG_STRLEN（128KiB）→ exit 255，重型依赖技能无法安装。修法=sortedScriptPaths 单点过滤 `.venv/`、`node_modules/`（安装产物非模型可调脚本），三处调用同愈。
- #3837：mcp_exposure.go 裸 goroutine（预热 :121 与 worker :139）无 recover，MCP 客户端 panic 杀整个进程（#3706 只修了 Execute 主 goroutine）。修法=两处 defer+recover，坏服务标记加载失败、preloadDone 照常关闭；同形态的 search_knowledge 子 goroutine 与 think.go 一并最小补。
- #3878：PaddleOCR-VL Cloud（600s）与 WeKnoraCloud（20min）轮询超时硬编码，无视 env 配置。修法=照抄 mineru_cloud_converter 的 requestTimeoutFromEnv 模式 + .env.example 文档 + 轮询间隔结构体化。

三域互不重叠（agentcatalog / agentruntime tools+think / docparser），可并行。

## 任务 SK（#3941）：internal/agentcatalog/service/tenant_skill_verify.go

1. sortedScriptPaths（:429）过滤 `.venv/` 与 `node_modules/` 前缀（相对 skill 根的路径判断，兼容两种分隔形态），注释说明「安装产物非模型可调脚本，健康由依赖验证环节负责，且避免拼 sh -c 超 MAX_ARG_STRLEN(#3941)」。
2. 三处调用（树校验/语言 parse/运行时前置）不改——单点过滤同愈。
3. 测试：含 .venv/node_modules 混合脚本的 bundle → 枚举只含真实脚本；全 vendored 无脚本 → 行为按既有语义（报错或空，以现实现为准钉死）；正常技能不受影响。

## 任务 MC（#3837）：internal/agentruntime/agent/tools/mcp_exposure.go（+同形态最小补）

1. 预热 goroutine（:121 形态）与 worker（:139 形态）各加 defer+recover：Error 日志带 debug.Stack()，该服务标记加载失败（entry.store(service, nil, "error") 同义写法），确保 close(c.preloadDone) 照常执行、select 返回、引擎准备不被单个坏 MCP 带走。
2. 同形态最小补：search_knowledge.go 工具内 go func() 直接调 HybridSearch 处、think.go:230——同样 defer+recover 降级为日志/失败结果（不改变正常路径行为）。
3. 测试（票面给了 harness 配方）：newMCPCatalog + panic loader → PrepareMCPTools 不再崩进程、返回的该服务标记失败；正常 loader 通过；（如 harness 可行）工具子 goroutine panic 经 executeToolCallsParallel 不再杀进程。

## 任务 TO（#3878）：internal/knowledge/docparser/{paddleocr_vl_cloud_converter,weknoracloud_http_reader,helpers}.go

1. PaddleOCRVLCloudReader 加 timeout 字段，构造用 requestTimeoutFromEnv("WEKNORA_PADDLEOCR_VL_CLOUD_TIMEOUT", 600*time.Second)；pollJob 用字段；超时文案带具体时长（对齐 MinerU Cloud 写法）。
2. WeKnoraCloudSignedDocumentReader.pollTimeout 改 requestTimeoutFromEnv("WEKNORA_WEKNORACLOUD_TIMEOUT", 20*time.Minute)。
3. 两 reader 轮询间隔结构体字段化（照 MinerUCloudReader），便于快速回归。
4. .env.example 在 WEKNORA_MINERU_CLOUD_TIMEOUT 后补两变量说明（WeKnoraCloud 项注明应小于 WEKNORA_DOCREADER_CALL_TIMEOUT）。
5. 测试（票面配方）：假服务端恒返 running + env 设 200ms/300ms → 按新超时返回 timed out after <dur>；env 空/非法/非正回退默认。
