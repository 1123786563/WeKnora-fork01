## 任务 K（#3951）：chunker 围栏解析对齐 CommonMark §4.5

位置（fork 实际）：`internal/modules/knowledge/chunker/`（heading_splitter.go、strategy.go；`internal/modules/knowledge/ingest/chunker_debug.go` 也调 ProfileDocument）。

缺陷：profiler 与 heading 扫描对「trim 后以三反引号开头的行」切换 fenced-code 状态——波浪线围栏被忽略；短反引号围栏或带尾随文本的伪围栏会把长围栏提前关闭。代码里的字面 `#`/`##`/`###` 因此影响策略选择、章节边界与 ContextHeader。

修法（CommonMark 0.31.2 §4.5 围栏规则）：
1. 反引号与波浪线两种 fence；≥3 个同字符；≤3 个前导空格；开栏 info string（反引号栏内不得含反引号）。
2. 闭栏：与开栏同字符、长度 ≥ 开栏、其后仅空格/tab。
3. 未闭合围栏延伸到文档末尾。
4. 围栏内容不贡献 heading/边界；有效闭栏后恢复识别。HasCode/CodeRatio 照常计入；chunk 内容与 rune 位置保持源文档对齐。
5. 两个扫描点（ProfileDocument 与 findHeadingBoundaries 等，以实际为准，可能还有 heading_splitter 内的扫描）共用同一判定——抽一个小 helper 而不是复制两份状态机。

测试：issue 给的 TestFenceRepro 场景（~~~ 包裹的 # Fake/## Fake sub 不计 heading、不产生边界、HasCode=true）+ 四反引号栏内三反引号线不闭合 + 未闭合围栏到文档尾 + 闭栏后真 heading 恢复 + ContextHeader 不被伪 heading 污染。包内既有测试全绿。
