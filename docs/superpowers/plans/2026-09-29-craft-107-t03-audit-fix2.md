# Craft T03 durable input-use audit Fix2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make T03 input-use evidence accurately identify admitted reader operands, fail closed when required preflight evidence cannot be persisted, and never report a successful read before authoritative provider completion.

**Architecture:** Keep command classification in `internal/craft/input_code.go`, durable preflight in the Craft execution policy adapter, and terminal provider evidence in the normal-exec service. Pass one immutable typed observation across those seams; store a single accepted preflight row for the complete canonical input set before provider creation. Record terminal success only from the direct execution path after complete provider/transport/output evidence, and describe it as command-level completion rather than proof that bytes were opened.

**Tech Stack:** Go, GORM-backed Craft audit log service, Docker normal-exec durable receipts.

**Spec:** `docs/specs/2026-09-23-craft-web-artifact-spec.md`; T03/#122 and parent Issue acceptance in `docs/plans/2026-09-23-craft-107-dag.md`; approved `CONTEXT.md`; ADR-0013/0014; prior Fix1 report/review and architecture note in `docs/plans/2026-09-29-craft-107-t03-*`.

## Global Constraints

- Uploaded code remains read-only input data and cannot be directly executed, including aliases, wrappers, copy-then-execute, or temporary-directory bypasses.
- Unknown or ambiguous reader syntax fails closed; an argument is not evidence of a read unless the reader grammar identifies it as a file operand.
- Required preflight audit failure prevents provider/create/claim/send; denial logging remains best-effort because denial itself is fail-closed.
- Preflight records `accepted`; only authoritative complete provider evidence may record command-level `success`; accepted/stopping/unknown/replay observations never become success.
- Keep Task ID equal to Session ID and Run as one execution inside the Task.
- No commit/stage, remote Issue mutation, Docker live operation, or unrelated file edits in this repair.

## Review Focus

- `grep -e <pattern> <file>` must classify pattern and file separately; test positional pattern, `--`, `-e/--regexp`, `-f/--file`, attached option forms, and ambiguous forms in the module test.
- Distinct admitted paths with the same Ref must both appear in a single complete accepted preflight record; nil/failing audit sink must reject before the provider is called in service tests.
- Provider create/start errors, failed terminal state, incomplete transport/output, claimed-never-started, replay, and completion-audit failure must never create a false successful input-read event; cover in normal-exec tests.
