# 向量库 CopyIndices 分页加固（#3868 / #3869 / #3870 / #3871）

日期：2026-10-06 · 分支：fix/copyindices-3868-3871 · 模式：团队（3 个并行实现者 + 1 个验证门）

## 背景

复制/克隆知识库（`reuse_vectors`）路径在三个向量库后端的 `CopyIndices` 各有分页遍历缺陷。各包 `move.go` 已有加固先例（seen 集合、带检查断言、GraphQL errors 检查），本计划把同等防护移植到 `CopyIndices`。

代码位置（fork 实际路径，与 issue 描述的 `internal/application/...` 不同）：

- `internal/knowledge/retriever/weaviate/repository.go`（#3868 + #3869，同一函数）
- `internal/knowledge/retriever/qdrant/repository.go`（#3870）
- `internal/knowledge/retriever/milvus/repository.go`（#3871）

三个文件域互不重叠，可安全并行。

## 任务 W：Weaviate #3869（GraphQL errors → panic）

1. 每页 `Do(ctx)` 后先检查：`result == nil || len(result.Errors) > 0` → 返回 `weaviate: copy indices query failed: <原始 message>`（对齐同文件 :608/:677 与 weaviate/move.go:31 的既有写法）。
2. 解包拆成两次逗号-ok 断言：`result.Data["Get"].(map[string]interface{})` 一次、`get[collectionName].([]interface{})` 一次；缺键返回 `weaviate: copy indices invalid response`，不得 panic。

## 任务 W2：Weaviate #3868（游标不动 → 无限重放）

1. `lastID = additional["id"].(string)` 改带检查断言；`!ok || id == ""` → 返回错误。
2. `seen := map[string]bool` 记录用过的游标；整页解析完、**批量写入前**检测：`lastID` 已在 seen → 返回 `weaviate: copy indices made no progress at cursor %q`（重复页不再多写一份）；否则记入 seen。
3. 页数上限 `maxCopyIndicesPages = 10000`（包级 const，注释注明 ≈64 万行）：触顶 Warn + 返回错误。对齐仓库既有分页防护风格（Confluence `maxPaginationHops`、飞书 `seenPageTokens`、weaviate/move.go seen 集合）。

## 任务 Q：Qdrant #3870（inclusive offset → 页边界重复写点）

1. `q.client.Scroll` → `q.client.ScrollAndOffset`（go.mod 为 go-client v1.18.1；实现者须先在 module cache 确认该 API 存在且返回 `(points, nextOffset, err)`，不存在则改为「用响应 next_page_offset 推进 + seen 去重兜底」并在报告中说明）。
2. 删除 `offset = scrollResult[pointsCount-1].Id`；以服务端返回的 `nextOffset` 为下一页游标，`nextOffset == nil` 即完成。
3. seen 集合（按 point id）+ 跳数上限：游标重复或超限 → 返回错误（no progress），不得静默截断。

## 任务 M：Milvus #3871（offset 窗口 → 顺序漂移静默漏向量）

1. 遍历方式从 offset 窗口改为**按映射分批读**：把 `sourceToTargetChunkIDMap` 的 key 切成 64/批，filter = `and(eq(knowledge_base_id, sourceKB), in(chunk_id, 批))`（filter.go 已有 `operatorAnd`/`operatorIn`，参考同文件 :545/:634 的既有 in 用法与 sqlite 版 CopyIndices 的 `chunk_id IN (...)` 分批形状）。
2. 删除 `offset`/`count < batchSize` 短页终止逻辑；映射批读完即结束。
3. 某源 chunk 查不到行：保持现有「跳过 + Warn」语义（该 chunk 可能本就无向量），不算错误。

## 测试（每任务至少一个可运行用例，沿用各包现有 `_test.go` 基建）

- weaviate（httptest 假 GraphQL）：a) 服务端恒返同一页 64 条 → 期望返回 no-progress 错误且目标库只被写一次；b) HTTP 200 + `errors` + 无 `data` → 期望返回 query failed 错误而非 panic。
- qdrant（进程内 gRPC 假 Qdrant）：150 源点跨 3 页 → 目标 upsert 恰好 150 点、无重复、正常终止；nextOffset 恒不前进 → 返回错误。
- milvus（进程内 gRPC 假 MilvusServiceServer，`DisableConn: true`，每次写确认后把读结果顺序旋转一位）：200 源 chunk → 全部写入目标、无重复、返回 nil。

命令：`go test ./internal/knowledge/retriever/{weaviate,qdrant,milvus}/...`
