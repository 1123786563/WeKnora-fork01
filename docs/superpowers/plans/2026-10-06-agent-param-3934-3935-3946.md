# Agent 工具参数验证三票（#3934 / #3935 / #3946）

日期：2026-10-06 · 分支：fix/agent-param-3934-3935-3946（基于 merge/upstream-20261003）· 模式：2 并行实现者 + 验证门

## 背景

`ToolRegistry.Execute` 对无自定义校验器的工具走 `CastParams` → `ValidateParams`（fork 路径 `internal/agentruntime/agent/tools/`）：

- #3934 `param_cast.go`：整体 unmarshal 到 `map[string]interface{}`（数字变 float64）→ 任一字段发生转换就整体 re-marshal，未触及的数值参数被静默舍入（`9007199254740993`→`...992`、嵌套大整数、高精度小数同殃）。
- #3935 `param_validate.go`：`minLength/maxLength` 用 `len(s)` 数 UTF-8 字节而非码点——中文/emoji 合法输入被拒，过短输入反而通过。
- #3946 `param_validate.go`：enum 比较用 `fmt.Sprintf("%v")` 文本相等——`["a","b"]` 匹配 `["a b"]]`、`[1]` 匹配 `["1"]`、`1` 匹配 `"1"`（enum-only 属性）。

文件域：#3934=param_cast.go+测试；#3935+#3946=param_validate.go+测试。互不重叠，可并行。

## 任务 C（#3934）：param_cast.go

1. 改造 `CastParams`：顶层参数保持 `json.RawMessage` 原始字节；仅对「考虑做转换的那个参数」单独 decode；仅当该字段确实发生转换才替换其原始 JSON 片段；其余参数字节原样保留。
2. 既有显式强制转换规则（string→bool/number 等既有 coercion 语义）不变；本票只消灭对未触及参数的连带改动。
3. no-op / 非法输入：返回值与输入字节一致（control 用例）。
4. 测试（param_cast_test.go 扩展）：issue 复现集——`{"enabled":"true","id":9007199254740993}` 转换 enabled 后 id 不变；声明 number 的数组/对象内嵌 ID；`9223372036854775807` 嵌套保持；`0.1234567890123456789012345` 保持；no-op 字节一致 control。既有 cast 用例全保。

## 任务 V（#3935 + #3946）：param_validate.go

1. #3935：`minLength/maxLength` 改 `utf8.RuneCountInString`；错误文案与 ASCII 行为不变；码点计数而非字素簇（`e`+组合重音仍算 2）。
2. #3946：enum 比较改「JSON 结构相等」——decode 后按类型与结构递归比较：数值 `1` 与 `1.0` 视为相等（合法匹配保留）、对象键序无关；`["a","b"]` vs `["a b"]]`、`[1]` vs `["1"]`、`{"a":"b","c":"d"}` vs `{"a":"b c:d"}`、enum-only 下 `1` vs `"1"`、`true` vs `"true"` 均须报 enum 违规。
3. null 处理、数值精度解码、schema 驱动的显式 cast 语义均不动（票外）。
4. 测试（param_validate_test.go 扩展）：#3935 十条表驱动（中文/emoji/重音/混合/组合码点/空串/ASCII）；#3946 七条回归（类型/结构碰撞 + 合法标量/数组/对象匹配）。
