## 任务 R（#3851）：reparse 配置合并刷新

1. 摸清现状：上传 Confirm 路径（knowledge_create.go / knowledge_process_config.go）如何合并「KB 当前配置 + 显式 overrides」成快照；reparse 路径（knowledge_process.go:2668 起）何处复用了上传时存的旧快照而非重算。
2. 修复：reparse（单条/批量/后台重试共用路径）改为与上传 Confirm 相同的合并——KB 当前最新配置 + 「reparse 请求显式覆盖，否则保留上传时显式覆盖项」生成新快照。显式覆盖语义不变：用户上传时/重解析时明确给过的覆盖仍然生效，KB 后续修改的未覆盖项以最新为准。
3. 「reset config option」属 UI 增量，票面为期望项非必须项——本轮不做，报告注明。
4. 测试：沿用 service 层既有 reparse/config 测试基建；至少覆盖 a) 上传后改 KB 配置（关问题生成）再 reparse → 新配置生效；b) 上传时的显式覆盖在 reparse 后仍保留；c) reparse 请求显式新覆盖优先。

## 任务 Q（#3865）：QA complete 事件透传 usage

1. 摸清现状：智能推理（smart/agent）路径如何把模型流返回的 usage 填进 complete 事件的顶层 usage 与 data.usage（native_usage.go / agent_stream_handler.go 为参考）；QA 路径（session_knowledge_qa.go）在哪结束流、事件结构体在哪。
