# T03 wallet-semantics runtime evidence

Sanitized, reviewable evidence for the Lago wallet batch-expiry,
consumption-order, concurrency, and withdraw-semantics experiments (E1–E4,
ticket #75). Everything here is generated by `lab.sh run <experiment>`; no
hand-edited verdicts.

## Evidence contract

- Each experiment writes exactly one JSON report: `e1-expiry.json`,
  `e2-order.json`, `e3-concurrency.json`, `e4-withdraw.json`.
- Report shape (the Task 1 harness contract): `run_id`, `status`
  (`pass | fail | blocked-env`), `error`, `experiment`, `base_url`,
  `release` (from `deploy/lago/images.lock.json`, never live API text),
  `checks` (each `{criterion, expected, observed, outcome}`),
  `created_object_ids`, `cleanup`, and UTC timestamps.
- Expected outcomes are **pre-registered** in the offline unit tests
  (`test_e*_*.py`) from the pinned-source research basis before any real run;
  the real run only fills in `observed`. A surprise is unambiguous.
- **No secret values.** No `.env` content, no API key material, no passwords.
  Synthetic `weknora-t03-<uuid>` ids, lago ids, and public image digests are
  fine. Before committing, grep the tracked tree for the live secret values —
  zero hits is the bar.
- `blocked-env` (no API key, stack down, transport failure) is honest
  environment evidence and is clearly labeled; it is never presented as a
  pass. A `fail` is a contract observation that contradicts the
  pre-registered expectation.
- Observations are summaries with integer minor units / decimal strings;
  raw response dumps are never stored.

## Regenerating

```bash
./deploy/lago-lab/wallet-semantics/lab.sh env && ./deploy/lago-lab/wallet-semantics/lab.sh up
LAGO_API_KEY=<lab operator key> ./deploy/lago-lab/wallet-semantics/lab.sh run-all
```

E1 waits for the hourly wallet-termination clock (fires at `*:45`), so a full
run can take up to about an hour. The final verdict lives in
`docs/migrations/lago/t03-wallet-semantics/verdict.md`.
