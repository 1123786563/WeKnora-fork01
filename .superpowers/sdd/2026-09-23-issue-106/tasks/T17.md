## Rulings（本任务代行裁决，均记录在案）

- **R1（resolve 新增工具保守写分类）**：计划 Step 1/5 测试注释称「新增只读 c → Enabled=true」「resolve 后目录=[t1,t2]」，但 live MCP ListTools 不携带治理分类（types.MCPTool 仅 Name/Description/InputSchema；readOnly/personal-auth/scopes 是清单声明域字段），而统一口径（Brief 验收条件 2）禁止 resolve 经清单重抓——从清单取分类=恶意插件可漂移后把写工具声明为只读提权。故 resolve 重定基：同名工具继承已接受分类，新增工具一律 ReadOnly=false → 策略行 Enabled=false（治理面启用是 T18 范畴）。Brief 验收条件 3「新增写工具仍关闭」⊇ 满足；偏差仅对计划注释文本。**代价若错**：新增只读工具 resolve 后默认关闭需管理员手动启用——放宽路径，非安全问题。
- **R2（DescriptionChanged 第四证据维）**：T09 运行守卫把 description 变化 fail-closed（prompt-injection 通道），若 CheckDrift 三列表不含它，description-only 漂移下成员被阻而管理面显示 none——复审闭环断裂。`PluginDriftDetail` 增设 `DescriptionChanged`，判定口径与运行守卫一致。**代价若错**：detail 多一列（加法，不破坏三形态断言）。
- **R3（capability seam 不扩 PluginRepository 接口）**：计划 Interfaces 写「PluginRepository 扩展：UpdateDrift」，但 T06-era fake（install_service_test.go 的 fakePluginInstallRepo 系，非本任务所有权）显式实现接口、无接口嵌入，扩接口必破坏他人测试文件。沿 T16 `installationUpgradeWriter` 先例：gorm 方法 + service 类型断言，装配缺方法时响亮失败。**代价若错**：编译期不可见 seam 缺失（生产 dig 必注入 gorm repo，风险与 T16 同级）。
- **R4（计划接口签名的 dto→types 修正）**：计划写 `CheckDrift(...) (*dto.PluginDriftReport, error)`，但 interfaces 包不得依赖 handler 层（仓库既有约定，PreviewFromManifest/AcceptUpgrade 同款 types-layer 契约）。接口用 `*types.PluginDriftReport`，handler 映射 dto。**代价若错**：无（与仓库全部先例一致）。
- **R5（手工服务用例改名）**：计划用例名 `TestManualServiceNotGovernedByDrift` 不匹配 Brief 测试命令 `-run 'TestDrift'`，改名 `TestDriftManualServiceNotGoverned` 使任务命令覆盖全部三用例（原名保留在注释）。**代价若错**：无。
- **模型路由 Ruling（任务书原样转写）**：任务书要求按 gpt-5.6-sol/terra/luna 分级派发，但本 host 仅配置 GLM-5.3 系列模型，动态工作流亦不支持按子代理选模型。实际全部子代理运行在会话模型 GLM-5.3（最高推理档）上。此为记录的替代方案，不声称使用了不可用模型。
